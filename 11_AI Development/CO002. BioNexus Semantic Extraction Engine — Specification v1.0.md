3. 処理フロー（Processing Pipeline）

Step 1 — Vault Scan
- すべての .md を読み込む  
- YAMLは無視（本文のみ使用）  
- ノートをチャンク化（300〜500 tokens＋オーバーラップ）

---

Step 2 — Semantic Extraction（意味論抽出）
各チャンクに対して LLM＋Pythonで以下を抽出：

`json
{
  "concept": [...],
  "model": [...],
  "entity_type": "...",
  "domain": "...",
  "thread_id": "...",
  "section": "..."
}
`

抽出ロジックは以下：

- Concept → 名詞句・技術語・モデル名を抽出  
- Model → 数式・パラメータ・計算ロジックを抽出  
- Entity Type → AGRIX/HealthBook/PBPEの分類辞書＋LLM推定  
- Domain → 語彙ベースのスコアリング＋LLM推定  
- Thread ID → タイトル・本文の語彙から推定  
- Section → Markdown構造から抽出

---

Step 3 — Metadata Attachment
チャンクにメタデータを付与：

`json
{
  "text": "...",
  "metadata": {
    "source": "2026-09-03.md",
    "title": "Hms040. BioNexus Knowledge Architecture v1.0",
    "section": "Architecture",
    "thread_id": "HMS-T01",
    "domain": "HealthBook",
    "concept": ["Planetary Metabolism", "Canonical Schema"],
    "entity_type": "architecture"
  }
}
`

---

Step 4 — VectorDB Registration
FAISS / ChromaDB に保存：

`python
collection.add(
    documents=[chunk_text],
    metadatas=[metadata],
    ids=[unique_id]
)
`

---

Step 5 — Knowledge Graph Construction（GraphRAG）
抽出した concept / model / entity_type をノード化し、  
本文から因果関係を抽出してエッジ化する。

例：

`
MBT55CA --uses--> microbeflux  
AGRIXCA --dependson--> soilstructureindex  
PBPEECO --convertsto--> carboncreditprice  
`

---

4. 出力（Outputs）

4.1 RAG用チャンク＋意味論メタデータ
検索精度の中核。

4.2 GraphRAG用ノード・エッジ
因果推論の中核。

4.3 Python計算エンジンへの入力
正しいモデル・正しいパラメータを渡す。

---

5. この仕様書が“唯一のKey”である理由

- RAGは抽出エンジンが生成したメタデータに依存  
- GraphRAGは抽出エンジンが生成したノード・エッジに依存  
- Python計算エンジンは抽出エンジンが抽出したモデルに依存  
- LLMは抽出エンジンが返す文脈に依存  
- サブエージェントは抽出エンジンが返す構造に依存

つまり：

> 抽出エンジンが正しければ、すべてが正しく動く。  
> 抽出エンジンが誤れば、すべてが誤る。
