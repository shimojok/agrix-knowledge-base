MCP（Model Context Protocol）は、**2024年11月にAnthropic社がオープンソースとして発表した非常に新しい標準規格**です。

生成AIの発展に伴い、「AIに外部データやツールをどう安全・効率的に連携させるか」という課題を解決するために登場しました。

ローカルRAG、ChromaDB、MCPなどの技術が登場した歴史的経緯と、それらの相関関係、および周辺の重要キーワードを整理して解説します。

## 1. 生成AI進化の系譜と各種技術の出現経緯

生成AI（LLM）の進化に伴い、AIが抱える課題を克服する形で新しい概念・技術が順次登場してきました。

```text
【2022年〜】 LLMの爆発的普及（ChatGPT等）
    │  └─ 課題：ハルシネーション（嘘）、最新・固有ナレッジの欠落
    ▼
【2023年〜】 RAG & ベクトルデータベース（ChromaDB等）の台頭
    │  └─ 解決：外部文書を検索してLLMに読ませる仕組みの確立
    │  └─ 課題：データ連携（API/ファイル操作/DB接続）の規格がバラバラで開発が複雑化
    ▼
【2024年〜】 MCP（Model Context Protocol）の登場
    │  └─ 解決：LLMと外部システム（DB/ツール/Vault）を繋ぐ世界標準インターフェース
    ▼
【現在】 ローカルRAG × MCP × AIエージェントの統合

```

## 2. 各技術の役割と相互関係

現在お手元で構築されている `bionexus-engine` のアーキテクチャに当てはめると、各技術は次のような役割分担で繋がっています。

| 技術・キーワード | 分類 | 役割と関係性 |
| --- | --- | --- |
| **LLM (ChatGPT, Ollama等)** | **頭脳** | ユーザーの質問を理解し、文章を生成するコアエンジン。 |
| **Vector DB (ChromaDB等)** | **長期記憶（本棚）** | 大量のテキストを数値（ベクトル）に変換して高速に類似検索する専門データベース。 |
| **RAG (Retrieval-Augmented Generation)** | **検索手法** | 「DBから関連情報を探して（Retrieval）、LLMに渡し、回答を生成させる（Generation）」という一連の仕組み。 |
| **MCP (Model Context Protocol)** | **標準プラグ通信規格** | LLMと外部システム（ChromaDB, Obsidian Vault, Web検索等）を結ぶ「USBハブ」のような共通規格。 |
| **Obsidian (Vault)** | **一次データ源** | 人間（ユーザー）が知識を蓄積・整理するナレッジベース（ノート群）。 |

### テキストで見るデータの流れ

* **従来のローカルRAG**
`Obsidianノート` ➔ （Pythonで解析） ➔ `ChromaDB` ➔ （LangChainで検索） ➔ `LLM` ➔ `Streamlit UI`
* **MCP導入後の拡張**
`MCPクライアント（Cursor / Claude Desktop等）` ──(MCP規格)──> `MCPサーバー（Obsidian / ChromaDB）` ➔ `LLM`
※AI側から「Obsidianのノートを直接読みに行く」「ChromaDBを検索する」といったアクションを標準化されたプロトコルで自律的に実行できるようになります。

## 3. 併せて押さえておきたい重要システム＆キーワード

RAGやMCPを扱う上で、今後触れる機会の多い必須キーワードです。

### ① AI接続・制御フレームワーク

* **LangChain / LlamaIndex**: RAGやLLMアプリケーションを構築するための標準的なPython/TypeScriptライブラリ。データベース検索とLLMへの呼び出しを鎖（Chain）のように繋ぎます。
* **Ollama**: Llama 3などのオープンソースLLMを、自分のパソコン（ローカル環境）で安全かつ簡単に動かすための実行エンジン。

### ② ベクトル化と検索技術

* **Embedding（埋め込み）**: テキストの意味を数千次元の数値列（ベクトル）に変換する処理（例: `multilingual-e5-small`）。類似した意味の文章同士が空間上で近く配置されます。
* **Graph RAG**: 単なる文章の類似度だけでなく、Obsidianの `[[内部リンク]]` やナレッジグラフ（概念同士の結合関係）を意識して情報を引き出す高度なRAG手法。

### ③ システムアーキテクチャ

* **MCP Server（MCPサーバー）**: データ（ObsidianのVaultやデータベース等）を保持し、MCP規格に従ってLLMからの要求（リクエスト）に応答するプロセスのこと。
* **AI Agent（AIエージェント）**: 単に指示に答えるだけでなく、「情報が足りないからChromaDBを検索しよう」「次にシミュレーションコードを叩こう」と自律的に判断してツール（MCPツールなど）を使いこなすAIプログラム。

## 結論：学習とプロジェクトへの活かし方

* **MCPの価値**: これまでプログラマーが毎回Pythonコードで書いていた「LLMと外部データの接続処理」を、コンセントを挿すようにワンタッチで接続できるようにした**次世代の共通言語**です。
* **学習の進め方**: まずは現在の `ChromaDB + LangChain` でローカルRAGの仕組み（データがどう切り分けられ、どう検索されるか）を体感し、その上で Cursor や Claude Desktop に **Semantic Notes Vault MCP** などを繋いでみると、「AIが自分のノートを直接参照してコードを書く体験」としてMCPの強力さが実感できます。
