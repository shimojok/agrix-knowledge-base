## STEP 1｜情報収集エージェント（Bill Gates 投稿自動収集）の設計

結論（要点）
BioNexus‑Core の構造を前提にすると、最適な情報収集エージェントは 3層構造（Source → Normalizer → Ingestor） で設計するのが最も合理的です。

---

### 1️⃣ 情報収集の目的（因果構造）

Bill Gates の投稿を収集する理由は、以下の因果連鎖で説明できます：

- 投稿内容  
　→ 世界的課題（気候・農業・AI・健康）に関する洞察  
- 洞察の抽出  
　→ BioNexus Project が提供できる価値の特定  
- 価値の特定  
　→ Planetary Metabolism（地球代謝モデル）との整合性  
- 整合性の確認  
　→ Kaz が返信すべき「戦略的コメント」の自動生成  
- 自動生成  
　→ BioNexus の社会的影響力の拡大

つまり、情報収集は BioNexus Project のグローバル発信戦略の起点 になります。

---

### 2️⃣ 対象プラットフォームの技術的制約と対応策

| プラットフォーム | API | 収集方法 | 技術的注意点 |
|---|---|---|---|
| LinkedIn | 公式APIは制限強い | HTMLスクレイピング / RSS代替 | ログインセッション管理が必要 |
| GatesNotes | RSSあり | RSS + HTML | 最も安定した情報源 |
| Threads | APIなし | 外部スクレイパー（Puppeteer） | 変動が多いので冗長化必須 |

Threads は API がないため、自動化の安定性を確保するには「二重スクレイピング構造」 が必要です。

---

### 3️⃣ 情報収集エージェントの構造（3層モデル）

Kaz のモデル構築スタイルに合わせて、抽象 → 具体の階層構造で示します。

---

#### 🔷 Layer 1：Source Layer（投稿取得）

目的
各プラットフォームから投稿を安定的に取得する。

構成
- LinkedInFetcher
- GatesNotesFetcher
- ThreadsFetcher

技術仕様
- すべて 非同期処理（async）  
- 失敗時は 指数バックオフ  
- 取得データは Raw JSON として保存

---

#### 🔷 Layer 2：Normalizer Layer（正規化）

目的
プラットフォームごとに異なるデータ構造を統一する。

正規化項目
- 投稿本文  
- 投稿日時  
- タグ  
- URL  
- メディア  
- 著者情報  
- トピック分類（後述の BioNexus Router）

出力形式（標準化）
`json
{
  "source": "LinkedIn",
  "timestamp": "2026-10-21T12:00:00Z",
  "text": "...",
  "topics": ["climate", "agriculture"],
  "url": "...",
  "raw": {...}
}
`

---

#### 🔷 Layer 3：Ingestor Layer（AGRIX Knowledge Base への取り込み）

目的
正規化された投稿を AGRIX Knowledge Base に保存し、後続の解析エージェントが利用可能にする。

保存先
- GitHub（AGRIX Knowledge Base）  
- Obsidian（Kaz のスマホ環境）  
- BioNexus‑Core の RAG（ローカルLLM）

保存形式
- Markdown（Obsidian）  
- JSON（GitHub）  
- ベクトル（RAG）

---

### 4️⃣ トピック分類（BioNexus Router）

Kaz の研究領域に合わせて、投稿を以下のカテゴリに自動分類します。

| カテゴリ | BioNexus との関連 |
|---|---|
| Climate | GHG削減、PBPE気候金融 |
| Agriculture | MBT55、土壌炭素、SOC、腐植質 |
| Health | HealthBook、微生物・栄養 |
| AI / Data | AGRIX Platform、RAG、AIエージェント |
| Economics | PBPEモデル、Scope3、投資 |
| Global Development | Planetary Metabolism OS |

分類は LLM + キーワード辞書 + embedding のハイブリッド方式が最適です。

---

### 5️⃣ 情報収集エージェントの全体アーキテクチャ（図式化）

`
[Source Layer]
   ├ LinkedInFetcher
   ├ GatesNotesFetcher
   └ ThreadsFetcher
        ↓
[Normalizer Layer]
   └ UnifiedPostModel(JSON)
        ↓
[BioNexus Router]
   └ Topic Classification
        ↓
[Ingestor Layer]
   ├ AGRIX Knowledge Base (GitHub)
   ├ Obsidian Sync
   └ BioNexus RAG
`
