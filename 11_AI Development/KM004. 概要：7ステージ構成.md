## AGRIX Knowledge Base System (BioNexus Engine)

全体の流れを7つのステージに体系化したロードマップを作成しました。

## 概要：7ステージ構成

```
Stage 1: RAG再構築・16リポジトリのRAG化
   └─ ChromaDB/LanceDB + 日本語埋め込みで統合検索空間を構築
   └─ 「03_MBT55 > 04_AGRIX > 06_PBPE > 02_Biological > 01/05 > 07_HealthBook(凍結)」
      の優先構造を検索時に強制するメタデータ設計
   └─ 受け入れ条件: 疎通検証（栄養カスケード・CCE数式のクエリで一次情報がヒット）

Stage 2: Python Hypercycle Scheme の枠組み（core/）
   └─ base_model.py / pipeline.py / rag_interface.py / genome.json
   └─ 受け入れ条件: ダミーノード2個で「事象→JSON」の最小ループが動く

Stage 3: コード生成AIの統合
   └─ 生成AIが出力してよいもの（コード・スキーマ案・テスト）と
      いけないもの（最終数値・確定係数）を構造的に分離
   └─ 生成→自動検証ループ（pytest + 型チェック + RAG根拠突合）

Stage 4: JSON格納層
   └─ agrix-platform-kb.json のスキーマ・バリデーション・バージョニング・二重計上防止

Stage 5: JSON照会層
   └─ 型安全デシリアライズ、主要クエリ定義、ダッシュボード供給形式

Stage 6: 個別エンジン群の作成
   └─ 優先順位: mbt_hypercycle → agrix_phenotype → pbpe → agriware/safetychain
      → （凍結解除後）healthbook
   └─ 各エンジンは「RAG根拠抽出 → 生成 → 検証 → genome登録 → 結合テスト → 採用」
      のハイパーサイクル的サイクルで開発

Stage 7: BioNexus Engine 統合
   └─ 最終テスト: 「廃棄物投入→GHG削減・NCS・PBPE価値のJSON出力→
      その内容がRAGで再検索できる」という一周テスト
```

## 設計上の要点

1. **依存関係**: Stage 1（RAG）が全ての起点。疎通検証合格がStage 6の着手条件。Stage 4・5はStage 2後に並行可能
2. **HealthBook凍結の構造化**: メタデータレベルで判別可能にし、コード生成ルールでも二次層として扱う
3. **数値の決定論性**: 生成AIはあくまでコード記述と根拠要約に専念。数値は常にPython実行由来（Pydantic検証通過のみ格納）
4. **還流ループ**: Stage 7で「新JSON→チャンク化→RAG再索引」の循環閉鎖を明示し、ハイパーサイクルとして完成

ツール選定（ChromaDB/LanceDB、multilingual-e5/bge-m3、Pydantic v2、scipy ODE、networkx、FastAPI、uv等）と付録も文書内に整理済みです。



次の一手としては **Stage 1-1 の棚卸し（16リポジトリの形式・サイズ一覧）** が現実的な出発点です。リポジトリ情報を共有いただければ、ingestパイプラインの設計に進めます。
