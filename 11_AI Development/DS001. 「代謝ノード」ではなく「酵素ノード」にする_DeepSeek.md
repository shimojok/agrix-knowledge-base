# BioNexus Python Hypercycle Scheme への提案

## 前提：既存設計の評価

`kb005` の設計は**「決定論的計算をPythonに、文脈検索をRAGに分離」**という点で正しい。ただし、これは**「ハイパーサイクル」ではなく「パイプライン」**です。真のハイパーサイクル（Eigenの定義）は：

1. **各ノードが自己複製的**（自分の出力を再入力として使う）
2. **各ノードが次のノードの触媒**（単なるデータ受け渡しでなく、活性化）
3. **閉じた超循環**（外部入力なしでも回り続ける）
4. **非平衡開放系**（エネルギー流入がある限り秩序を維持）

現設計は 1→2→3→4 の一方向フローです。以下、真のハイパーサイクルにするための**奇抜な提案**を5点出します。

## 提案1：**「代謝ノード」ではなく「酵素ノード」にする**

### 現状の問題
`MetabolicPathwayEngine` は「入力→計算→出力」の関数。これは**酵素ではなく代謝経路そのもの**。

### 提案
各Pythonモジュールを**「酵素（Catalyst）」**として定義する。酵素は：
- **基質特異性**（受け取る型が厳密）
- **触媒活性**（入力を消費せず、出力を生成）
- **阻害・活性化**（他の酵素の存在で活性が変わる）
- **フィードバック阻害**（自分の出力が閾値超で自身を抑制）

```python
class EnzymeNode(BaseHypercycleEngine):
    """酵素ノード：基質を触媒的に変換"""
    substrate_type: type      # 受け取る型
    product_type: type        # 生成する型
    km: float                 # ミカエリス定数（親和性）
    vmax: float               # 最大反応速度
    inhibitors: list[str]     # 阻害する他ノードID
    activators: list[str]     # 活性化する他ノードID
    
    def catalyze(self, substrate, allosteric_signals: dict) -> tuple:
        # アロステリック制御：他ノードの状態で活性が変わる
        activity = self.vmax
        for inhibitor_id in self.inhibitors:
            if allosteric_signals.get(inhibitor_id, 0) > 0.8:
                activity *= 0.3  # フィードバック阻害
        for activator_id in self.activators:
            activity *= (1 + allosteric_signals.get(activator_id, 0))
        
        # ミカエリス・メンテン式で反応速度決定
        rate = (activity * substrate.concentration) / (self.km + substrate.concentration)
        return self.product_type(...), rate
```

**効果**：AGRIXの炭素固定酵素が、HealthBookのSCFA産出酵素を**活性化**する、といった**相互触媒**が自然に表現できる。

## 提案2：**「意味論的アドレス空間」でノートとコードを同一視**

### 現状の問題
Vaultノート（`.md`）とPythonコード（`.py`）が**別世界**にある。RAGはノートだけ検索し、コードは別管理。

### 提案
**すべてのノート・コード・JSONに「代謝アドレス」を付与**する。

```
アドレス形式：<ドメイン>.<経路>.<酵素>.<変種>
例：
  agrix.carbon.soc_sequestration.mbt55_standard
  healthbook.microbiome.scfa_butyrate.mbt_probiotics_v2
  pbpe.market.carbon_credit.clb_2026
```

**すると何が起きるか**：
- RAG検索が「意味論的アドレス」で**コードとノートを同時ヒット**
- Pythonエンジンが自分のアドレスを宣言し、**RAGに自分を登録**
- ノートを更新すると、**対応するPythonエンジンのバージョンが自動検知される**

```python
@metabolic_address("agrix.carbon.soc_sequestration.mbt55_standard")
class SOCSequestrationEngine(EnzymeNode):
    """土壌有機炭素固定エンジン（アドレスでノートと紐付け）"""
    # このエンジンは RAG の "agrix.carbon.soc_sequestration" ノート群を参照
```

**効果**：Vaultが**「コードの設計図」と「コード本体」の両方を保持**し、乖離を防ぐ。

## 提案3：**「時間軸」を第一級市民にする**

### 現状の問題
`HypercycleNodeResult.timestamp` はあるが、**過去の結果を再利用していない**。毎回ゼロから計算。

### 提案
**「代謝記憶（Metabolic Memory）」** を導入。各酵素ノードは：
- 過去の計算結果を**時系列DB（ChromaDB + SQLite）に保存**
- 新入力時、**類似の過去ケースを検索**して初期値に使う
- **差異（Delta）だけを計算**する

```python
class EnzymeNode:
    def catalyze_with_memory(self, substrate):
        # 過去の類似ケースを検索
        similar_cases = self.memory.search(substrate, top_k=5)
        
        if similar_cases and similar_cases[0].similarity > 0.95:
            # 高類似：差分だけ計算（高速化）
            base_result = similar_cases[0].output
            delta = self._compute_delta(substrate, similar_cases[0].input)
            return base_result + delta
        else:
            # 低類似：フル計算して記憶に追加
            result = self.catalyze(substrate)
            self.memory.store(substrate, result)
            return result
```

**効果**：
- 計算コストが**指数関数的に低下**（類似ケース再利用）
- **自己進化**：使うほど賢くなる
- **説明可能性**：「この結果は○月○日の類似ケースを基に算出」と根拠提示

## 提案4：**「エントロピー予算」で計算リソースを動的配分**

### 現状の問題
すべての酵素が同じ優先度で動く。重要な計算と些末な計算を区別しない。

### 提案
**熱力学第二法則を模倣**し、各酵素に「エントロピー予算」を割り当てる：

- **高エントロピー予算**（重要・不確実）：フル計算、RAG深掘り、LLM説明生成
- **低エントロピー予算**（些末・確定的）：キャッシュ利用、近似計算

```python
class EntropyBudget:

    def allocate(self, node_id: str, uncertainty: float) -> float:
        # 不確実性が高いノードに多くの予算を配分
        # 予算を使い切ったノードは近似モードに落ちる
        ...
```

**効果**：
- **ゲイツ氏向けデモ**：重要な問いには深く、些末な問いには浅く答える
- **API コスト最適化**：LLM呼び出しを本当に必要な時だけに
- **レイテンシ削減**：9割のクエリはキャッシュで即答

## 提案5：**「反証可能な予測」を出力に含める**

### 現状の問題
`MetabolicOutput` は**点推定値のみ**。「この予測が外れる条件」を示さない。

### 提案
すべての出力に**「反証条件（Falsification Condition）」**を付与：

```python
class MetabolicOutput(BaseModel):
    mitochondrial_atp_yield: float
    glp1_secretion_relative: float
    
    # 新規追加：この予測が崩れる条件
    falsification_conditions: list[FalsificationCondition] = Field(
        default_factory=list,
        description="この予測が外れる条件と、その確率"
    )

class FalsificationCondition(BaseModel):
    condition: str          # 例："被験者のShannon Index < 2.0"
    probability: float      # その条件が成立する確率
    impact: str             # 成立時の影響（例："ATP産出-40%"）
    reference: str          # 根拠ノートのアドレス
```

**出力例**：
```json
{
  "mitochondrial_atp_yield": 85.3,
  "falsification_conditions": [
    {
      "condition": "腸内Shannon Index < 2.0（多様性喪失）",
      "probability": 0.15,
      "impact": "ATP産出が85.3% → 51.2%に低下",
      "reference": "healthbook.microbiome.diversity.threshold"
    },
    {
      "condition": "MBT Probiotics投与量 < 5g/day",
      "probability": 0.22,
      "impact": "GLP-1分泌刺激が半減",
      "reference": "healthbook.probiotics.dose_response"
    }
  ]
}
```

**効果**：
- **ゲイツ氏が最も評価する**：科学者は「反証可能な予測」を出すシステムを信頼する
- **ハルシネーション防止**：LLMが「確からしさ」を偽装できない
- **実験計画の自動生成**：「この予測を検証するには○○を測定せよ」と導ける

## 統合：**真のPython Hypercycle Scheme**

5提案を統合すると：

```
┌─────────────────────────────────────────────────────────┐
│  Entropy Budget Manager（予算配分）                      │
│    ↓ 予算に応じてノード活性化                            │
├─────────────────────────────────────────────────────────┤
│  Enzyme Nodes（酵素ノード群）                            │
│  ┌──────────┐  相互触媒  ┌──────────┐                  │
│  │ AGRIX    │←─────────→│HealthBook│                  │
│  │ 酵素群   │            │ 酵素群   │                  │
│  └────┬─────┘            └─────┬────┘                  │
│       │ 代謝アドレス           │                        │
│       ↓                        ↓                        │
│  ┌─────────────────────────────────────┐               │
│  │  Metabolic Memory（時系列DB）        │               │
│  │  - 過去ケース検索                    │               │
│  │  - 差分計算                          │               │
│  └─────────────────────────────────────┘               │
│       ↓                                                 │
│  Falsification Conditions（反証条件）                   │
│       ↓                                                 │
│  RAG（Vaultノート＋コード＋JSONの統合検索）             │
│       ↓                                                 │
│  新たなノート・コードとしてVaultに還元（閉じた循環）    │
└─────────────────────────────────────────────────────────┘
```

**これが真のハイパーサイクル**：
1. **自己複製**：出力が新しいノート・コードとしてVaultに戻る
2. **相互触媒**：酵素ノードが互いの活性を制御
3. **閉じた循環**：外部入力なしでも記憶から再計算可能
4. **非平衡開放系**：エントロピー予算（エネルギー）流入で秩序維持
