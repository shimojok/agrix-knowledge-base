LLM は、Ollama でもいいですね？

---

はい。OllamaをローカルLLMとして使う構成で問題ありません。 BioNexusのナレッジ基盤では、Ollamaを使うことで、外部APIへの依存を減らしながら、Obsidian Vaultの検索・解析・知識抽出をローカル環境で実行できます。

ただし、重要なのは Ollama単体ではなく、Ollama＋RAG＋MCPを組み合わせることです。

## BioNexus向けの推奨構成

① Obsidian Vault

Markdown／Daily Notes／YAML／Wiki Links

② 知識解析・インデックス化

ノート解析／メタデータ／リンク・バックリンク／更新検知

③ Vector DB

Embedding／意味検索

④ Source DB

原文参照／出典／位置情報

⑤ MCP Server

検索・原文取得・関連ノート取得をLLMに提供

Ollama ＋ ローカルLLM

検索結果の分析／要約／分類／知識抽出／推論

この構成なら、LLMにVault全体を読み込ませるのではなく、質問に関連する原文だけを検索して渡せます。

## Ollamaの担当範囲

| 機能            | 推奨する仕組み            |
| ------------- | ------------------ |
| ノートの分類・要約・構造化 | OllamaのLLM         |
| 意味検索用のベクトル生成  | Embeddingモデル       |
| 類似ノート検索       | Vector DB          |
| 原文・出典・リンク管理   | SQLiteなどのSource DB |
| LLMからの検索・取得操作 | MCP Server         |

注意点： OllamaでLLMを動かすだけでは、トークン消費やコンテキスト長の問題は自動的には解決しません。検索対象を絞るRAGの設計が重要です。ローカル推論では外部LLM APIの入力トークン課金を避けられますが、PCのメモリや計算資源は必要です。

また、Semantic Notes Vault MCPを採用する場合、すでに提供されている検索機能と自作のVector DB・MCP機能を二重実装しないよう、先に機能を確認するのが合理的です。
