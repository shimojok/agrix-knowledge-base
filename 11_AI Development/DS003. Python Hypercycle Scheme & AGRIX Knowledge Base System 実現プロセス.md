## Stage 2: ハイパーサイクル実装（Hypercycle）

### Phase 4: Python Hypercycle Scheme の枠組み

**目的**：`kb005_rev2`（修正版）の設計を**コード骨格**に落とす。

| 項目 | 内容 | 成果物 |
|------|------|--------|
| **4-1. 酵素ノード抽象クラス** | `EnzymeNode`（基質特異性、触媒活性、阻害・活性化） | `core/enzyme_node.py` |
| **4-2. 代謝アドレス** | `<ドメイン>.<経路>.<酵素>.<変種>` 形式 | `core/metabolic_address.py` |
| **4-3. 代謝記憶** | 過去ケースを時系列DBに保存、差分計算 | `core/metabolic_memory.py` |
| **4-4. エントロピー予算** | 重要度に応じた計算リソース配分 | `core/entropy_budget.py` |
| **4-5. 反証条件** | すべての出力に「反証条件」を付与 | `core/falsification.py` |
| **4-6. MBTハイパーサイクル核心** | 120菌種、$\gamma_{ij}$ マトリックス、CCE/HFR/NCS | `mbt_hypercycle/` |

**判断基準**：
- 酵素ノードが**相互触媒**できること（AGRIXの酵素がHealthBookの酵素を活性化）
- 代謝記憶が**差分計算**で高速化すること
- 反証条件が**Pydanticモデル**で型安全に表現されること

### Phase 5: コード生成AIの統合

**目的**：RAG + LLMで、**新しいPythonコードを自動生成**。

| 項目 | 内容 | 成果物 |
|------|------|--------|
| **5-1. プロンプトテンプレート** | RAGコンテキスト + 生成指示 | `prompts/code_generation.md` |
| **5-2. コード生成パイプライン** | RAG検索 → LLM生成 → 検証 → 保存 | `scripts/generate_code.py` |
| **5-3. 検証層** | 生成コードをpytestで検証 | `tests/generated/` |
| **5-4. 人間レビュー** | 生成コードをユーザーが承認 | レビューログ |
| **5-5. フィードバックループ** | 承認/却下をRAGにフィードバック | `memory/code_feedback/` |

**注意**：
- **LLMはコードを「提案」するのみ**。実行は決定論的Pythonエンジン
- 生成コードは必ず**型安全（Pydantic）**かつ**テスト済み**

### Phase 6: JSON生成・格納・抽出の自動化

**目的**：Pythonエンジンの出力を**JSON**として格納し、**必要情報を抽出**。

| 項目 | 内容 | 成果物 |
|------|------|--------|
| **6-1. JSONスキーマ定義** | `agrix-platform-kb.json`, `healthbook-platform-kb.json` | `schemas/` |
| **6-2. JSON生成** | Pydanticモデル → JSON | `core/json_generator.py` |
| **6-3. JSON格納** | `data/` 配下に時系列で保存 | `data/generated/` |
| **6-4. JSON抽出** | 必要なフィールドをクエリ | `core/json_extractor.py` |
| **6-5. RAG還元** | 生成JSONをRAGインデックスに追加 | `update_rag_index.py` |
| **6-6. 循環完了** | 新JSONが新ノートとしてVaultに戻る | 閉じた循環 |

**これが真のハイパーサイクル**：Pythonの出力が、次のPythonの入力になる。
