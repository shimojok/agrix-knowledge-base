## 2. 既存スクリプトの問題点

共有いただいた `update_rag_index.py` では、キャッシュは次の場所に設定されています。

```
C:\Users\user\bionexus-engine\chroma_db\file_cache.json
```

このファイルが実際に存在しない場合、スクリプトは空のキャッシュとして処理を開始します。

さらに、現在の `.env` は旧Vaultのパスを指しています。

```
OBSIDIAN_VAULT_PATH=C:\Users\user\agrix-knowledge-base
```

この状態で新Vaultに切り替えると、次の問題が発生する可能性があります。

- 新VaultのMarkdownファイルがすべて新規・更新対象として検出される。
    
- 既存DBに保存された旧Vault由来のベクトルが、その処理だけでは確実に削除されない。
    
- 旧データと新データが混在し、検索結果に重複や古い情報が残る可能性がある。
    

したがって、現行の `update_rag_index.py` をそのまま実行して切り替える方法は採用しません。
