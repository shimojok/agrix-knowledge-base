🧠 1｜なぜ Dropbox が最適なのか（因果構造）

✔ 理由①：Obsidian Mobile が Dropbox と直接同期できる
あなたはすでに：

- スマホで ReadItLater → Obsidian  
- PCで Obsidian → RAG  
- GitHub → Obsidian → Pinecone  
- デイリーノートの時系列構造  
- 分野別連番  
- メタデータ付与

という スマホ中心の知識入力ルート を確立しています。

Dropbox に置けば：

- スマホの Obsidian  
- PCの Obsidian  
- GitHub push  
- Pipeline  
- RAG  
- MCP  

すべてが 同じフォルダを参照 できます。

---

✔ 理由②：GitHub に push する前の「安全な staging（待機場所）」になる
Dropbox にコピーを置くことで：

- GitHub に push する前に構造を確認  
- メタデータの整合性をチェック  
- ノートの連番・目次を確認  
- 不要ファイルを除去  
- AIが読みやすい構造に最終調整  

ができます。

GitHub に直接 push すると、  
誤った構造がそのまま公開されるリスク があります。

Dropbox は「安全な中間地点」です。

---

✔ 理由③：スマホで即時確認できる
Kaz の運用は：

- スマホでノートを読む  
- スマホでデイリーノートを書く  
- スマホで構造を確認  
- スマホで設計コンセプトを追加  
- スマホで Evidence Registry を更新  

これらが Dropbox → Obsidian Mobile で即時反映されます。

GitHub はスマホでの編集が難しいため、  
Dropbox が最適です。

---

✔ 理由④：Pipeline がローカルのフォルダを参照しやすい
Pipeline（検索 → 選別 → 生成 → 保存）は：

- ローカルのフォルダ  
- GitHub  
- Obsidian  
- RAG  
- MCP  

を連結します。

Dropbox はローカルフォルダとして扱えるため、  
Pipeline が 直接参照できる という利点があります。

---

✔ 理由⑤：GitHub push の安全性が最大化される
あなたが言った通り：

- 古い構造が混入しない  
- AI生成の誤ノートが混入しない  
- 16リポジトリの破損構造が混入しない  
- 最新の BioNexus-Knowledge-Base の純度が保たれる  

GitHub は「最終保存場所」なので、  
Dropbox → GitHub の流れが最も安全です。
