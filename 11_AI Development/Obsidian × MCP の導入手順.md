Obsidianに mcpを導入し、Claude などのトークン消費を抑える方法を調べてください。

---

Obsidian に **MCP（Model Context Protocol）** を導入することで、Claude などの AI ツールから Obsidian 内のノート（Vault）に直接アクセスできるようになります。

毎回ノートの全文をコピペしたり不要なファイルをコンテキストに読み込ませたりする無駄がなくなり、AI の**トークン消費量を最大で 40%〜80% 程度削減**することが可能です。

導入手順と、トークン消費を最小限に抑えるためのテクニックを解説します。

---

## 1. Obsidian × MCP の導入手順

Obsidian と Claude Desktop（または Claude Code）を MCP 接続する標準的な構成は以下のとおりです。

1. **Obsidian 側に REST API プラグインを導入:** 約 3 分.
Obsidian の「設定」→「コミュニティプラグイン」の閲覧から **`Local REST API`** （または `REST and MCP server`）を検索してインストール・有効化します。

設定画面を開き、表示される **API Key** と **ポート番号**（デフォルトは `27124` 付近）を控えておきます。


2. **Node.js のインストール確認:** 事前準備.
MCP サーバーの実行には Node.js 環境が必要です。ターミナル（macOS）や PowerShell（Windows）で `node -v` を実行し、未インストールの場合は [nodejs.org](https://nodejs.org/) から LTS 版をインストールしてください。


3. **Claude 側に MCP サーバーを登録:** 約 2 分.
**Claude Desktop の場合:**
`claude_desktop_config.json` ファイルを開き、以下のように設定を追加します。

```json
{
  "mcpServers": {
    "obsidian": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-obsidian"
      ],
      "env": {
        "OBSIDIAN_API_KEY": "YOUR_API_KEY_HERE"
      }
    }
  }
}

```

*※ `YOUR_API_KEY_HERE` を Step 1 で控えた API Key に差し替えます。*

**Claude Code の場合:**
ターミナルから以下のコマンドを実行して登録します。

```bash
claude mcp add obsidian -e OBSIDIAN_API_KEY="YOUR_API_KEY_HERE" --scope user -- npx -y mcp-obsidian

```


4. **動作確認:** 1 分.
Claude Desktop や Claude Code を再起動し、「Obsidian のノート一覧を表示して」とプロンプトを入力します。一覧が返ってくれば連携完了です。

## 2. トークン消費を抑える 5 つの最適化テクニック

MCP を導入しても、使い方が大雑把だと大量のトークンを消費します。以下の工夫により、API コストや制限の消費を最小限に抑えられます。

### ① 「ピンポイント検索・取得」の指示を与える

ノート全体を取得させたり、Vault 全体を検索させると、取得したテキスト量に応じて一気にトークンが跳ね上がります。

* **NG例:** 「Obsidian のメモを全部読んで、今週のタスクをまとめて」
* **OK例:** 「`Task.md` というファイルの『今週』セクションだけを読み込んで、タスクを抽出して」

### ② システムプロンプト・`CLAUDE.md` で出力形式を制限する

Claude の回答テキスト量（出力トークン）を抑えるルールを定義しておきます。
Vault 内のルートまたは Claude の設定に `CLAUDE.md` などを置き、以下のように指示します。

```markdown
- 回答は簡潔に要点のみ述べること（プレビュー用の冗長な挨拶や前置きは不要）。
- Obsidian から取得したファイル内容をそのまま出力に全転記しないこと。

```

### ③ 不要なツール（MCP）の有効化を減らす

複数の MCP サーバー（GitHub、Web 検索、Obsidian など）を同時に登録しすぎていると、**接続しているすべてのツールの定義（スキーマ）が毎ターンのプロンプトに含まれる**ため、メッセージ送信だけで数千〜数万トークンが浪費されます。

* 使わない MCP は一時的に設定ファイルでコメントアウトするか無効化する。

### ④ 定期的なセッションリセット（`/clear` の活用）

会話が長くなると、過去のやり取り履歴すべてがコンテキストとして送信され続けます。

* 話題が変わったタイミングや、作業の区切りで `/clear` コマンド（または新規チャット）を実行し、トークン履歴をリセットする癖をつけます。

### ⑤ ノートのフォーマットを軽量化（Markdown・JSON ミニファイ）

装飾や余計な HTML タグが含まれたメモはトークンを圧迫します。

* 純粋な Markdown 記法に保つ。
* ノート内に大きな画像をキャプチャのまま埋め込まず、必要なテキスト部分のみにする。
