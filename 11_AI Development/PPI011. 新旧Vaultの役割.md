旧Vaultは既存RAG・数理モデルの稼働実績を持つ参照基盤、新VaultはBioNexusの実装対象となる新しい知識基盤として扱います。旧Vaultの構成をそのまま新Vaultへ複製するのではなく、既存資産を再利用しながら、新Vaultに適した構成を設計します。

## 新旧Vaultの役割

| 項目                 | 旧Vault        | 新Vault           |
| ------------------ | ------------- | ---------------- |
| 位置づけ               | 既存の実装・検証環境    | 新しい実装対象          |
| ノート                | 6,400以上       | 新Vaultの実際の構成に基づく |
| Ollama／RAG         | 稼働済み          | 既存環境の再利用可否を確認    |
| ChromaDB／Embedding | e5-smallで構築済み | 再利用・再構築を判断       |
| 数理モデル              | 16リポジトリ統合など   | 必要な機能を選択して接続     |
| MCP                | 既存機能の確認が必要    | 新Vaultへの接続方式を設計  |

## 新Vaultの実装方針

1. 新Vaultの正本を確立する。 旧Vaultの原文や構造を無条件にコピーしません。

2. 既存エンジンを再利用する。 Ollama、RAG更新スクリプト、数理モデルなどは、新Vaultとの互換性を確認して活用します。

3. 新Vault専用のインデックスを管理する。 旧Vaultのベクトルやメタデータが新Vaultの情報と混在しないようにします。

4. MCPを接続する。 新Vaultの検索・原文取得・関連ノート探索を公開し、対応クライアントから利用できるようにします。

5. 新Vaultを基準に検証する。 検索精度、出典追跡、更新処理、トークン削減効果を測定します。

ただし、新Vaultのノート数、フォルダ構造、旧Vaultとのデータ共有範囲は、まだ確定情報として扱いません。

次に確認したいのは、新Vaultがすでに作成済みかどうかです。 すでに作成されているなら、そのVaultの構成を基準に実装設計を進めます。
