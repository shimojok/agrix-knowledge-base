Obsidian プラグインのSemantic Notes Vault MCPが、ChatGPT などのトークン消費抑制に絶大な効果があると聞きました。これは、どのような仕組みなのですか？

---

結論から言うと、Semantic Notes Vault MCP の大きな利点は、Vaultの全ノートを毎回ChatGPTに読み込ませるのではなく、質問に関係する情報だけを検索して取得できることです。

BioNexus-Knowledge-Baseのように、AGRIX、PBPE、MBT55、HealthBookの大量のノートを横断して扱う場合、この仕組みは特に有効です。ただし、トークン削減の効果は検索方式、取得する文章量、AIクライアントのMCP対応状況によって変わります。

## 1. どのような仕組みなのか

通常のAI利用と、MCPを利用した知識検索を比較すると、違いが分かります。

### 通常の方法：大量の文書を会話に投入

Vaultの大量のノート

必要な資料も、不要な資料もAIのコンテキストに入る

入力トークンの増加・重要情報の埋没

### MCPによる検索：必要な資料を選んで取得

Vault全体を索引化しておく

質問 → 意味検索・キーワード検索 → 関連ノートを特定

必要な原文・関連ノートだけをAIに返す

後者では、索引の作成と検索処理はあらかじめ用意した仕組みが担い、AIは必要な情報を取得して推論します。これが、コンテキストの節約につながる基本原理です。

## 2. トークンを節約する4つの技術

| 技術           | 仕組み                      | 効果             |
| ------------ | ------------------------ | -------------- |
| セマンティック検索    | 単語が一致しなくても意味の近いノートを探す    | 探索対象を絞る        |
| 関連箇所の抽出      | 文書全体ではなく、関連する見出しや文章を返す   | 入力トークンを削減      |
| リンクグラフ探索     | Wikiリンク、バックリンク、関連ノートをたどる | 無関係な資料の大量投入を防ぐ |
| キャッシュ・索引の再利用 | 毎回ゼロから検索インデックスを作らない      | 検索処理の重複を減らす    |

このプラグインの公式説明では、全文検索、関連度による順位付け、リンクグラフ探索、読み取り専用モードなどが案内されています。

ここで大切なのは、ベクトル検索そのものがChatGPTのトークンを減らすのではないという点です。トークンを大幅に減らせるのは、検索結果を必要な範囲に限定し、不要な原文をモデルへ送らないからです。

## 3. BioNexusでの具体例

たとえば、次の質問をしたとします。

> PBPE金融モデルは、MBT55による農業生産コストの低減を通じて、為替安定化にどう寄与するのか？

従来なら、PBPE、AGRIX、MBT55、金融モデルに関する大量のノートを探し、まとめてAIに渡す必要があるかもしれません。

MCP検索を使えば、次のように段階的に資料を取得できます。

1. 最初の検索： PBPE金融工学論、PBPE通貨モデル、為替安定化の関連ノートを特定する。

2. 原文の取得： 関連ノートから、因果関係・数式・前提条件が記載された箇所を読む。

3. 関連資料の追跡： AGRIXやMBT55の生産コスト、廃棄物処理、農業生産性に関するリンク先を調べる。

4. 統合分析： 原資料の記述を保持しながら、技術的効果から実体経済、国際収支、為替への波及経路を整理する。

これなら、最初からVault全体をコンテキストに投入せずに済みます。資料が不足していれば追加検索し、十分な根拠が集まった段階で分析します。

## 4. 重要な区別：MCPとベクトルDBは別のもの

Semantic Notes Vault MCPは、Vaultへのアクセスと検索をAIに提供するMCPサーバーです。公式説明で確認できる機能には、全文検索、リンク探索、ノートの読み書き、Dataview連携などがあります。

![](https://www.google.com/s2/favicons?domain=https://github.com\&sz=32)

+1

一方、このプラグインを導入すれば、必ず専用のベクトルDBが構築される、あるいはChatGPTのトークンが一定割合減る、という意味ではありません。

Semantic Notes Vault MCP

Obsidian内のノート検索・原文取得・リンク探索をAIに提供する接続層。

ベクトルDB

ノートや文章のEmbeddingを格納し、意味の近さから検索するデータ層。採用する実装によって、保存先や検索方式は異なります。

ChatGPT側のMCP接続

対応するクライアント・プラン・接続方式が必要です。Obsidian側でプラグインが動いているだけでは、ChatGPTとの接続は成立しません。

OpenAIの公式案内では、カスタムMCPサーバー接続はChatGPTのプランやワークスペース設定による制約があります。Freeプランを含め、すべての環境で同じ方法が使えるとは限りません。

## 5. BioNexus-Knowledge-Baseでの採用方針

私の推奨は、Semantic Notes Vault MCPを原文へのアクセス窓口として活用し、必要に応じて専用のローカルRAG・ベクトルDBを補完する構成です。

* ② ノート解析：既存Vaultの文書ID、メタデータ、Wikiリンクを解析する。

* ③ ベクトルDB：意味検索を可能にする。

* ④ 原文・リンクDB：元の記述とノート間の関係を保持する。

* ⑤ MCP：AIが検索・取得できる統一インターフェースを提供する。

この構成なら、プラグインに存在する機能を重複実装せず、不足する機能だけを補えます。

また、削減効果は実測すべきです。同じ質問を使い、①全ノートを投入する方式と、②MCP検索で必要な箇所だけ取得する方式について、取得文字数、入力トークン、検索時間、回答の根拠網羅率を比較します。

目標は単なるトークン削減ではありません。少ないコンテキストで、Vaultの原資料に忠実な分析を実現することです。 これをBioNexusの知識エンジンの設計基準にするのが適切です。
