GitHub Discussions , issue, wiki の特徴と使い方を教えて下さい。

---

GitHubの**Discussions**、**Issues**、**Wiki**は、プロジェクトのコミュニケーションや情報共有を整理するための主要な機能です。それぞれの特徴と適切な使い分けは以下の通りです。

### 各機能の特徴と使い分け

|**機能**|**役割**|**主な用途**|**特徴**|
|---|---|---|---|
|**Discussions**|コミュニティ・雑談|Q&A、アイデア出し、意見交換、お知らせ|結論がすぐに出ないオープンな議論向け。Threads（スレッド）形式で分類しやすい。ベストアンサーの指定が可能。|
|**Issues**|タスク・バグ管理|バグ報告、機能追加リクエスト、作業タスク|明確な「完了（Close）」のゴールがある課題向け。担当者（Assignee）や期限（Milestone）を設定可能。|
|**Wiki**|長期的なドキュメント|設計書、開発ガイドライン、API仕様書、ナレッジベース|プロジェクトに関する体系的な情報を蓄積・編集する場所。複数ページで構成され、検索・閲覧がしやすい。|

### 具体的な使い方と使い分けの指針

#### 1. GitHub Discussions（議論・Q&A）

- **使いどころ**: 「この機能についてどう思う？」「〇〇の使い方を教えてほしい」といった、タスク化する前のオープンな会話。
    
- **メリット**: Issueが雑多な質問や議論で埋まるのを防ぎます。質問に対して回答を「Answered（解決済み）」としてマークできるため、よくある質問（FAQ）のナレッジベースとしても機能します。
    
#### 2. GitHub Issues（タスク・バグ）

- **使いどころ**: 「ログインボタンが反応しない」「〇〇機能を実装する」といった、具体的かつ解決・実装すべき事項。
    
- **メリット**: Pull Request（PR）と直接紐付けることができ、コードの変更とタスクの進捗を一元管理できます。プロジェクトボード（Projects）と連携してカンバン形式で運用するのが一般的です。
    
#### 3. GitHub Wiki（ドキュメント管理）

- **使いどころ**: 「環境構築手順」「プロジェクトの設計思想」「用語集」など、頻繁に参照される固定的な情報。
    
- **メリット**: Gitリポジトリとして独立しているため、マークダウン形式で簡単にページを増やせます。リポジトリの直下に置く `README.md` よりも情報量が多く、カテゴリ別に整理したい場合に最適です。
    

> **簡単な判断の目安**
> 
> - **「これ直して/作って！」**（作業が必要） $\rightarrow$ **Issue**
>     
> - **「これどう思う？/教えて！」**（会話・質問） $\rightarrow$ **Discussions**
>     
> - **「これ読んでおいて！」**（蓄積された情報） $\rightarrow$ **Wiki**
