### ローカルRAG標準構成と `bionexus-engine` の対比

### **Python環境・ベクトルDB**

* **標準事例：** Python + Chroma / Qdrant
* **本プロジェクト：** **Python + ChromaDB**
* **理由：** 完全ローカルで動作し、軽量かつディレクトリ単位（`chroma_db/`）で安全に永続化できるため、Obsidian Vaultとの親和性が最高レベルです。

### **RAGフレームワーク**

* **標準事例：** LlamaIndex / LangChain
* **本プロジェクト：** **LangChain (Python)**
* **理由：** 柔軟なチャンク分割（見出し対応）と、将来的な確定記述エンジン（GHG、PBPE等のPythonコード実行）との連携が容易なためです。

### **データ読み込み & 埋め込み（Embedding）**

* **標準事例：** 大量のMarkdown/PDF読み込み ＋ ローカルEmbedding（SentenceTransformers等）
* **本プロジェクト：** **`agrix-knowledge-base` (6,600+ MD) ＋ OpenAI Embeddings**
* **理由：** `build_rag_index.py` により、見出し構造を保持したまま一括解析します。Embeddingには現時点で世界最高水準の文脈理解力を持つモデルを採用し、日本語・英語混在の「MBT55」等の複雑な概念を高精度にベクター化します。

### **LLM推論エンジン & ハードウェア（GPU/CPU）**

* **標準事例：** Ollama / llama.cpp (GPU/CPUでのローカル推論)
* **本プロジェクト：** **ハイブリッド構成（OpenAI API / 将来的なOllama完全ローカル化に対応）**
* **理由：** 機密性の高いローカル運用が必要な場合はOllama等へ即座に切り替え可能なコード設計にしつつ、開発・検証段階では最高精度のLLM推論を活用します。

---

### 本プロジェクト（bionexus-engine）独自の決定的な強み

一般的なRAGと大きく異なるのは、「RAG（検索）の上に、決定論的Pythonエンジン（計算）を載せている点」です。

1. **RAG（前処理）：** Vault全体の6,600+ノートから、質問に関連する文脈・数式・パラメーター（GHG削減率、PBPE利回り等）をChromaDBから集める。
2. **Python Engine（主役）：** 集めた数値・数式をもとに、Pythonコードが100%正確な決定論的計算（シミュレーション）を実行する。
3. **LLM（説明役）：** 計算結果と根拠を統合し、人間（投資家や意思決定者）に提示するプレゼン文章を生成する。

この構成により、一般的なRAGにありがちな「LLMの計算ミス（ハルシネーション）」をゼロにし、完璧な根拠と精度を持つ意思決定基盤が完成します。
