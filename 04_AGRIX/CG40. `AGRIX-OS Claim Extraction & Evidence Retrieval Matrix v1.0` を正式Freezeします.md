# 4. Source Fidelity Rule

今回最も重要な実行規則です。

### Claim Extractionでは、

> **元資料に書かれている内容を抽出する。**

### 行わないこと

- 科学的妥当性の独自判断
- 過去AI記述の自動否定
- 過去AI記述の自動採用
- 外部知識による補完
- Claimの勝手な高度化
- Evidenceの先回り判定

つまり、

```
Source
  ↓
Extract
  ↓
Atomic Claim
```

までです。

```
Claim
 ↓
True / False
```

は次工程のReconciliationです。

**「AIが生成したから除外」**

とはしません。

逆に、

**「過去AIが完成と言ったから採用」**

とも扱いません。

```

       ↓

       ↓
Reconciliation
```

これによって、過去数年間のAIとの共同作業を**捨てずに再利用可能なKnowledgeへ変換**できます。

# 8. Local RAG / ASTとの接続

Claim Extraction Batchには、後続工程で使用するRetrieval指示も付与します。

例：

```
{
  "claim_id": "AGRIX-OBJ-XXX-CLM-XXX",
  "retrieval_plan": {
    "exact_search": true,
    "semantic_search": true,
    "rag_search": true,
    "ast_search": false,
    "metadata_filter": [
      "repository",
      "file_type"
    ]
  }
}
```

これにより、Kazさんが構築するLocal InfrastructureとAGRIX-OSのKnowledge Governanceを分離できます。

```
PMOS / AGRIX-OS
       │
       │ Retrieval Specification
       ▼
Local Knowledge Infrastructure
       │
 ┌─────┴─────┐
 ▼           ▼
RAG         AST
 │           │
 └─────┬─────┘
       ▼
Evidence
```
