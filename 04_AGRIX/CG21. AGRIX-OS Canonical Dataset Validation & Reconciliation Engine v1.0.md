# AGRIX-OS Canonical Dataset Validation & Reconciliation Engine v1.0

**正式設計・Freezeします。**

今回の目的は、29 Objectsをさらに増やすことではありません。  
**「Canonical Datasetに登録された知識が、Schema・Ontology・Evidence・Provenance・Relationship・Governanceの各層で矛盾していないかを機械的に検査し、問題をAIが勝手に修正せず、Reconciliation候補として返すEngine」**を固定します。

```
SCENARIO → REALIZED IMPACT
MODEL → OBSERVED EVIDENCE
```

# 6. V3 — Ontology Validation

Object TypeとOntologyの整合性を検査。

例：

```
MBT55 Biological Core
        ↓
biological_core
```

に対して、

```
PBPE Impact Engine
```

を誤ってbiological_coreとして登録した場合、

```
ONTOLOGY_CONFLICT
```

を返します。

---

# 7. V4 — Provenance Validation

これはAGRIX-OSで最重要です。

```
Object
  ↓
Evidence
  ↓
Source Repository
  ↓
Source Document
  ↓
Source Locator
```

のchainを検証します。

### 不合格例

```
Claim
 ↓
No Source
```

↓

`PROVENANCE_MISSING`

### KPI

**Provenance coverage = 100%**

---

# 8. V5 — Evidence Validation

Evidence StatusとGolden Statusの論理整合性を検査します。

例えば、

```
evidence_status = PENDING
golden_status = REFERENCE
```

という組み合わせは、DatasetのGovernanceルールに反する可能性があるため、

```
STATUS_CONFLICT
```

として検出します。

一方、

```
SOURCE_CONFIRMED
+
REFERENCE
```

は正常です。

---

# 9. V6 — Relationship Validation

現在の29 JSON Objectsではrelationshipsが空ですが、今後ここがKnowledge Graphの核心になります。

例えば、

```
AGRIX-OBJ-001
     │
     └── HAS_FUNCTION
              ↓
        AGRIX-OBJ-006
```

について、

- source exists
- target exists
- predicate is valid
- direction is valid
- provenance exists

を検証します。

### KPI

**Broken KG reference = 0**

# 11. Reconciliation Engine

ValidationとReconciliationを分離します。

### Validation

> 「問題があるか？」

### Reconciliation

> 「どの情報同士が衝突しているか？」

です。

```
Validation
    │
    ├── PASS
    │
    └── FAIL
          │
          ▼
   Conflict Detection
          │
          ▼
   Reconciliation Proposal
          │
          ▼
   Human Adjudication
```
