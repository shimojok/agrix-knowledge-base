# Ds001. ローカルVaultへのアクセス基盤

生成AIの設計により違いはあると思いますが、生成AIが、直接、ローカルフォルダのVaultノートを検索し、必要な情報やデータを抽出し、AGRIX システムアーキテクチャ構築、AGRIX シミュレーションシステム(デモシステム)の構築を可能とする技術的要件を纏めてください。

---

生成AIがローカルVaultのノートを直接検索し、AGRIXのアーキテクチャ構築やシミュレーションシステムの構築に必要な情報を抽出するための技術的要件を整理します。

### 🔌 ローカルVaultへのアクセス基盤

生成AIがObsidian Vaultのノートを直接読み取るには、**MCP（Model Context Protocol）** を介した接続が現在の標準的な手法です。

**主要な接続方式は2つ**あります：

| 方式 | 仕組み | 特徴 |
|------|--------|------|
| **ファイルシステム直接アクセス** | MCPサーバーがVaultのパスを直接読み取る | Obsidian起動不要。ローカル完結。ファイル監視による差分インデックス更新が可能 |
| **Local REST API経由** | Obsidianの「Local REST API」プラグインが提供するAPIをMCPサーバーがラップ | Obsidianの機能（アクティブノート、コマンド実行、グラフ構造）をフル活用できる |

**セキュリティ要件**として、パストラバーサル防止（Vault外へのアクセス拒否）、システムディレクトリ・`.git`のブロック、破壊的操作への明示的な確認が必須です。

### 🔍 検索・抽出エンジン

Vault内のノートからAGRIX関連情報を効率的に抽出するには、**ハイブリッド検索**が有効です。

**検索手法の組み合わせ**：
- **BM25ランキング検索**：キーワード完全一致に強く、型番や識別子（例：ISO 11783、TASKファイル仕様）の検索に適する
- **ベクトル検索（意味検索）**：ローカル埋め込みモデル（例：`bge-small-en-v1.5`）を使い、概念的な関連性を捉える。APIキー不要でオフライン動作可能
- **メタデータフィルタリング**：YAML frontmatterの`tags`、`category`、`status`等による絞り込み

**技術要件**：埋め込みモデルはローカル実行が望ましく（プライバシー保護）、チャンク分割（256〜512トークン）とオーバーラップ設定による文脈保持が重要です。

### 🏗️ AGRIXシステムアーキテクチャ構築への適用

AGRIXは農業機械のISOBUS（ISO 11783）互換制御システムであり、以下の要素がVaultノートから抽出対象となります：

**アーキテクチャ構築に必要な情報**：
- **ISOBUS通信仕様**：Task Controller（TC）とVirtual Terminal（VT）の連携、Process Dataメッセージ構造
- **実装プロトタイプ**：AGRIX Basic Prototypeの構成（PDAベースのTC、CANバス接続、実装機制御）
- **データモデル**：TASKファイル（ISOBUS XML形式）の構造、装置記述（DDOP）の管理

**抽出後の処理**：生成AIは抽出した仕様を基に、**機能ブロック図・データフロー図・インターフェース仕様書**のドラフトを生成できます。

### 💻 AGRIXシミュレーションシステム構築への適用

シミュレーションシステム（デモ）の構築には、以下の要件が考えられます：

**シミュレーション環境の構成要素**：
- **CANoe.ISO11783等のツール**：Task Controllerシミュレーション、Virtual Terminal、実装機ECUのモデリング（CAPL言語）
- **OPC UAベースのTC**：処方マップに基づく可変施用制御の検証（セクションコントロール含む）
- **ハードウェア要件**：CANインターフェース（CANCardXL等）、2台のPC間接続、リアルタイムOS

**Vaultノートから抽出すべき情報**：
- シミュレーション対象となる**タスク管理ワークフロー**（計画→XML変換→TC転送→実行→ドキュメント化）
- **処方マップ**と**セクション制御アルゴリズム**の仕様
- **AGRIXプロトタイプの実装詳細**（センサー仕様、アクチュエータ制御、キャリブレーション手法）

### 📋 技術要件サマリー

| カテゴリ | 要件 |
|----------|------|
| **接続** | MCPサーバー（ファイルシステム直接 or Local REST API経由） |
| **検索** | BM25 + ベクトル検索のハイブリッド、YAML frontmatterフィルタ |
| **埋め込み** | ローカルモデル（APIキー不要、オフライン動作） |
| **セキュリティ** | パス検証、読み取り専用モード、破壊的操作の確認 |
| **出力** | AGRIXアーキテクチャ設計書、シミュレーション仕様書の自動生成 |
| **シミュレーション** | CANoe/ISO11783、OPC UA TC、実装機モデル（CAPL） |

**現状の課題**として、AGRIXプロジェクト自体は2003〜2005年頃の研究であり、当時のVaultノートが存在する場合でもISOBUS標準の初期ドラフトに基づく記述が含まれる可能性があります。最新のISO 11783仕様（特にPart 10の改訂）との整合性確認が必要です。

また、シミュレーションシステムの構築には、CANoe等の商用ツールに依存する部分が大きく、Vaultノートからの抽出だけでは完結しない領域（ハードウェア接続、リアルタイム性保証）が存在することも考慮すべきです。
