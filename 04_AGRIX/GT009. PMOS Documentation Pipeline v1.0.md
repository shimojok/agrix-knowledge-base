**PMOSはソフトウェアではなく、「Knowledge Operating System」です。**

そのため、ソースコードではなく**MarkdownをSingle Source of Truth（SSOT）**にするべきです。

この考え方は、MicrosoftのDocs、Kubernetes、OpenAPI、Terraform、Azure Well-Architected Frameworkなど、多くの大規模プロジェクトでも採用されている思想と整合します。

# この設計で追加したいもの

ここで、私から一つ設計上の提案があります。

これまでの設計では **Markdownを中心**に据えていますが、BioNexus Projectの規模を考えると、それだけでは将来の保守性に限界が出る可能性があります。

そこで、**Markdownの上位に「PMOS Knowledge Schema（PKS）」**という概念を追加することを提案します。

役割は以下のようになります。

|レイヤー|役割|
|---|---|
|PMOS Knowledge Schema (PKS)|知識の型・メタデータ・命名規則・関係性を定義する標準|
|Markdown|PKSに従って記述された知識コンテンツ|
|Documentation Pipeline|Markdownから各成果物を生成|
|Pinecone / AI Agents|PKSを利用して検索・推論・知識統合|

PKSを導入すると、将来的にリポジトリが18から50、100へ増えても、AIエージェントは同じ知識モデルで理解・検索できます。また、Microsoftなど外部パートナーへも「独自の知識アーキテクチャ」として説明しやすくなります。

私は、この**PMOS Knowledge Schema（PKS）**こそが、BioNexus Projectを支える長期的な知識基盤になると考えています。
