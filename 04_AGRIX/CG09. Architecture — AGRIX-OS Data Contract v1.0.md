# 2. Purpose

AGRIX-OS Data Contractの目的は、

> **異なるAI、Repository、Engine、Dashboard、Databaseが、同じ現実世界のObjectを同じ意味で読み書きできるようにすること**

です。

これにより、これまでの

```
Kaz
 ↓
自然言語Prompt
 ↓
ChatGPT
 ↓
自然言語
 ↓
Gemini
 ↓
NotebookLM
 ↓
Claude
```

という伝達方式を、

```
                 Canonical Data Contract
                         │
        ┌────────────────┼────────────────┐
        ↓                ↓                ↓
    ChatGPT          Gemini/Gem         Claude
        │                │                │
        └────────────────┼────────────────┘
                         ↓
                  Shared Object
```

へ移行します。

---

# 3. Core Principle

AGRIX-OS Data Contract v1.0では、

> **Natural Language is an Interface; Structured Data is the System Contract.**

を基本原則として固定します。

つまり、

**自然言語を禁止するのではありません。**

自然言語：

- 人間との対話
- 仮説生成
- アイデア生成
- Executive communication

Structured Data：

- AI間通信
- Evidence
- Domain Objects
- Model Input/Output
- KPI
- Audit
- Version Control

と役割を分離します。

# 37. Formal Freeze

## **AGRIX-OS Data Contract v1.0 — FROZEN**

正式決定事項：

1. **Canonical Object Modelを15 Objectに固定**
2. **Source / Observation / Evidence / Claimを分離**
3. **Observation / Mechanism / Outcome / Impactを分離**
4. **Impact / Value / Asset / Financeを分離**
5. **Provenanceを全Data Objectに要求**
6. **Evidence Statusを必須化**
7. **UNKNOWNを正式なAI Outputとして許容**
8. **SimulationとObserved Dataを分離**
9. **AI-to-AI通信ではStructured DataをCanonical Interfaceとする**
10. **Natural LanguageはHuman/AI Interfaceとして残す**
11. **HealthBook/MIOSは別Data Contractとして管理**
12. **PBPEはImpact Asset Layerとして接続**
13. **AGRIX-OS Data Contractを今後のSchema/API設計の上位規約とする**
