# 3. Reference Datasetの基本原則

Reference Datasetは、17 Repositoryの全データを一度に投入するものではありません。

まず、

> **AGRIX-OSを代表する最小だが十分なCanonical Knowledge Set**

を作ります。

これを **Golden Reference Dataset** とします。

```
17 Repositories
      ↓
Asset Registry
      ↓
Evidence Registry
      ↓
Ontology
      ↓
Canonical Objects
      ↓
Golden Reference Dataset
```

これにより、後から大量データを投入しても、

**「正しいAGRIX-OS KGとは何か」**

を比較できます。

**実測値が資料に存在しない場合は、絶対に補完しません。**

# 10. Claim Validation

Claimは最重要Validation対象です。

例えば：

```
CLAIM
MBT55 ──[FUNCTION]──> X
```

だけでは登録完了としません。

最低限：

```
Claim
 ├── Subject
 ├── Predicate
 ├── Object
 ├── Evidence
 ├── Provenance
 ├── Epistemic Status
 └── Confidence
```

が必要です。

---

# 11. EvidenceとClaimの分離

今回、重要なGovernance Ruleとして固定します。

```
Evidence ≠ Claim
```

さらに、

```
Claim ≠ Fact
```

です。

例えばAIが資料から、

> 「この機構が存在する可能性がある」

と推論した場合、

```
epistemic_status = INFERRED
```

とし、Evidenceそのものとして登録しません。

---

# 12. Validation Suite

Validation Suiteは5層構造とします。

```
                 Validation Suite
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
     Schema          Ontology       Referential
     Validation       Validation     Integrity
        │               │               │
        └───────────────┼───────────────┘
                        ▼
                 Evidence / Provenance
                        │
                        ▼
                  Graph Integrity
```

---

# 13. Level 1 — Schema Validation

検証対象：

- Required fields
- Data types
- Enum
- Format
- Array structure
- ID format
- Version

例：

```
id = required
type = required
version = required
status = required
```

---

# 14. Level 2 — Ontology Validation

例えば、

```
MBT55
```

を、

```
FinancialEntity
```

として登録することを禁止します。

Ontology ClassとDomainの整合性を検証します。

---

# 15. Level 3 — Referential Integrity

Graphの参照切れを検出します。

```
REL-001
subject = ENT-001
object  = ENT-999
```

なのに、

```
ENT-999
```

が存在しない場合：

```
FAIL
```

とします。

---

# 16. Level 4 — Evidence / Provenance Validation

Claim：

```
CLM-MBT-000001
```

に対して、

```
evidence_refs = []
```

なら、

```
FAIL
```

とします。

ただし、

```
epistemic_status = HYPOTHESIZED
```

など、Evidenceを要求しないObjectについては例外ルールを設けます。

---

# 17. Level 5 — Graph Integrity

以下を検証します。

```
Orphan Nodes
Broken Edges
Circular Invalid Relations
Duplicate IDs
Duplicate Claims
Invalid Predicates
Missing Evidence
Missing Provenance
Version Conflicts
```

---

# 18. Contradiction Validation

AGRIX-OSでは、矛盾を削除しません。

例えば：

```
Claim A
    ↓
SUPPORTED

Claim B
    ↓
CONTRADICTED
```

の場合、

```
CONTRADICTED
```

という状態自体をKnowledge Graphに保存します。

これによりAIは、

> 「どちらが正しいか」

をReasoning対象にできます。

---

# 19. Regression Dataset

Validation SuiteにはRegression Datasetを持たせます。

```
Golden Dataset
      ↓
KG Update
      ↓
Validation
      ↓
Regression Test
```

過去に正常だったKnowledge Objectが、更新によって壊れていないかを確認します。

# 20. AI Hallucination Detection

今回の設計で特に重要な機能です。

AI生成Objectについて、

```

   ↓

   ↓
Evidence Reference Check
   ↓

   ↓

   ↓

```

を通します。

どれかを満たさなければ、

```

```

としてKnowledge Registryに正式登録しません。
