# Architecture — AGRIX-OS Evidence Registry v1.0

## 正式設計・正式Freeze

**結論：`AGRIX-OS Evidence Registry v1.0` を正式設計し、FROZENとして固定します。**

今回のRegistryは、単なる「資料一覧」ではありません。

これまで蓄積したMBT55資料、17 Repository、映像、PDF、Field Case、M3 Model、PBPE Verificationを、**「どの主張が、どの一次資料・観測・モデル・検証によって支えられているか」まで追跡可能にするEvidence Governance Layer**です。

特に今回のファイル群を見ると、既存資産にはすでにEvidenceの種がかなり存在します。例えばM3-Core-Engineには24時間発酵の観測映像をEvidence Sourceとして参照する一方、N₂O/CH₄係数については「field evidence pending」と明記されています。 またPBPE側には、Evidence Hash、Verifier、Audit Log、第三者検証などの仕組みが既に設計されています。

したがって、**新しくゼロから作るのではなく、既存のEvidence資産を一つのCanonical Registryに昇格させる**方針とします。

# 17. Model Evidence Separation

これは非常に重要なGovernance Ruleです。

```
OBSERVED VALUE
      ≠
MODELLED VALUE
      ≠
SIMULATED VALUE
      ≠
PROJECTED VALUE
```

例えばM3のモデル出力は、

```
MODEL_OUTPUT
```

として保存します。

実測データが得られれば、

```
FIELD_OBSERVATION
```

を別Objectとして登録します。

その後、

```
Model
  ↕
Field Data
```

を比較し、Validationを行います。

# 18. Evidence Quality Score

Evidence Qualityを5軸で管理します。

```
Q1 Source Integrity
Q2 Method Quality
Q3 Reproducibility
Q4 Independent Corroboration
Q5 Verification
```

総合Qualityは、

```
Evidence Quality =
Q1 + Q2 + Q3 + Q4 + Q5
```

という単純加算ではなく、**各軸を独立保持**します。

理由は、

> 高品質な映像Evidenceが存在しても、第三者検証がなければ「Verified」にはならない

ためです。
