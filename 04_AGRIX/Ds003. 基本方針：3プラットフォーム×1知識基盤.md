## 1. 基本方針：3プラットフォーム×1知識基盤

| 項目 | AGRIX | HealthBook | PBPE Marketplace |
|------|-------|-----------|------------------|
| 入力 | 圃場・微生物・気候データ | 問診・血液動態・ライフログ | 資源・経済・炭素データ |
| 中核概念 | MBT55 / MSC | 137疾病リスク表 / Gut–Endocrine Axis | Carbon Loop Bond / グリーンプレミアム |
| 出力 | アーキテクチャ・シミュレーション | 個別健康改善プログラム | 経済価値・投資評価 |
| 共通基盤 | **agrix-knowledge-base (BioNexus Engine)** | 同左 | 同左 |

**キーアイデア**：3プラットフォームは別々のRAGを持つのではなく、**単一のナレッジグラフ＋単一の決定論的計算エンジン**を共有し、検索クエリのコンテキスト（AGRIX/HealthBook/PBPE）で参照範囲と実行モデルを切り替える。これにより、例えば「MBT55」というノード一つが、農業・健康・経済の3側面から同時に引ける。

## 2. ローカルRAGを起点としたアイデア（10項目）

### アイデア①：3モード切替型RAG（Tri-Mode RAG）
- 単一のChromaDBに対し、**メタデータフィルタで参照範囲を切替**。
  - `mode=AGRIX` → `tag:AgriWare`, `03_MBT55`, `05_MSC` のみ
  - `mode=HealthBook` → `tag:HealthBook`, `137疾病`, `Hamada` のみ
  - `mode=PBPE` → `tag:PBPE`, `Carbon`, `Finance` のみ
  - `mode=Integrated` → 全範囲＋ナレッジグラフで橋渡し
- 実装は `ask_rag.py --mode=agrix` のようにCLIオプションで切替。

### アイデア②：ノート種別ごとのチャンク戦略
- AKG024のように**問診シート・137疾病リスク表・ファイトケミカル分類表**は表形式。AKG005のように**アーキテクチャ・数式**は構造形式。
- チャンクを「**散文チャンク／表チャンク／数式チャンク／定義チャンク**」に分け、表はDataFrame、数式はLaTeX＋変数辞書としてメタデータ化。
- 検索時に「数式が欲しい」場合は数式チャンクのみを優先取得。

### アイデア③：概念ハブノードの固定（MBT55, MSC, 137疾病, Carbon Loop Bond）
- AKG005の「共通概念の立体交差」を実装。**ハブノードに到達したら関連3プラットフォームのノートを自動展開**。
- 例：「MBT55」検索 → 農業（第2章）／健康（reCLA, MBT Probiotics）／経済（Carbon Loop Bond）を同時提示。

### アイデア④：決定論的計算エンジンへの自動ルーティング
- 検索結果に `model_id`（例：`soc_dynamics`, `gut_endocrine_axis`, `carbon_loop_bond`）が含まれる場合、**LLMではなくPython関数を呼び出す**。
- AKG014の「RAG→Python Engine→LLM」の3層構造を、Vaultのメタデータで自動判定。

### アイデア⑤：浜田プロトコルの「ゆらぎ問診」RAG
- 200問診シートを**質問ベクトル＋意図ベクトル＋疾患寄与ベクトル**の3層で保持。
- 患者の自由記述から、ゆらぎ表現を介して複数の問診項目にマッピング。AKG024の「質問表現をゆらぎ手法で重ねる」をRAGで実装。

### アイデア⑥：137疾病リスク表のナレッジグラフ化
- 「質問×疾患」の＋/−相関マトリクスを**二部グラフ**として保持。
- 例：「色の濃い野菜×肺がん＝+」「色の濃い野菜×慢性胃炎＝−」をエッジ属性で保持。
- RAG検索時に、患者の問診回答セットから**リスク寄与の合成スコア**を計算。

### アイデア⑦：Gut–Endocrine Axis の双方向ループをRAGで表現
- AKG024の6段階ループ（腸内細菌→代謝産物→内分泌→全身代謝→腸環境）を**循環グラフ**として保持。
- 検索クエリが「GLP-1」なら、上流（アミノ酸代謝）と下流（インスリン・摂食行動）を同時に取得。

### アイデア⑧：MBT Probiotics スクリーニングのRAG＋計算
- 漢方・ファイトケミカル分類表をベクトル化し、MBT55代謝経路モデル（AKG024の解糖系→PDH→TCA→ATP）と結合。
- 個人の代謝ボトルネック（例：PDH補酵素不足）に対し、**候補アイテムをRAGで検索→ATP改善率をPythonで計算**。

### アイデア⑨：GitHub⇔Obsidian⇔ChromaDBの自動同期（AKG014準拠）
- `update_rag_index.py` をファイル監視＋GitHub Actionsで自動実行。
- ノート更新時に**影響を受けるハブノードと計算モデルを再評価**し、シミュレーション結果を再生成。

### アイデア⑩：トレーサビリティ付き回答
- 全回答に「Git Commit + ノートパス + 行番号 + 使用した計算モデル」を付与。
- AKG005のSSOT（Single Source of Truth）とAKG014のハルシネーション・フリーを、RAG層で担保。

## 3. ローカルアクセス（RAG）からシミュレーション構築への流れ

```
[Vault 6,600+ノート]
   │  build_rag_index.py（見出し・表・数式・メタデータ）
   ▼
[ChromaDB + ナレッジグラフ]
   │  ask_rag.py --mode=agrix/healthbook/pbpe/integrated
   ▼
[検索結果 + model_id 判定]
   │  → Python Engine 呼び出し（soc_dynamics, gut_axis, carbon_bond...）
   ▼
[決定論的計算結果]
   │  LLMが根拠付きで説明文生成
   ▼
[AGRIXアーキテクチャ図 / HealthBook処方 / PBPE投資評価]
```

**最初の一歩**としては、AKG015のPhase 1に沿って：
1. `build_rag_index.py` で**3プラットフォーム分のメタデータタグを付与**して初回インデックス化
2. `ask_rag.py` に `--mode` オプションを追加し、Tri-Mode RAGを試作
3. AKG024の137疾病リスク表・200問診シートを**表チャンクとして構造化**し、アイデア⑥の二部グラフを試作

## 4. 次に詰めるべき論点

| 論点 | 選択肢 |
|------|--------|
| ナレッジグラフの実装 | NetworkX（軽量）／Neo4j（本格）／ChromaDBメタデータのみ（最小） |
| 埋め込みモデル | OpenAI Embeddings（AKG014踏襲）／multilingual-e5（完全ローカル） |
| 計算エンジンの呼び出し | ルールベース（model_id）／LLM Tool Use／ハイブリッド |
| 3モードの境界 | タグベース／ディレクトリベース／ハブノードベース |
