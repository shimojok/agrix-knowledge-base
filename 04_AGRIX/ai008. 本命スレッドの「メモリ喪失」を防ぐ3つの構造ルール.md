### 1. 本命スレッドの「メモリ喪失」を防ぐ3つの構造ルール

スレッドが長くなると、AIは「初期のシステム前提」や「16リポジトリの仕様」を忘れます。これを防ぐためのコンテキスト管理手法です。

#### ① プロンプトの「プレフィックス固定（コンテキストアンカー）」

本命スレッドで長文のやり取りを行う際、毎回の指示の先頭に数行の「コンテキストアンカー（固定定義）」を挟むか、定期的に再読み込みさせます。

```xml
<context_anchor>
  【プロジェクト】agrix-knowledge-base / BioNexus Executive Engine
  【現在地】Phase 2 コアエンジン実装完了 -> Phase 3 ダッシュボード構築中
  【基本数式/モデル】AGRIX(炭素) + HealthBook(浜田137リスク/PDH/ATP/GLP-1) + PBPE(トークン)
</context_anchor>

```

#### ② セッション跨ぎ時の「State Dump（状態出力）」の義務付け

スレッドの会話数が多くなったら、新しいスレッドに移行する前にAIに現在の状態を出力させます。

* **指示文:** 「これまでの決定事項、作成したスクリプト一覧、次回開始時のタスクをMarkdown形式で短くサマリー（State Dump）してください。」
* **運用:** 出力されたState Dumpだけを新しいスレッドの1通目に貼り付けて再開します。

### 2. トークン消費を90%削減する「プロンプト圧縮」テクニック

16リポジトリや6,400件のノートをそのまま読ませるとトークンを劇的に消費するため、AIへ渡すデータを事前圧縮します。

#### ① コードのスケルトン（型・構造）圧縮

関数の中身（body）を捨て、定義と型だけを渡します。

* **圧縮前（生のPythonコード）:** 100行（処理ロジックやコメントが詰まっている）
* **圧縮後（AI向けスケルトン）:** 5行
```python
class HealthBookEngine:
    def __init__(self, mbt_probiotics_dose_g: float, tcm_herb_input_g: float): ...
    def calculate(self) -> dict: ... # Returns: SCFA, GLP-1, ATP, ORP metrics

```



#### ② Obsidian ノートの「ヘッダー・リンク抽出」圧縮

Obsidianノート（.md）本文を丸ごと渡さず、YAMLヘッダー、見出し（#）、内部リンク（`[[...]]`）のみを抽出したXML形式に変換して渡します。

### 3. 本命スレッド向け：ハルシネーション防止用・システムプロンプト構成案

本命スレッドのAIに最初に読み込ませる（またはプロンプトの冒頭に置く）ことで、無駄な自動推測やハルシネーションを強力に抑止するプロンプト設計です。

```xml
<system_instruction>
  あなたは agrix-knowledge-base の PMO / 開発エンジニアです。

  【行動原則】
  1. 提示されたコード・Obsidianノート・数理モデルの「事実」のみに基づいて回答してください。
  2. 情報が不足している場合や文脈が不明確な場合は、勝手に推測してコードや理論を補完せず、「〇〇の情報が不足しています」と明示して停止してください。
  3. 回答を出力する際は、必ず参照したモジュール名（例: bionexus_sim_engine.py）やAKGノート番号（例: AKG024）を根拠として明示してください。
  4. 記憶の断絶を防ぐため、複雑なタスクの開始前には「理解した要件の短文サマリー」を最初に出力してから実装に入ってください。
</system_instruction>

```
