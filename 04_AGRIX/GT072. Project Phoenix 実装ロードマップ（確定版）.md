# Phase 3

## PMOS Knowledge Governance v1.0

これは、PMOS全体の「知識の憲法」に相当する運用仕様です。

### 目的

AIが知識を検索できることよりも、

**AIが正しい知識だけを使うこと**

# Governanceで定義する内容

## 1. Knowledge Lifecycle

すべての知識に状態を持たせます。

```text
Idea
   ↓
Research
   ↓
Draft
   ↓
Review
   ↓
Approved
   ↓
Official
   ↓
Archived
```

AIは **Official** を優先し、**Draft** は必要な場合のみ参照します。

---

## 2. Document Classification

PMOSでは文書種別を統一します。

* Manifesto
* Constitution
* Architecture
* Specification
* White Paper
* ADR (Architecture Decision Record)
* Research Note
* Business Proposal
* API Contract
* Data Contract
* Implementation Guide
* Governance Rule
* Meeting Record

---

## 3. AI Reference Priority

AIが回答時に参照する優先順位を定義します。

1. Manifesto / Constitution
2. Architecture
3. Specification
4. ADR
5. White Paper
6. Research Note

これにより、構想メモが正式仕様より優先されることを防ぎます。

---

## 4. Repository Governance

各リポジトリに共通の構造を採用します。

```text
/docs
/specifications
/architecture
/governance
/adr
/research
/models
/src
/tests
```

---

## 5. Knowledge Metadata

すべてのKnowledge Objectに共通メタデータを付与します。

```yaml
KnowledgeID
Repository
Category
Lifecycle
Version
Language
Tags
Dependencies
Status
ReviewDate
```

---

## 6. AI Governance

AIエージェントの役割を明確化します。

* **Architect Agent**：設計整合性の確認
* **PMO Agent**：文書品質・ライフサイクル管理
* **Research Agent**：研究ノート・外部情報の整理
* **Implementation Agent**：コード・実装支援
* **Executive Agent**：提案書・プレゼンテーション作成

# ここから実装へ

Knowledge Governanceが確定したら、実装は以下の順で進めます。

1. **PMOS-Sync-Pipeline リポジトリ作成**
2. **GitHub Repository Loader**
3. **Chunk / Metadata Engine**
4. **Embedding Engine**
5. **Pinecone同期**
6. **GitHub Actionsによる自動同期**
7. **AIエージェント統合**

この順序で進めることで、将来PineconeやEmbeddingモデルが変わっても、PMOSの知識資産と統治ルールは維持されます。

これは、Project Phoenixを一過性のシステムではなく、**長期にわたり進化できる知識プラットフォーム**として育てるための基盤になります。
