隣のスレッドで、agrix-knowledge-base をローカルRAG化したように、16のリポジトリを直接、AIがクロール、検索し、システムアーキテクチャ構築をするテクニックはないのですか？AIの機能は高くても、負の特性が目立つのでは進展しません。

---

仰る通りです。LLMのコンテキストウィンドウが100万〜200万トークンに拡大したとはいえ、**「巨大なファイルをテキストとして丸ごと流し込む方法（コンテキスト投入）」は、読み飛ばし（Needle in a Haystack）やトークンコスト、ハルシネーションというAIの負の特性が強く出てしまいます。**

  

`agrix-knowledge-base` でRAG（検索拡張生成）を構築されたように、16個のリポジトリに対しても**AIに直接ローカルコードベースを「自律的に検索・クロール・コードジャンプ」させながらアーキテクチャを理解させる手法**が存在します。

  

現代のソフトウェア開発において、この問題に対する**最も確実で実用的な3つのアプローチ**を提案します。

  

### 1. Cline / Roo Code などのAI Agent（MCP連携）を使う【最も推奨】

VS Codeなどのエディタ上で動くオープンソースのAIエディタ拡張（**Cline** や **Roo Code** など）を利用する方法です。これらは「ファイルを一気に読む」のではなく、AIが人間のようにコード内を探索します。

  

- **仕組み:**
    
    16個のリポジトリを1つのローカルワークスペース（マルチルートワークスペース等）にまとめます。AIは必要に応じて `grep`（全文検索）、ファイル構造の確認、関連ファイルの読み込みを**自律的にツールを呼び出しながら繰り返し実行**します。
    
      
    
- **MCP (Model Context Protocol) の活用:**
    
    MCPサーバーを導入することで、リポジトリの構造解析をさらに強力にできます。
    
      
    - **FileSystem MCP / Git MCP:** AIがローカルフォルダを自由に検索・閲覧できるようにする。
        
          
        
    - **Code Search MCP (例: Sourcegraph, Serpl, Greptile等):** コードシンボルや定義ジャンプ、依存関係グラフをAIに検索させる。
        
          
        

> **メリット:** 全テキストをコンテキストに詰め込まないため、コンテキスト汚染や読み飛ばしが発生せず、正確なコード位置に基づいたアーキテクチャ設計が可能です。
> 
>   

### 2. ローカルコード専用RAG / ナレッジグラフツールの構築

通常のテキスト用RAG（LangChain等で単純分割したもの）では、コードの構造や関数呼び出しの依存関係が切れてしまい、システム全体のアーキテクチャ把握には不向きです。コード専用のRAG構造をローカルに構築します。

  

- **AST (抽象構文木) ベースのベクトル化:**
    
    単なる文字数分割ではなく、AST解析（Treesitter等を利用）でクラス、関数、モジュール単位でチャンク化してベクトルDB（Qdrant, Chroma, LanceDB等）に格納します。
    
      
    
- **Graph RAG（ナレッジグラフ + RAG）:**
    
    リポジトリ間の呼び出し関係やモジュール依存関係をグラフDB（Neo4j等）に保持させ、ベクトル検索とグラフ検索を組み合わせます。
    
      
    - 例: 「`repo-auth` のログイン処理から呼び出されている他リポジトリのAPIは？」といったクエリに対して、グラフ構造を辿って正確なコンテキストだけをAIに抽出して渡します。
        
          
        

### 3. Cursor などの「ローカルインデックス型」AI IDEの活用

16リポジトリを単一のワークスペースにまとめ、コードベース全体をインデックス化する機能を備えたAIエディタ（Cursor等）を利用します。

  

- **仕組み:**
    
    バックグラウンドでコードベース全体のシンボルや依存関係を自動でベクトル・グラフ化（Codebase Indexing）します。
    
      
    
- **利用方法:**
    
    `@Codebase` や `@Folder` を指定して質問することで、16リポジトリの中から**質問（アーキテクチャ設計）に関連する最適なコードスニペットだけをAIが自動で検索・抽出して回答**を生成します。
    
      
    

### なぜこれが「負の特性」を回避できるのか？

|**手法**|**仕組み**|**メリット**|**負の特性への対策**|
|---|---|---|---|
|**丸ごとテキスト投入 (Repomix等)**|16リポジトリの全コードをプロンプトに入れる|手軽|❌ **読み飛ばし・ハルシネーションが発生しやすい**|
|**AI Agent (Cline / Roo Code)**|AIが検索コマンドを発行し、必要なファイルだけを開く|非常に正確・最新コードに対応|⭕ **必要な部分だけを読むため読み飛ばしゼロ**|
|**コード専用RAG / Graph RAG**|ASTや依存関係をDB化し、関連箇所のみ抽出|巨大コードベースでも高速|⭕ **コンテキストサイズ制限を根本解決**|
