## 4. ハルシネーション・メモリ異常を徹底排除する技術構想（4つの軸）

チャットAI内での長文コード出力・コンテキスト肥大化による破綻を防ぐため、以下のアーキテクチャを採用します。

1. **ローカルRAG（ChromaDB / LangChain / LlamaIndex 等）の導入**
    
    - 16リポジトリのソースコードおよび各種ナレッジドキュメント（Markdown/Excel/JSON）をローカルでベクトル化・インデックス化。
        
    - AIは全文をコンテキストに読み込むのではなく、必要な関数・型定義・ナレッジのみをRAG検索でピンポイント取得する構造へ転換。
        
2. **JSON Schema による厳格なデータ契約（Data Contract）**
    
    - 各ナレッジファイル（`healthbook-knowledge-base.json` 等）の厳密な `json-schema.json` を定義。
        
    - Python（Pydantic v2）により、データ生成・読み込み時に 1 バイトの構造ブレも許さないバリデーションガードを配置。
        
3. **モジュール分割と自動統合スクリプト（Build Pipeline）**
    
    - チャット上での「コード全量出力」を止め、コンポーネント単位（モデル、リポジトリ、ドメインロジック、パイプライン）で小分けに設計・テスト。
        
    - ローカル側の Python スクリプトで全モジュールを自動結合・テスト評価する仕組みを確立。
        
4. **ダッシュボード構築の凍結**
    
    - バックエンドのドメインロジック・RAG・JSON基盤が完全に構築され、検証評価が完了するまで UI 開発は一切停止。
