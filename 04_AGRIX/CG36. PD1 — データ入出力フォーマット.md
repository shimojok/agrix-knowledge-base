です。

# 2. PD2 — Python + Local RAG

### 判定：方向性は正しい

ここはKazさんが準備するInfrastructureです。

ただし、1点だけ重要な改善があります。

## RAGを「Knowledge Database」と定義しない

RAGは、

> **検索Index**

です。

Canonical Knowledgeそのものではありません。

正式には、

```text
Source of Truth
      │
      ├── Git Repository
      ├── Source Documents
      └── Canonical Registry
             │
             ▼
       Local RAG Index
             │
             ▼
       Retrieval
             │
             ▼
          AI Agent
```

とします。

したがって、

**ChromaDB ≠ PMOS Knowledge Base**

です。

ChromaDBは、

**PMOS Knowledge Retrieval Infrastructure**

と位置付けます。

# 5. PD4 — SQLite

### 判定：有用。ただし主系統を決める

PD4には、かなり重要な選択肢が整理されています。

提示された内容では、ChromaDBはSQLite + HNSWを利用するPersistent構成で、単一フォルダに永続化できます。

また、sqlite-vecを使えば単一`.db`ファイルにまとめる方式も提示されています。

比較表でも、ChromaDBは導入容易性、sqlite-vecは単一DBファイルという運用上の利点が整理されています。

### 私の推奨

現段階では、

**ChromaDBをPrimary Retrieval Store**

としてください。

SQLiteは、

**Metadata / Registry / Audit Store**

として利用する構成がきれいです。

```text
                 Local PMOS Knowledge Infrastructure
                              │
               ┌──────────────┴──────────────┐
               ▼                             ▼
          ChromaDB                        SQLite
       Vector Retrieval              Metadata / Registry
               │                             │
               └──────────────┬──────────────┘
                              ▼
                       Reconciliation
```

# 6. ただし、PD4には一つ注意

PD4の、

> 「ベクトルデータをSQLiteに保存する」

という考え方と、

> 「Canonical RegistryをSQLiteで管理する」

という考え方は分けた方がよいです。

後者は非常に有効です。

例えば、

```text
pmos_registry.db

sources
repositories
files
claims
evidence
canonical_objects
reconciliation_queue
validation_results
```

という構造です。

一方、Vector StoreについてはChromaDBに任せる。

これなら役割が明確になります。

# 8. ASTについては、さらに重要な改善があります

Kazさんが挙げた、

> **AST（抽象構文木）解析による精密データ伝達**

は、このプロジェクトでは非常に重要です。

ただし、私はこれをRAGの補助機能ではなく、

## **Structural Knowledge Extraction Layer**

として独立させることを推奨します。

```text
Repository
     │
     ├──────────────┐
     ▼              ▼
 Text Parser       AST Parser
     │              │
     ▼              ▼
Semantic          Structural
Knowledge         Knowledge
     │              │
     └──────┬───────┘
            ▼
       Knowledge Object
```

これにより、

**「AIがコードを読んで理解した」**

ではなく、

**「Python ASTから実際に存在するClass / Function / Import / Call構造を抽出した」**

という決定論的情報を保持できます。
