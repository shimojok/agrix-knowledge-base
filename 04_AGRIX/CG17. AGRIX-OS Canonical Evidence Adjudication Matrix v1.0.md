# 1. 結論

ここで重要なのは、29 Objectsを「正しい／間違い」の二択で判定しないことです。

AGRIX-OSでは、以下を分離します。

```
                 CANONICAL OBJECT
                        │
          ┌─────────────┼─────────────┐
          ▼             ▼             ▼
       Evidence       Claim         Model
          │             │             │
          ▼             ▼             ▼
      VERIFIED       CLAIM ONLY    MODELLED
          │             │             │
          └─────────────┼─────────────┘
                        ▼
                 Golden Candidate
                        │
                        ▼
                 AGRIX Knowledge Graph
```

特に今回のRepositoryには、**「Observed」「Model-derived」「Pending」が同じデータ構造の中に存在する**ことが確認できます。

例えばM3-Core-Engineでは、24時間分解について `decomposition_rate_24h = 1.0` と記録される一方、同じmetadataに「direct metabolite CSVが必要」と明記されています。

さらにN₂O/CH₄係数についてはschemaそのものが `PENDING — requires field measurement data` と明示しています。M3-Core-Engine.txtTXT

したがって、今回のAdjudication Matrixは**AIによる過大評価を防止するEvidence Firewall**として機能させます。

# 3. Adjudication Classification

## E0 — Source

原資料・映像・文書・コード・ログそのもの。

## E1 — Observation

直接観察・実測された現象。

## E2 — Verified Evidence

規定された検証手続きにより確認されたEvidence。

## E3 — Model-Derived

数式・Simulation・Economic Model等から導出された値。

## E4 — Claim

資料・Repositoryに記載された主張。

## E5 — Hypothesis / Scenario

仮説・将来予測・Scenario。

# 4. Status Vocabulary

|Status|意味|
|---|---|
|`SOURCE_CONFIRMED`|原資料を確認|

Evidence不足を明示したままKnowledge Graphに保持するための状態です。
