## 目的と定義、原点

目的と定義、原点である `AGRIX_Theory_MBT55_ja` および指定ノート（`AKG005`, `AKG019`, `AKG020`, `AKG021`, `AKG022` 等）に示された全構想を再確認し、本プロジェクトが目指すべき全体構造と確固たる定義を再構築しました。

ご指摘の通り、これまでのダッシュボード作成（UI構築）は時期尚早でした。 本丸である **`agrix-knowledge-base`** は、単なる浜田ファイルのWeb可視化ではなく、**土壌（AGRIX）から経済（PBPE）、そして人体・ライフログ（HealthBook）へとつながる全一的な代謝連鎖（Soil-Gut-Metabolic Axis）を数理的・構造的に表現する基盤**です。

生成AIの文脈長制限やメモリ異常・ハルシネーションに二度と依存せず、**ローカルRAGとコード/JSONによる決定論的計算基盤**を用いて、本丸の `agrix-knowledge-base` を完成させるための「全体スキーム」「現状整理」「実装計画」を整理して提示します。

## 1. プロジェクトの原点と真の目的の再定義

本プロジェクトの原点は、**`AGRIX_Theory_MBT55_ja`** にあります。 それは、**微生物生態系ベースの代謝再接続モデル（M³-BioSynergy System / MBT55）** により、電子の流れと元素循環を再構築する構想です。


この原点から展開される 3 大プラットフォームと本丸 `agrix-knowledge-base` の関係性は以下の通りです。

  
```Plaintext
========================================================================================
                      agrix-knowledge-base (BioNexus Engine: 本丸)
========================================================================================
   │
   ├── [ 1. AGRIX Platform (広域炭素・土壌・農業基盤) ]
   │    └── MBT55による土壌微生物相の再構築、炭素固定、有機代謝産物の増大[cite: 8, 11]
   │
   ├── [ 2. PBPE Marketplace Platform (分散型経済・資材循環基盤) ]
   │    └── 物質循環に基づくカーボンクレジット、MSC（物質・情報・経済）価値循環[cite: 8, 9]
   │
   └── [ 3. HealthBook Platform (生命・人体・代謝循環・フェノタイピング) ]
        │   └── 生成物: healthbook-knowledge-base.json (※命名と位置づけの正当化)
        │
        ├── A. ライフログ & 疾患フェノタイピングモデル

        │    ├── mbt-kampolibrary / MBT漢方代謝ライブラリー（生薬巨大分子の代謝超高速変換）[cite: 10]
```

### HealthBook の位置づけと重要性

浜田ファイル（200問診＋137疾病リスク）やファイトケミカル表は、単なるリスクチェック表ではなく、**ユーザーの生体状態を捉えるライフログであり、フェノタイピングモデルの根幹**です。 これらが **MBT Probiotics / 漢方代謝ライブラリー** と結合することで、**「土壌微生物（AGRIX）➔ 食・ファイトケミカル ➔ 腸内細菌代謝（MBT Probiotics）➔ 内分泌（GLP-1等）・ATP産出」** という一連の科学的メカニズムが完成し、AIヘルスケアモデルとしての真の価値を発揮します。

## 3. ハルシネーション・メモリ異常を排除する全体スキームと技術構想

チャットAI内部の文脈肥大化による破綻を防ぎ、16 リポジトリとナレッジドキュメントを自律的かつ確定的に参照・計算するための 4 つのアーキテクチャ原則を確立します。


```Plaintext
[ Obsidian Vault (AKG / ノート) ] + [ 16 GitHub Repositories (Python/Code) ]
                                   │
                                   ▼ (ローカルインデックス化)
                   ┌───────────────────────────────┐
                   │   Local Vector DB (ChromaDB)  │
                   │  & Code Dependency Analyzer   │
                   └───────────────┬───────────────┘
                                   │ (必要な文脈・モジュールのみ抽出)
                                   ▼
                   ┌───────────────────────────────┐
                   │     BioNexus Core Engine      │
                   │ (Python Execution/ODE Solver) │
                   └───────────────┬───────────────┘
                                   │ (厳格な Pydantic ガード)
                                   ▼
                [ healthbook-knowledge-base.json ]
```

1. **ローカル RAG 基盤の構築（ChromaDB + Ollama/e5-small）**
    
    - 16 の GitHub リポジトリ（コード・AST・数式モデル）および AKG ノート群をローカルの Vector DB に常駐。
       
    - チャットAIにコード全量を読み込ませるのではなく、必要最小限のクラス定義や数式（ODE等）を RAG 経由で検索・注入する設計。
       
2. **Data Contract（厳格な Pydantic v2 スキーマ定義）**
    
    - データ構造の揺らぎや AI のハルシネーションを排除するため、すべての JSON 生成・読み込みに厳密な型定義（Pydantic / JSON Schema）を適用。
    
3. **決定論的 Python コードエンジンの分離**
    
    - ATP 算出、GLP-1 ホルモン発現予測、短鎖脂肪酸（SCFA）フラックス、炭素固定量（5.8 tCO₂e/ha/年）などの数理計算は、LLM ではなく検証済みの Python 数理モデル（ODE solver / 代謝ネットワーク計算）に委ねる。
        
4. **UI（ダッシュボード）構築の完全凍結**
    
    - バックエンドの RAG パイプライン、`healthbook-knowledge-base.json` の完全化、全代謝経路・ATP・内分泌計算ロジックが CLI 上で 100% 決定論的にテスト通過するまで UI 開発は一切行わない。
        
        
## 4. 今後の進行ロードマップ（段階的実装計画）

### 【Phase 1】`healthbook-knowledge-base.json` の設計・生成スクリプト完全化

- **目的:** `agrix-knowledge-base` 内の `HealthBook` 領域のスキーマを完全に確立する。
    
- **タスク:**
    
    1. 出力ファイル名を **`healthbook-knowledge-base.json`** に正式改称。
        
    2. 200項目問診シート（揺らぎ表現解析）、137/123疾病リスク表、ファイトケミカル分類表、漢方代謝ライブラリー、動物薬、Probiotics を網羅する Pydantic モデル（`src/agrix_kb/models/healthbook.py`）の構築。
        
    3. データを単一の `healthbook-knowledge-base.json` に構造化して出力する一括変換スクリプトの作成。
        
### 【Phase 2】ローカルRAG ＆ 16リポジトリ統合参照エンジンの構築

- **目的:** 16 リポジトリとナレッジノートをローカル環境で自動参照・解析できるようにする。
  
- **タスク:**
    
    1. 16 リポジトリのソースコードおよび Obsidian ノート（AKG シリーズ等）をベクトル化する ローカル RAG 構築スクリプトの作成。
    
    2. リポジトリ間の依存関係やインターフェース不整合を静的解析（AST）するアナライザーの完成。
    
### 【Phase 3】全代謝経路・内分泌系・ATP算出エンジンの実装

- **目的:** HealthBook データと生体メカニズム（代謝・内分泌）の結合。
    
- **タスク:**
    
    1. MBT Probiotics / 漢方代謝バイオトランスフォーメーションモデル（SCFA生成量、GLP-1/PYY分泌シグナル）のコード化[cite: 10, 11]。
        
    2. ミトコンドリア ATP 産出効率および ORP（酸化還元電位）計算モジュールの実装[cite: 10, 11]。
        
### 【Phase 4】統合バッチテスト ＆ 定量評価

- **目的:** ハルシネーションゼロの確定型シミュレーションおよび整合性検証。
    
- **タスク:**
    
    1. `pytest` による問診データ ➔ 代謝変換 ➔ 内分泌/ATP 影響度のエンドツーエンドテスト実行。
        
    2. エグゼクティブ向け統合レポートの自動出力（CLI / Markdown）。
