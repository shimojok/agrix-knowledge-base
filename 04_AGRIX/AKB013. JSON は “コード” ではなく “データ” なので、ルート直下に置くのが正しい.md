あなたの質問：

> JSONコードはどうしますか？

これは **NotebookLM → Claude → Python → UI → Azure** の流れを壊さないために、正しい配置と役割を理解する必要があります。

# 🟥 結論（最重要）

## **JSON は “コード” ではなく “データ” なので、ルート直下に置くのが正しい。**

## **ただし、置くべき JSON は 1つだけ：canonical_data.json（唯一の真値）。**

理由は明確です：

- Python計算エンジンが直接読み込む
    
- UIが直接参照する
    
- Azure Functionsが直接参照する
    
- Claudeがロジック生成時に参照する
    
- NotebookLMが構造化データを返すときの「正解」として使う
    

つまり、**JSON は AGRIX Knowledge Base の “心臓”** です。

# 🟩 なぜ canonical_data.json をルート直下に置くのか？

### ✔ Python計算エンジンが直接読み込むため

例：

python

```
import json

with open("canonical_data.json") as f:
    data = json.load(f)
```

階層が深いと Azure Functions が参照パスでエラーを起こします。

### ✔ UI（ダッシュボード）が直接参照するため

UI は API 経由で canonical_data.json を読み込みます。

### ✔ Claude がロジック生成時に参照するため

Claude向けプロンプトに canonical_data.json を貼ることがあるため、 ルート直下が最も扱いやすい。

### ✔ NotebookLM が構造化データを返すときの「正解」として使うため

NotebookLMは JSON を返しますが、 その「正解」が canonical_data.json です。

# 🟦 では、NotebookLM が返す JSON はどうするのか？

## 🟥 結論

### **NotebookLM が返す JSON は “コードではなく成果物” なので、GitHubに保存して OK。**

ただし、**計算に使うのは canonical_data.json のみ**。

NotebookLM の JSON は：

- Claude に渡す
    
- 設計の材料にする
    
- RAG の検索対象にする
    
- GitHub に保存する（成果物として）
    

しかし、**計算には使わない**。

計算は canonical_data.json のみを使う。

# 🟩 NotebookLM の JSON の正しい配置

コード

```
agrix-knowledge-base/
    22_Claude/
        methane_reduction_summary.json
        pbpe_finance_model.json
        mbt55_processing_model.json
```

または：

コード

```
agrix-knowledge-base/
    11_AI_Development/
        notebooklm_outputs/
            methane_reduction_summary.json
```

どちらでも良いですが、 **ルート直下には置かない**のが正しい。

理由：

- 計算エンジンが誤って NotebookLM の JSON を読み込むと壊れる
    
- canonical_data.json と混同する
    
- Claude が誤参照する
    
- Azure Functions が誤参照する
    

# 🟦 JSON の分類（PMOとしての最終整理）

|JSONの種類|役割|配置|
|---|---|---|
|**canonical_data.json**|公式数値テーブル（唯一の真値）|**ルート直下**|
|NotebookLMのJSON|構造化データ（候補値）|22_Claude/ または 11_AI_Development/|
|ClaudeのJSON|UI・ロジック生成用|22_Claude/|
|RAG用にtxt化したJSON|RAG検索対象|txt/|
