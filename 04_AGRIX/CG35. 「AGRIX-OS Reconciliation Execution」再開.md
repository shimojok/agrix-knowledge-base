# 2. まず「RAG」と「AST」を分離してください

ここは非常に重要です。

## RAG

RAGは、

> **意味的に関連する情報を探す**

ためのものです。

```text
質問
 ↓
Embedding
 ↓
Vector Search
 ↓
Relevant Chunks
```

## AST

ASTは、

> **コードの実際の構造を決定論的に読む**

ためのものです。

```text
Python
 ↓
AST
 ├── Module
 ├── Class
 ├── Function
 ├── Import
 ├── Call
 └── Dependency
```

したがって、

```text
RAG
＝ Semantic Retrieval

AST
＝ Structural Extraction
```

です。

**両者を混ぜないことが重要です。**

# 6. 最重要：Chunkではなく「Source Identity」を先に作る

RAG実装でよくある失敗が、

```text
PDF
 ↓
chunks
 ↓
embeddings
```

から始めることです。

AGRIX-OSでは逆に、

```text
Repository
 ↓
File
 ↓
File Hash
 ↓
Source ID
 ↓
Document Type
 ↓
AST / Text Extraction
 ↓
Chunk
 ↓
Embedding
```

とします。

例えば、

```text
AGRIX-SRC-MBT-001
AGRIX-SRC-PBPE-017
AGRIX-SRC-M3-004
```

のようなSource IDを持たせます。

その下に、

```text
SRC-001
 ├── CHUNK-001
 ├── CHUNK-002
 ├── CHUNK-003
 └── ...
```

とします。
