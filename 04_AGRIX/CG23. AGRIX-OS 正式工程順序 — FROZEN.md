## 2. 各工程の役割

### Phase ① Test Vector

29 Objectsを対象として、Validationルールを実際に試験可能な状態にする。

**目的：**

> 「AGRIX-OSが壊れたデータを正しく拒否できるか」を先に確認する。

---

### Phase ② Reconciliation

Test Vectorで検出された問題を、

```
Conflict
   ↓
Classification
   ↓
Evidence Requirement
   ↓
Reconciliation Proposal
   ↓
Human Adjudication
```

として処理する。

**AIは修正を確定しない。**

---

### Phase ③ Canonical Dataset v1.1

Human Adjudicationを経た結果だけをCanonical Datasetへ反映。

```
v1.0
 ↓
Validation
 ↓
Reconciliation
 ↓
Adjudication
 ↓
v1.1
```

したがって、**Dataset Versionは監査可能な状態遷移**になります。

---

### Phase ④ Engine Implementation

Dataset v1.1を基準として初めてValidation & Reconciliation Engineを実装する。

これにより、

> **「仕様を作ってからデータを合わせる」のではなく、「実データを壊して検証してからEngineを実装する」**

という順序になります。

---

# 3. Governance Rule

今後のAGRIX-OSでは以下を固定します。

### Rule 01

**Canonical Dataset v1.0を直接変更しない。**

### Rule 02

問題は必ずReconciliation Queueへ送る。

### Rule 03

AIはEvidence Statusを単独で昇格させない。

### Rule 04

Dataset v1.1への変更にはAdjudication Recordを要求する。

### Rule 05

Engine実装はDataset v1.1確定後に開始する。

### Rule 06

Engine実装後も、DatasetとEngineを独立Version管理する。
