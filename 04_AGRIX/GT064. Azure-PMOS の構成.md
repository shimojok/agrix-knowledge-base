# 私の見解

このリポジトリを見て分かったことがあります。

**これはPinecone投入前の「知識ソース」として非常に扱いやすい構成**です。

投入対象はほぼMarkdownとJSONです。

例えば

```
README.md
README_JA.md

01_AGRIX_Platform/README.md

04_Azure_Economic_Impact/docs/*.md
```

は、そのままEmbedding対象になります。

一方、

```
*.py
```

は、現段階ではEmbedding対象から除外することを推奨します（将来、コード支援エージェントを作る場合は別インデックスに登録）。

また、

```
questionnaire_200_jp.json
disease_matrix_137_jp.json
mbt_kampo_library.json
```

は構造化データなので、そのまま1チャンクにせず、用途に応じた分割を検討できます。

# この後の流れ

このリポジトリを基準に、**GitHubから直接取得してPineconeへ登録する自動ローダー**を作成できます。

そのローダーは、

1. GitHubリポジトリを取得
2. Markdown・JSONを抽出
3. チャンク分割
4. OpenAI Embedding生成
5. `agrix-knowledge-base`へ登録

までを一括で実行します。

そうすれば、残り17リポジトリは**リポジトリURLを追加するだけ**で同じ仕組みで取り込めます。

このAzure-PMOSを**テンプレートリポジトリ**としてローダーを作成し、その後18リポジトリへ横展開するのが最も効率的です。
