できれば、両方まとめて進めてください。

---

両方とも、ADR-001の「Layer 2（実装分離）」に沿って、それぞれ独立したリポジトリ（`03-AGRIX` / `04-HealthBook`）に属する形で作成しました。

**AGRIX Agent**は、圃場データ（IoTセンサー・衛星NDVI）に基づく5つのドメイン語彙と、規制基準超過時に確信度に関係なく強制エスカレーションする農業固有ルールを定義しています。

**HealthBook Agent**は、AGRIXとの決定的な違いとして**プライバシー要件**（PHIを一切GitHub/Pineconeに置かない、匿名化コホートIDのみ扱う）と、**CRITICAL状態は必ず人間の臨床レビューを経てからダッシュボードに反映する**というルールを明記しています。これは健康データを扱う以上、AGRIXと同じ自動化度では運用できないという実務上重要な差です。

両Agentとも共通の `contract-mi-code-v1` に準拠しつつ、ドメイン固有のペイロード拡張（`agrix-payload-extension-v1` / `healthbook-payload-extension-v1`）を持つ設計にしてあり、Agent Communication Protocol v1.0との整合が取れています。

これで、ADR-001が示した「共有アーキテクチャ＋分離実装」の構造が、実際のドキュメントレベルで一通り揃いました。次は、この一式（8文書）をGitHubへ初期コミットするための実際のREADME・ディレクトリ一式を作りますか。それとも、この段階で一度全体をレビューしたいですか。

## 6. エスカレーションルール（AGRIX固有の追加条件）

Agent Protocol Section 5.3の一般ルール（confidence<0.5、他ドメインとの矛盾）に加え、AGRIX Agentは以下の場合、confidenceに関わらず**強制的に`ESCALATE`（priority=critical）**を発行する。

- `pesticide_residue_ppm` が規制基準値を超過した場合
- `NDVI` が7日間で0.15以上急落した場合（作物ストレスの急性シグナル）

これは食品安全・環境規制に関わるため、通常のconfidence閾値ロジックより優先される。

## 6. エスカレーションルール（HealthBook固有の追加条件）

Agent Protocol Section 5.3の一般ルールに加え、HealthBook Agentは以下の場合、confidenceに関わらず**強制的に`ESCALATE`（priority=critical）＋人間の臨床レビュー必須フラグ**を発行する。

- `hba1c_pct` が臨床的危険閾値（例: 9.0%）を超過した場合
- `egfr_ml_min` が急性腎機能低下を示す閾値を下回った場合
- Agent Protocol Section 7実例のように、`confidence < 0.5` で環境曝露リスクとの相関が疑われる場合（Waterborne Exposureの例）

健康ドメインでは、AGRIXと異なり**自動応答のみでダッシュボードに反映することを禁止**し、`CRITICAL`状態は必ず人間の確認を経てから `Dashboard Agent` へ配信する（`pmos-director`が裁定するまで `Alert Panel` には "Pending Clinical Review" 状態で表示）。
