## 1. AGRIX Project の全体像（Vault記述からの抽出）

提供ノートから、AGRIX Project は以下の階層構造を持つことが読み取れます。

| 階層 | 名称 | 内容 |
|------|------|------|
| 理論層 | MBT55 / M³-BioSynergy System | 微生物群の代謝ネットワーク、電子フロー再設計、SOC形成モデル |
| モデル層 | MBT Sustainable Cycle (MSC) | 物質・情報・経済のエコ・ハイパーサイクル |
| アーキテクチャ層 | 4階層アーキテクチャ | 微生物代謝層／データ制御層／経済インセンティブ層／社会実装層 |
| プラットフォーム層 | AGRIX / HealthBook | 農業生産管理、健康管理、炭素会計、教育 |
| 実装層 | ケニア・ルワンダ・インド Pilot | Phase 1〜5 のロードマップ |

## 2. 技術要件の全体像

### 2.1 ローカルVault接続・検索基盤

| 要件 | 内容 |
|------|------|
| 接続方式 | MCP（Model Context Protocol）サーバー経由。ファイルシステム直接アクセス or Obsidian Local REST API |
| 検索方式 | BM25（キーワード）＋ベクトル検索（意味）のハイブリッド |
| メタデータ | YAML frontmatter（`tag: AgriWare` 等）、見出し階層、数式ブロック、表、コールアウト（`> [!note]`）の構造認識 |
| チャンク設計 | 章・節単位＋数式・表を独立チャンク化。オーバーラップ256〜512トークン |
| 埋め込み | ローカルモデル（例：bge-m3、multilingual対応）。日本語・英語混在対応必須 |
| 更新 | ファイル監視による差分インデックス更新 |

**AGRIX固有の要件**：ノート内にLaTeX数式（`$$...$$`）、Markdown表、コールアウト、絵文字タグが混在するため、**構造を保ったまま抽出**できるパーサが必要です。

AGRIXは概念間の関係が密接なため、単純なチャンク検索では不十分です。以下の**バイオ・ナレッジ・グラフ**を構築する必要があります。

```
ノード例：
  MBT55, M³-BioSynergy, MSC, AGRIX, HealthBook,
  reCLA, SOC, Carbon Loop Bond, Sustainability Index,
  ケニアPilot, Phase 1〜5, ISOBUS（旧AGRIX文脈）

エッジ例：
  MBT55 --構成--> M³-BioSynergy
  MSC --基盤--> MBT55
  AGRIX --実装--> MSC
  HealthBook --連携--> AGRIX
  reCLA --生成--> MBT55
  Carbon Loop Bond --評価--> SI
```

**抽出対象**：
- 定義文（「〜とは」「〜である」）
- 数式とその変数定義
- 表形式のパラメータ（C/N比、pH、k₁〜k₃、η、αβγ 等）
- Phase別KPI
- パートナー機関と役割

| モデル | 式 | 用途 |
|--------|-----|------|
| 炭素固定 | \( C_f = \lambda \cdot E_d/(E_d+K_m) \) | 電子供与体→炭素固定 |
| SOC動態 | \( dC_s/dt = I - k_d C_s + f_m \eta \) | 土壌炭素蓄積 |
| 電子フロー | \( J_{e^-} = \sum k_i [S_i] \phi_i \) | 代謝ネットワーク |
| 物質循環 | \( dC/dt = -k_1 C + k_2 N + k_3 E \) | MSC物質収支 |
| 経済FB | \( dV/dt = \alpha C + \beta I - \gamma W \) | 地域経済 |
| 統合FB | \( dS/dt = \eta_1 C + \eta_2 V + \eta_3 R \) | 持続性指数 |
| SI | \( SI = w_1 E + w_2 S + w_3 Ec \) | 総合評価 |
| グリーンプレミアム | \( V_{gp} = (C_{red}+N_{fix})P_c \) | 経済価値 |

## 4. 現状の課題と留意点

1. **用語の二重性**：ノート内の「AGRIX」は、①ISOBUSベースの農業機械制御プロトタイプ（旧文脈）と、②MBT55/MSCを中核とする統合プラットフォーム（新文脈）の二義性があります。Vault検索時に**文脈タグ**で分離が必要です。
2. **微生物種数の不一致**：2.2「55種類」、2.3「120種」、公式定義「多様な微生物コンソーシアム」→ 生成AIは差異を明示し、最新定義を優先すべき。
3. **数式の検証**：SOC動態式の \( f_m(MBT55) \) は関数形未定義。シミュレーション実装には追加定義が必要。
4. **シミュレーションの検証データ**：ケニア実証値（SOC+12〜18%、CO₂ 1.8〜2.6 t/ha/年等）はVault記載値であり、実データとの照合工程が必須。
5. **金融・健康データの規制**：地域ごとの規制対応（GDPR、ケニアData Protection Act等）。

## 5. まとめ

AGRIX Project をVaultから再構成し、シミュレーションまで構築するための技術要件は、以下の5本柱に集約されます。

1. **MCPベースのローカルVault接続＋ハイブリッド検索**
2. **構造化パーサ＋バイオ・ナレッジ・グラフ**
3. **AGRIX 4階層アーキテクチャの自動生成**
4. **Vault記載の数理モデル群を実装したシミュレーションエンジン**
5. **根拠提示・矛盾検出・多言語・セキュリティを備えた生成AI推論層**

これにより、生成AIは単なる要約ではなく、**AGRIXの設計図・デモ・評価指標をVaultから再帰的に生成・更新**できる基盤が整います。
