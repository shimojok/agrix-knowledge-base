# 4. Test Vectorの構造

各Test Vectorを機械可読化します。

```
{
  "test_id": "AGRIX-TV-001",
  "object_id": "AGRIX-OBJ-001",
  "validation_layer": "SCHEMA",
  "test_type": "POSITIVE",
  "condition": "valid canonical object",
  "expected_result": "PASS",
  "severity": "INFO",
  "action": "NONE"
}
```

これにより、

> 「AIがこのObjectを読んでどう思ったか」

ではなく、

> **「同じ入力に対して、Validation Engineが同じ判定を返すか」**

をテストできます。

# 6. Reconciliation Queue

ここがTest Vectorと異なるところです。

Validationが、

```
FAIL
```

となった場合でも、Objectそのものを修正しません。

代わりに、

```
AGRIX-REC-001
```

というQueue Itemを生成します。

```
{
  "reconciliation_id": "AGRIX-REC-001",
  "object_id": "AGRIX-OBJ-009",
  "conflict_type": "EVIDENCE_CONFLICT",
  "severity": "HIGH",
  "status": "OPEN",
  "required_action": "EVIDENCE_REVIEW",
  "decision_authority": "HUMAN_ADJUDICATOR"
}
```

# 8. Pending Objectsの扱い

現在の29 Objectsには、Evidenceがまだ完全に確定していないものがあります。

これは非常に重要なので、

```
PENDING
```

を**失敗扱いにしません。**

例えば、

```
AGRIX-OBJ-009
Decomposition Rate
```

について、

```
Object exists       → PASS
Schema              → PASS
Provenance          → PASS
Claim exists        → PASS
Evidence status     → PENDING
```

なら、

```
OVERALL
= PASS_WITH_PENDING_EVIDENCE
```

とします。
