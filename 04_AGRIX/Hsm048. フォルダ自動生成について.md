# 1. フォルダ自動生成について

今回の方式では、必要なフォルダを**事前に手作業で作る必要はありません**。

例えば`02_extract_knowledge_units.py`は実行時に、

```text
agrix-knowledge-base/
└── _knowledge_index/
    └── knowledge_units/
```

を自動生成します。

Pythonの、

```text
Path.mkdir(parents=True, exist_ok=True)
```

により、

```text
存在しない
   ↓
自動生成

既に存在する
   ↓
そのまま使用
```

となります。

---

# 2. `02_extract_knowledge_units.py` の役割

これは今回のKnowledge Infrastructureで非常に重要です。

```text
6,000 Notes
      │
      ▼
Source File
      │
      ▼
Heading Hierarchy
      │
      ▼
Section
      │
      ▼
Knowledge Unit
```

つまり、

```text
2026-04-24.md
```

を1つの巨大な知識として扱いません。

例えば、

```text
2026-04-24.md
│
├── 🤖MBT Probiotics Screening
│
│       ├── System Architecture
│       ├── MBT55 Function
│       ├── HealthBook Relation
│       └── AGRIX Relation
│
└── Other Topics
```

を、**Heading / Section単位のKnowledge Unit**へ自動抽出します。

これが、Kazさんが問題視した、

> 「1つのDaily NoteがPROJECT 01〜06の複数に関係する」

という問題を解決するための基礎になります。

# 4. 最重要：Raw Vaultは変更しません

```text
RAW KNOWLEDGE
       │
       │ Read Only
       ▼
Python Extraction
       │
       ▼
_knowledge_index
```

したがって、

* Daily Notesを移動しない
* PROJECT別フォルダへコピーしない
* 元ノートを書き換えない
* AI判断で削除しない

という方式です。

---

# 5. Knowledge Unitに保持する情報

各Unitには最低限、

```text
Knowledge Unit ID

Source Path

Source Filename

Start Line

End Line

Heading Path

Section Title

Original Text

Character Count

Content SHA256

Obsidian / Markdown Links

Extraction Provenance
```

を保存します。

つまり将来、

```text
AI Answer
    ↓
Knowledge Unit
    ↓
Original Daily Note
    ↓
Original Heading
    ↓
Line Range
```

まで遡れる構造です。

これは、過去に問題となった**「AIがどこから判断したのか分からない」状態を防ぐためのProvenance基盤**になります。

```text

└── _knowledge_engine/
    └── 02_extract_knowledge_units.py
```

に配置します。
