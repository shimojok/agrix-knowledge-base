# Test Vector設計

29 Objectsそれぞれについて、最低限、

```
Positive
Negative
Boundary
```

の3系列を持たせます。

さらに7 Validation Layers：

```
V1 Schema
V2 Identity
V3 Ontology
V4 Provenance
V5 Evidence
V6 Relationship
V7 Governance
```

を対象にします。

したがって設計上は、

**29 × 7 × 3 = 609 test conditions**

をカバーできる構造にします。

ただし、**609件すべてを「実際に問題が存在する」とは扱いません。**

これは「検査可能性」の定義です。

---

# Reconciliation Queue

検査で問題が発生した場合は、Canonical Objectを直接変更せず、

```
Test Vector
   ↓
Validation Result
   ↓
Conflict Classification
   ↓
Reconciliation Queue
   ↓
Human Adjudication
   ↓
Dataset v1.1
```

とします。

Conflict TypeはFreeze済みの、

```
RC-001 Duplicate Object
RC-002 Missing Provenance
RC-003 Evidence Conflict
RC-004 Status Conflict
RC-005 Ontology Conflict
RC-006 Relationship Conflict
RC-007 Claim/Evidence Conflict
RC-008 Model/Evidence Conflict
RC-009 Source Conflict
RC-010 Version Conflict
```

をそのまま使用します。

---

# Governance

特に今回、以下を**絶対ルール**とします。

> **Test VectorがFAILしても、AIはCanonical Objectを修正しない。**

FAILは、

```
FAIL
 ↓
RECONCILIATION REQUIRED
```

で止めます。

そして、

```
Human Adjudication
 ↓
Accept
Reject
Request Evidence
```

の結果だけがDataset v1.1への変更権限を持ちます。
