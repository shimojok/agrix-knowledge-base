ChromaDBのメタデータフィルターを活用して、特定フォルダやタグで検索範囲を絞り込む機能の拡張案を提案してください。

---

6,400 件以上のノートから目的のドメイン（例：`03_MBT55` のみ、または `#framework` タグ付きノートのみ）に検索範囲を限定し、ハルシネーション（誤情報の混入）を大幅に減らす**メタデータフィルター拡張案**です。

ChromaDB の `where` フィルタリング機能を活用し、既存のデータ構造を拡張します。

### 1. メタデータ抽出構造の設計

インデックス作成・更新時（`build_rag_index.py` / `update_rag_index.py`）に、Obsidian 特有の要素を ChromaDB のメタデータへ自動挿入します。

- **フォルダ階層（`folder`）:** ファイルパスから最上層カテゴリ（例: `03_MBT55`, `06_PBPE`）を自動抽出。
    
- **タグ（`tags`）:** YAML Frontmatter（`---` で囲まれた冒頭ヘッダー）内の `tags:` や本文内の `#tag_name` を抽出。

```Python
# ChromaDB に保存されるメタデータ構造のイメージ
metadata = {
    "source": "C:\\...\\03_MBT55\\MBT55炭素収支_1127.md",
    "folder": "03_MBT55",
    "filename": "MBT55炭素収支_1127.md",
    "tags": "mbt55, carbon_balance, framework" # カンマ区切り文字列
}
```

### 2. インデックス更新スクリプトの拡張点 (`update_rag_index.py`)

テキスト読み込み時に Frontmatter を解析し、メタデータを付与するロジックを追加します。

```Python
import re

def extract_metadata(filepath):
    """ファイルパスおよび冒頭の YAML Frontmatter からメタデータを抽出"""
    rel_path = os.path.relpath(filepath, VAULT_DIR)
    folder = rel_path.split(os.sep)[0] if os.sep in rel_path else "root"
    
    tags = []
    try:
        with open(filepath, 'r', encoding='utf-8') as f:
            content = f.read(2000) # 冒頭2000文字のみスキャン
            
            # YAML Frontmatter の tags: [tag1, tag2] 解析
            yaml_match = re.search(r'^---\n(.*?)\n---', content, re.DOTALL)
            if yaml_match:
                yaml_text = yaml_match.group(1)
                tag_match = re.search(r'tags:\s*\[?(.*?)\]?$', yaml_text, re.MULTILINE)
                if tag_match:
                    tags.extend([t.strip().strip('"\'') for t in tag_match.group(1).split(',')])
                    
            # 本文中の #tag の抽出
            inline_tags = re.findall(r'(?<!\w)#([a-zA-Z0-9_\u3040-\u30ff\u4e00-\u9faf-]+)', content)
            tags.extend(inline_tags)
    except Exception:
        pass

    return {
        "source": filepath,
        "folder": folder,
        "tags": ",".join(set(tags)) # 重複を除外して文字列化
    }
```

### 3. RAG 検索スクリプトでのフィルタリング実装 (`ask_rag.py`)

`similarity_search` の引数 `filter` に条件を指定することで、目的のディレクトリに絞り込んだ高速検索が可能になります。

```Python
# 例 1: 03_MBT55 フォルダ配下のみに絞り込んで検索
results = db.similarity_search(
    query="query: 炭素収支の計算式",
    k=4,
    filter={"folder": "03_MBT55"}
)

# 例 2: 「agrix」タグが含まれるノートのみ検索 (ChromaDB の $contains 演算子)
results = db.similarity_search(
    query="query: 代謝チェーンの定義",
    k=4,
    filter={"tags": {"$contains": "agrix"}}
)
```

### 4. 実用インタフェース案 (`ask_rag.py` への組み込み)

質問入力時に、必要に応じて対話形式でカテゴリを選択できるようにします。

```Plaintext
[カテゴリ指定] 1: 03_MBT55, 2: 06_PBPE, 3: 全体検索
選択 (1-3) > 1

質問 > 炭素収支の計算モデルについて教えてください。
[BioNexus Engine 思考中... (対象: 03_MBT55 フォルダのみ)]
```

### メリット

- **精度向上:** 関係のないドメイン（例：`HealthBook` 側の医療データ）が `MBT55` の技術仕様の質問に混入する事故を物理的に防止できます。
    
- **検索速度向上:** 検索対象範囲が狭まるため、類似度検索の処理時間が短縮されます。
