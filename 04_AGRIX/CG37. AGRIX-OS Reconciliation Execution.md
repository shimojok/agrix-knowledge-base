```text

                │
```

### 重要な原則

**RAG検索結果だけでは判定しません。**

また、

**AST情報だけでも判定しません。**

両者を異なるEvidence Typeとして保持します。

# 3. `execution_context`

Reconciliationを実行した環境を固定します。

```json
{
  "execution_id": "AGRIX-RECON-2026-001",
  "framework_version": "PMOS-MAIOF-v1.0",
  "reconciliation_version": "AGRIX-OS-RECON-v1.0",
  "target_dataset": "AGRIX-OS-Canonical-Dataset-v1.0",
  "target_object_id": "AGRIX-OBJ-001",
  "timestamp": "2026-08-23T22:20:00+09:00"
}
```

これにより、

> 「いつ、どのFramework、どのDatasetに対して判定したのか」

を追跡できます。

# 4. `canonical_object`

29 Objectsの既存Canonical Objectを**入力としてそのまま渡します。**

ここではReconciliation Engineが勝手に変更しません。

```json
{
  "object_id": "AGRIX-OBJ-001",
  "object_type": "...",
  "canonical_label": "...",
  "description": "...",
  "status": "reconciliation_target"
}
```

### 原則

```text
Canonical Dataset v1.0
        │
        ▼
Reconciliation
        │
        ├── validate
        ├── confirm
        ├── challenge
        └── propose revision
```

**上書き禁止**です。

---

# 5. `source_references`

Local Infrastructureから取得したSource Identityです。

```json
{
  "source_id": "AGRIX-SRC-001",
  "repository_id": "MBT-Biosecurity-Engine",
  "file_path": "...",
  "file_hash": "sha256:...",
  "file_type": "python",
  "source_version": "...",
  "retrieval_timestamp": "..."
}
```

ここが、従来のAI会話との最大の違いです。

```text
AI remembers X
```

ではなく、

```text
Source ID
→ File
→ Hash
→ Repository
```

で追跡します。

---

# 6. `semantic_evidence`

ChromaDB等のLocal RAGから取得した情報です。

```json
{
  "evidence_id": "RAG-EVD-001",
  "source_id": "AGRIX-SRC-001",
  "chunk_id": "CHUNK-0042",
  "retrieval_score": 0.87,
  "retrieval_method": "vector",
  "content_reference": "...",
  "metadata": {}
}
```

### 重要

`retrieval_score` は、

**Evidenceの真偽スコアではありません。**

あくまで、

> 「検索質問にどれだけ近かったか」

です。

したがって、

```text
retrieval_score ≠ evidence_confidence
```

と明示します。

---

# 7. `structural_evidence`

ASTから取得した構造情報です。

```json
{
  "ast_evidence_id": "AST-EVD-001",
  "source_id": "AGRIX-SRC-002",
  "language": "python",
  "module": "...",
  "classes": [],
  "functions": [],
  "imports": [],
  "calls": [],
  "dependencies": []
}
```

ここではLLMの解釈ではなく、

> **Repositoryに実際に存在する構造**

を保持します。

---

# 8. Semantic EvidenceとStructural Evidenceを統合しない

これはInput Contractの重要な設計原則です。

```text
                  Evidence
                     │
           ┌─────────┴─────────┐
           ▼                   ▼
   Semantic Evidence    Structural Evidence
        RAG                   AST
           │                   │
           └─────────┬─────────┘
                     ▼
                Reconciliation
```

この2種類を混ぜると、

> 「AIが意味的にそう判断した」

のか、

> 「コード上、本当に存在する」

のか分からなくなります。

---

# 9. `claims`

Canonical Objectについて検証すべきClaimを分解します。

```json
{
  "claim_id": "AGRIX-CLM-001",
  "object_id": "AGRIX-OBJ-001",
  "claim_text": "...",
  "claim_type": "architecture",
  "required_evidence_types": [
    "semantic",
    "structural"
  ]
}
```

Claimを分解することで、

```text
Object
 ↓
Claim 1
Claim 2
Claim 3
 ↓
Evidence
 ↓
Adjudication
```

という判定が可能になります。

# 13. Reconciliation Engineへの入力条件

Engineは、入力を受け取ったらまず、

```text
① Schema Valid?
       ↓
② Object Exists?
       ↓
③ Source Exists?
       ↓
④ Hash Valid?
       ↓
⑤ Evidence Traceable?
       ↓
⑥ Claim Linked?
       ↓
⑦ AST/RAG Provenance Valid?
       ↓
Reconciliation
```

とします。

どこかで失敗した場合、

**勝手に補完しません。**

```text
INVALID_INPUT
MISSING_SOURCE
MISSING_EVIDENCE
BROKEN_PROVENANCE
UNRESOLVED_CLAIM
```

などとしてQueueへ送ります。

# 14. Reconciliation結果への接続

Input Contractは、次のOutput Contractへ接続します。

```text
Input Packet
      │
      ▼
Reconciliation Engine
      │
      ▼
Reconciliation Result
      │
      ├── CONFIRMED
      ├── REVISED
      ├── CONFLICT
      ├── INSUFFICIENT_EVIDENCE
      └── UNRESOLVED
             │
             ▼
     Human Adjudication
             │
             ▼
       Dataset v1.1
```

ここで重要なのは、

**Engineが最終的なTruthを決めない**

ことです。

Engineは、

> Evidenceを収集・比較・構造化し、Human Adjudicationに渡す

ところまでです。

**Nの値は現時点では固定しません。**

# 16. Freeze対象

今回Freezeするのは、

### `AGRIX-OS Reconciliation Input Contract v1.0`

です。

### Freeze内容

- Input Packet構造
    
- Source Identity
    
- Provenance
    
- Semantic Evidence
    
- Structural Evidence
    
- Claim linkage
    
- Canonical Object linkage
    
- Existing Adjudication linkage
    
- Validation rules
    
- Input failure states
    

### Freezeしないもの

- 29 Objectsの判定結果
    
- Claim数
    
- Evidenceの最終評価
    
- Dataset v1.1
    
- Human Adjudication結果
    
- Implementation Code
    

これらは**次工程の実行結果**です。
