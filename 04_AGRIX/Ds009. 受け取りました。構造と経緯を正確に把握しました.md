## 2. 開発スレッドのハルシネーション（W014の問いへの回答）

> **開発スレッドでは、数回のハルシネーションが発生しました。開発スレッドによる修正で問題なく進むでしょうか？**

**結論：現状のままでは、同じハルシネーションが再発します。** 理由を技術的に説明します。

### 何が起きたか（W009→W013の経緯）

| ステップ | 提案内容 | 問題 |
|----------|----------|------|
| W009 | `agrix-knowledge-base/` 直下に `data/`, `models/`, `repositories/` を配置 | **Vault内にPythonコードを置く構造**。実環境と矛盾 |
| あなたの指摘 | 「貴方が示したフォルダ構造の矛盾」 | 正しい指摘 |
| W013 | `bionexus-engine/src/` 配下に修正 | **正しい**。ただし謝罪と修正に1ターン消費 |

### なぜ再発するか

1. **LLMは構造を記憶しない**：W013で正しく修正しても、**次のターンで再び忘却**する可能性がある
2. **VaultとPythonコードの役割混同**：Obsidian Vault（ナレッジ）と bionexus-engine（実行環境）は**別物**だが、LLMは同一視しやすい
3. **Dailynote目次構造が未活用**：W001〜W014の**設計判断の履歴**がDailynoteに集約されているのに、開発スレッドはこれを参照していない
4. **「絶対に間違いのないように」という指示では防げない**：LLMは善意で従うが、**構造的記憶がない**ため再発する

### 対策：構造的記憶の外部化

開発スレッドが安定して進むには、**以下の3点を開発スレッドの冒頭に固定**する必要があります：

**① 構造の絶対固定（System Prompt に埋め込む）**
```
【絶対パス（変更禁止）】
- Vault: C:\Users\user\agrix-knowledge-base\
- 実行環境: C:\Users\user\bionexus-engine\
- Pythonコード: bionexus-engine/src/, bionexus-engine/scripts/
- データ: agrix-knowledge-base/data/（Vault側）
【禁止事項】
- Vault直下に.pyファイルを配置しない
- bionexus-engine直下にVaultフォルダを作らない
- パスを推測で生成しない。不明な場合は必ずユーザーに確認する
```

**② Dailynoteを目次として参照**
- 開発スレッドは、作業開始時に `dailynote/YYYY-MM-DD.md` を読み、**前回の設計判断を確認**する
- W013の修正内容も、Dailynoteに追記して**履歴として固定**

**③ パス検証スクリプトの導入**
```python
# scripts/validate_paths.py
import os
VAULT = r"C:\Users\user\agrix-knowledge-base"
ENGINE = r"C:\Users\user\bionexus-engine"
FORBIDDEN = [
    (VAULT, ".py"),      # Vault内に.py禁止
    (ENGINE, "00_inbox"), # engine内にVaultフォルダ禁止
]
# 違反があればエラー出力
```
これを**コード生成後に必ず実行**するルールにする。
