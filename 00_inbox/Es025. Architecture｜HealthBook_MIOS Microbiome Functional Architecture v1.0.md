# 3. Functional Capacityの階層

```
Microbiome
    │
    ▼
Microbial Taxa
    │
    ▼
Genes / Enzymes
    │
    ▼
Microbial Functions
    │
    ▼
Functional Capacity
    │
    ▼
Metabolic Transformation
    │
    ▼
Metabolite
```

ここで重要なのは、

**Taxonomy ≠ Function**

です。

同じ機能を複数の菌が担う場合があるため、

```
Taxon A ─┐
Taxon B ─┼→ Equol-producing Function
Taxon C ─┘
```

という**Functional Redundancy**をKnowledge Graphで表現できるようにします。

# 5. 「必須性」のOntology

個別菌種に「必須」を直接付けるのではなく、Functional Capacityに評価します。

```
Microbial Function
        │
        ├── Essential
        ├── Beneficial
        ├── Context-dependent
        ├── Neutral / Unknown
        └── Potentially Harmful
```

### Essentialの判定基準案

**3段階のEvidence Gate**を設けます。

```
Functional Importance
        ↓
Host Dependence
        ↓
Evidence Strength
        ↓
Essentiality Classification
```

「Essential」と表示するには、臨床・生理学的根拠を要求します。

---

# 6. Evidence Layer

ここはAIが過剰解釈しないために必須です。

```
Evidence
│
├── E0 = Unknown
├── E1 = Hypothesis
├── E2 = Mechanistic Evidence
├── E3 = Observational Human Evidence
├── E4 = Clinical Evidence
└── E5 = Validated Intervention
```

例えば、

**「大豆を食べればエクオール産生菌が定着する」**

という仮説は、現時点で自動的にE4/E5にはできません。

このGovernanceをKnowledge Graphに組み込みます。

# 8. AI Agent Architecture

MIOS AI Agentにも新しい判断順序を設定します。

```
User Phenotype
      ↓
Food Intake
      ↓
Phytochemical Exposure
      ↓
Microbiome Functional Capacity
      ↓
Metabolite Potential
      ↓
Host Signaling
      ↓
Phenotype Association
      ↓
Evidence Check
      ↓
Recommendation
```

つまりAIは、

> 「この食品が良い」

と直接回答するのではなく、

> **「この食品 → この基質 → この微生物機能 → この代謝物 → この宿主経路」**

という**Metabolic Chain**を確認してから回答する設計にします。
