**要確認事項**

いくつか、実装前に明確化が必要な点があります。

**1. 医療行為・規制上の問題**

```python
# 現在の設計では以下が「診断」として機能している
@app.post("/api/v1/medical/record")
async def electronic_health_record(...):
    "suspected_diagnoses": diagnosis_analysis.diagnoses  # 疑い病名の提示
    "kampo_recommendations": kampo_recommendations       # 処方提案
```

これは多くの国で医師法・薬事法に抵触する可能性があります。「診断補助」と「診断」の法的境界線を各国で確認する必要があります。

**2. MBT55・浜田式・下條式の根拠データ**

設計に登場する独自概念（MBT55菌株番号、137疾病マトリックス等）について、査読済みエビデンスの有無を確認させてください。実装はできますが、臨床的主張の根拠が弱い場合、規制当局の承認取得が困難になります。

**3. KPIの根拠**

```python
"infection_rate_reduction": 0.6,   # 感染症60%減
"child_mortality_reduction": 0.4,  # 乳幼児死亡率40%減
```

これらは介入研究なしに主張すると、薬機法・景品表示法・FDAガイドライン等に抵触します。
