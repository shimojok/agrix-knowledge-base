ご提示いただいたJSONデータおよび前提条件の補足、しっかりと受け取りました。

なるほど、現在記述されているJSONコードの大部分は**HealthBook（疾患、漢方、腸内細菌代謝、臨床メタデータなど）**に関連するものであり、一部を除いて農業・環境系の**AGRIX**のドメインデータではない、ということですね。さらに、これら大量のJSON定義がMarkdownファイル（`.md`）のなかに直接テキストとして埋め込まれている構造であることも理解しました。

これらの構造（Markdown内にHealthBook用の複雑なJSONが内包されている状態）を正確に処理し、かつ完全無料（ローカル計算によるベクトル化）で動作させるための、GitHub Actionsワークフローおよび最適化したPythonスクリプトを構築しました。

## 🛠️ GitHub Actions 定義ファイル

`.github/workflows/sync_to_pinecone.yml` としてリポジトリに配置する設定です。

GitHubの無料枠（Privateでも月2,000分）を消費して動作します。

YAML

```
name: Sync Obsidian Vault to Pinecone

on:
  push:
    branches:
      - main  # 本番用のブランチ名に合わせて調整してください
    paths:
      - 'vault/**'  # vaultディレクトリ内の変更時のみ実行して無料枠を節約

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/tools/python@v5
        with:
          python-version: '3.10'

      - name: Install Dependencies
        run: |
          python -m pip install --upgrade pip
          pip install pinecone-client pyyaml sentence-transformers

      - name: Run Sync Script
        env:
          PINECONE_API_KEY: ${{ secrets.PINECONE_API_KEY }}
          PINECONE_INDEX_NAME: ${{ secrets.PINECONE_INDEX_NAME }}
        run: |
          python scripts/sync_obsidian_to_pinecone.py
```

## 🐍 完全無料版 同期スクリプト

`scripts/sync_obsidian_to_pinecone.py` として配置します。

OpenAIのAPI（有料）の代わりに、オープンソースかつ世界標準の軽量高精度モデル **`all-MiniLM-L6-v2`** をGitHub Actionsサーバーローカル上で動かしてベクトル化するため、**Embeddingの通信・計算費用は永久に0円**です。

Python

```
import os
import re
import glob
import yaml
import json
from typing import List, Dict, Any
from pinecone import Pinecone
from sentence_transformers import SentenceTransformer

# ==========================================
# 1. 環境変数とモデルの初期化（完全無料構成）
# ==========================================
PINECONE_API_KEY = os.getenv("PINECONE_API_KEY")
PINECONE_INDEX_NAME = os.getenv("PINECONE_INDEX_NAME", "healthbook-agrix-knowledge")
VAULT_DIR = "./vault"

# GitHub Actionsのサーバー上でオープンソースモデルを無料実行 (384次元)
print("📥 埋め込みモデルをダウンロード/ロード中...")
embedding_model = SentenceTransformer('sentence-transformers/all-MiniLM-L6-v2')

# Pineconeクライアント初期化
pc = Pinecone(api_key=PINECONE_API_KEY)
index = pc.Index(PINECONE_INDEX_NAME)

# ==========================================
# 2. Markdown & 内包JSON の高度なパース
# ==========================================
def parse_markdown_file(file_path: str) -> List[Dict[str, Any]]:
    with open(file_path, 'r', encoding='utf-8') as f:
        content = f.read()

    # フロントマターの解析
    front_matter = {}
    body = content
    front_matter_match = re.match(r'^---\s*\n(.*?)\n---\s*\n', content, re.DOTALL)
    if front_matter_match:
        try:
            front_matter = yaml.safe_load(front_matter_match.group(1)) or {}
            body = content[front_matter_match.end():]
        except yaml.YAMLError:
            pass

    filename = os.path.basename(file_path)
    processed_chunks = []
    chunk_idx = 0

    # ----------------------------------------------------
    # 戦略A: Markdown内のJSONコードブロックを優先抽出
    # ----------------------------------------------------
    # ```json ... ``` で囲まれた領域をキャプチャ
    json_blocks = re.findall(r'```json\s*\n(.*?)\n```', body, re.DOTALL)
    
    for block in json_blocks:
        try:
            # 途中で切れているJSON（末尾の閉じ括弧不足など）に対応するための簡易バリデーション
            # カウントが合わない不完全な記述は手前で補正するかスキップ
            json_data = json.loads(block.strip())
            
            # 疾患IDなどをメタデータとして自動抽出
            disease_id = json_data.get("disease_id", "unknown")
            disease_name = json_data.get("name_jp", "")
            
            metadata = {
                "source_file": filename,
                "data_type": "json_matrix",
                "module_id": front_matter.get("module_id", "HealthBook"),
                "disease_id": disease_id,
                "disease_name": disease_name,
                "chunk_index": chunk_idx
            }
            
            processed_chunks.append({
                "id": f"{filename}#json-{disease_id}-{chunk_idx}",
                "text": block.strip(), # JSONテキストそのものをベクトル化対象にする
                "metadata": metadata
            })
            chunk_idx += 1
        except json.JSONDecodeError:
            # 万が一途中で切れているJSON（D017の末尾など）があってもスクリプトを落とさない
            print(f"⚠️ 解析スキップ (不完全なJSON構造): {filename} 内の一部ブロック")
            continue

    # ----------------------------------------------------
    # 戦略B: 通常のテキストセクションもパース（見出し単位）
    # ----------------------------------------------------
    # JSONブロックを除去したプレーンテキスト側もAIエージェントのコンテキスト用に確保
    clean_body = re.sub(r'```json\s*\n(.*?)\n```', '', body, flags=re.DOTALL)
    sections = re.split(r'(^#{1 mour,4}\s+.*$)', clean_body, flags=re.MULTILINE)
    
    current_header = "概要"
    if sections[0].strip():
        sections.insert(0, "# 概要\n")

    for i in range(0, len(sections)-1, 2):
        header = sections[i].strip().replace("#", "").strip()
        text = sections[i+1].strip() if i+1 < len(sections) else ""
        
        if text:
            metadata = {
                "source_file": filename,
                "data_type": "text_prose",
                "module_id": front_matter.get("module_id", "HealthBook"),
                "section_header": header,
                "chunk_index": chunk_idx
            }
            processed_chunks.append({
                "id": f"{filename}#text-{chunk_idx}",
                "text": f"[{header}]\n{text}",
                "metadata": metadata
            })
            chunk_idx += 1

    return processed_chunks

# ==========================================
# 3. 同期メイン処理ループ
# ==========================================
def sync_vault():
    print("🚀 同期パイプラインを起動しました...")
    md_files = glob.glob(os.path.join(VAULT_DIR, "**/*.md"), recursive=True)
    
    if not md_files:
        print("❌ 対象となるMarkdownファイルが見つかりません。パスを確認してください。")
        return

    for file_path in md_files:
        print(f"📄 ファイルスキャン中: {os.path.basename(file_path)}")
        chunks = parse_markdown_file(file_path)
        
        if not chunks:
            continue
            
        vectors_to_upsert = []
        # 大量処理時にクラッシュしないよう、テキストリストを一括で抽出して高速ローカルベクトル化
        texts = [c["text"] for c in chunks]
        embeddings = embedding_model.encode(texts).tolist()
        
        for idx, chunk in enumerate(chunks):
            pinecone_metadata = chunk["metadata"]
            # 検索ヒット時に利用するためオリジナルテキストもメタデータへ格納
            pinecone_metadata["text"] = chunk["text"]
            
            vectors_to_upsert.append({
                "id": chunk["id"],
                "values": embeddings[idx],
                "metadata": pinecone_metadata
            })
            
        # Pineconeへの一括アップサート実行
        if vectors_to_upsert:
            index.upsert(vectors=vectors_to_upsert)
            print(f"   -> ✅ {len(vectors_to_upsert)} 個のデータブロックを同期しました。")

if __name__ == "__main__":
    sync_vault()
```

## 💎 この設計のポイントと効果

1. **`data_type` による明確な分離**:
    
    メタデータに `"data_type": "json_matrix"` と `"data_type": "text_prose"` を自動付与するようにしました。これにより、Next.js側やエージェントから、「D011の純粋なJSONデータだけを取り出したい」ときと、「周辺のテキスト説明（Guided Linksなど）だけを参照したい」ときで、Pineconeのクエリ時に完全にフィルタリングし分けることが可能です。
    
2. **不完全な記述へのレジリエンス（耐障害性）**:
    
    チャットログや執筆中のドキュメントでは、プロンプト例の `D017` のように末尾のJSONが途中で切れた状態で保存されるケースがあります。スクリプトがそれを検知した際、システム全体をクラッシュさせずに警告ログを出して安全にスキップ（または次へ進行）する例外処理を組み込んでいます。
    
3. **完全無料の担保**:
    
    `sentence-transformers` を用いてGitHub ActionsのCPU上でベクトル化の計算処理を行うため、OpenAI等の従量課金APIキーが無くとも、完全に無料でデータベースへの同期が完結します。
