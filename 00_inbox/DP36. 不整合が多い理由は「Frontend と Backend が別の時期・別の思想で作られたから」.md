# 🎯 **不整合が多い理由は「Frontend と Backend が別の時期・別の思想で作られたから」。**

もっと具体的に言うと：

---

# 🟥 **1. Backend は「PBPE Marketplace（旧版）」の API 設計で作られている**

あなたの backend の API は、明らかに **旧 PBPE Marketplace の仕様**で作られている。

特徴：

- `/dashboard/summary`
- `/dashboard/ghg-breakdown`
- `/dashboard/flywheel`
- `/dashboard/credits/market`
- `/dashboard/finance/bonds`
- `/impact/scope3`
- `/products/list`

これらは **旧 UI（Streamlit 時代）** の API 設計。

---

# 🟦 **2. Frontend（Next.js）は「Dashboard v3（新設計）」で作られている**

Next.js の Dashboard v3 は、  
あなたと私が一緒に作った **新しい UI 設計**に基づいている。

特徴：

- `/dashboard/kpis`
- `/dashboard/impact`
- `/credits/market`
- `/finance/bonds`
- `/finance/insurance/products`
- `/scope3/convert`

つまり：

# 🟥 **Frontend と Backend が “別の API 設計” を参照している。**

---

# 🟥 **3. Backend は「PBPE Marketplace 全体 API」

Frontend は「Dashboard v3 API」**

Backend は PBPE Marketplace 全体の API を意識している：

- PBPE 発行
- PBPE 決済
- PBPE レーティング
- Ledger
- Products
- Impact
- Bonds
- Insurance

一方、Next.js Dashboard v3 は：

- KPI
- Impact
- Market
- Finance
- Enterprise
- PBPE Issuance

つまり：

# 🟥 **Backend は “広い世界” を想定している**

# 🟦 **Frontend は “Dashboard に必要な部分だけ” を想定している**

---

# 🟥 **4. さらに Backend は「複数の開発フェーズのコードが混在」している**

あなたの backend には：

### ✔ 正しく動くコード

- insurance.py

### ❌ 旧仕様のコード

- dashboard.py
- products.py

- credits.py（market API がない）

つまり：

# 🎯 **Backend は “複数の時代のコード” が混ざっている。**

- Backend は旧仕様のまま
