# 🟩 **なぜ今 Codespaces を使うべきなのか（PMO の判断）**

## 1️⃣ **フロントとバックの同期が一瞬で揃う**

あなたは今：

- frontend → 整備済み（index.tsx / login.tsx）
- backend → まだ修正していない
- ローカル環境 → まだ整っていない可能性が高い

この状態でローカルで進めると：

- Python バージョン
- Node バージョン
- パスのズレ
- 仮想環境
- パッケージの不整合

こういう“余計な問題”が必ず出る。

Codespaces なら：

- GitHub のコードがそのまま動く
- Python / Node / pnpm / uvicorn が最初から揃っている
- VS Code Web で即編集できる
- ローカル環境の汚染ゼロ

つまり **「環境構築の時間ゼロ」**。

---

## 2️⃣ **あなたのプロジェクトは“OS 全体”を動かす必要がある**

PBPE Marketplace は：

- Backend（FastAPI）
- Blockchain（Python）
- Registry（Python）
- Dashboard（Next.js）
- JWT 認証
- axios interceptor

これらが **全部つながって初めて動く**。

ローカルで全部揃えるのは、  
正直かなり面倒。

Codespaces なら：

- backend と frontend を同時に起動
- ポート 8000 と 3000 が自動公開
- ブラウザで即アクセス可能

**OS 全体を一気に動かすには最適。**

---

## 3️⃣ **あなたは今 “実装フェーズ”に入った**

Kaz が今やっているのは：

- ファイル差し替え
- API 接続
- Dashboard の動作確認
- Registry / Blockchain の統合
- Trace ボタンの追加

これは **コードを大量に貼り替えるフェーズ**。

Codespaces は：

- GitHub と完全同期
- ファイル編集が安全
- 失敗してもすぐ巻き戻せる
- ローカルを壊さない

つまり **実装フェーズに最適な環境**。

---

## 4️⃣ **あなたは以前 Codespaces で混乱したが、それは“使い方の誤解”だった**

あなたは以前こう言った：

> Codespaces は GitHub を見ているだけで、ローカルに生成されない

これは正しい理解。

Codespaces は：

- **ローカルではなく、クラウド上に環境を作る**
- だからローカルに clone されない
- でもそれで正しい

むしろ：

> Codespaces は「GitHub のコードをそのまま実行するクラウド環境」

だから **ローカルに clone する必要はない**。

# 🟦 **PMO 結論：

Kaz の今のフェーズでは Codespaces が最適。**

# 👉 **Codespaces を開く**

GitHub のリポジトリで：

```
Code → Codespaces → Create codespace on main
```

これだけ。

開いたら：

- backend フォルダ
- frontend フォルダ
- blockchain
- registry
- routers

全部が揃っている。

---

# 🟩 **Codespaces を開いたら、次にやること（PMO が案内）**

1. **backend を起動**

```
uvicorn backend.main:app --reload
```

2. **frontend を起動**

```
npm install
npm run dev
```

3. **Dashboard にアクセス**

```
https://<your-codespace-url>/dashboard/registry
```

4. **Credits を発行して Registry に反映されるか確認**
