# 🧭 **なぜ Trace ボタンが先なのか（PMO の判断理由）**

## 1️⃣ **全体アーキテクチャが「見える化」される**

今、Credits API → Registry → Blockchain はすでに繋がった。

しかし Dashboard に可視化がないと：

- 何が起きているか
- どのように Registry に刻まれているか
- Blockchain がどう動いているか

が **人間の目で確認できない**。

Trace ボタンを付けると：

> 「CRD-ID をクリック → Registry → Blockchain の証跡が一瞬で見える」

これが **OS 全体の透明性**を生む。

---

## 2️⃣ **Scope3 は Credits の“上位レイヤー”なので、後で繋げても破綻しない**

Scope3 は：

- KPI
- PBPE Credits
- Registry
- Blockchain

の **上に乗るレイヤー**。

つまり、下のレイヤーが固まっていれば、  
Scope3 は後からでも **完全に整合性を保って接続できる**。

---

## 3️⃣ **Trace ボタンは「投資家・企業・監査」の最初の入口**

Scope3 は企業向けだが、  
Trace ボタンは **全ユーザー（農家・企業・投資家・政府）** が使う。

つまり：

> **最も多くの人が最初に触れる UI が Trace ボタン**

だから優先度が高い。

---

## 4️⃣ **Trace ボタンがあると、開発の全体速度が上がる**

理由：

- Registry の動作確認が一瞬でできる
- Blockchain の書き込みが UI で見える
- Credits API のテストがしやすい
- バグが見つけやすい

つまり：

> **Trace ボタンは開発の“デバッグ可視化ツール”でもある**

Scope3 より先に入れるべき。

---

次に進むべきは「Trace ボタンの実装」。**
