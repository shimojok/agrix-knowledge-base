# 3. Essential Microbial Functionsの位置付け

ここを明確にします。

```
Microbiome Functional Layer
│
├── Microbial Taxonomy
│
├── Microbial Function
│
├── Essential Microbial Functions   ← CORE
│
├── Functional Capacity
│
├── Biotransformation
│
├── Cross-feeding
│
└── Host Complementation
```

### Definition

> **Essential Microbial Function = 宿主の生理・代謝に重要であることがEvidenceによって支持される、微生物由来の機能単位。**

ただし、

> **Essential ≠ Essential Bacterium**

です。

つまり、

```
菌種A ─┐
菌種B ─┼──→ 同一Functional Capacity
菌種C ─┘
```

という代替可能性を許容します。

## 4.2 EssentialMicrobialFunction

`MicrobialFunction`の単なるBooleanではなく、独立したSemantic Entityとして管理します。

```

{
  emf_id

  host_domain[]
  dependency_type

  evidence_ids[]
}
```

### `essentiality_class`

```

BENEFICIAL
CONTEXT_DEPENDENT
UNKNOWN
POTENTIALLY_HARMFUL
```

これにより、将来Evidenceによって評価が変更されてもOntologyを破壊しません。

# 10. Claim Contract

ここがAI Governance上重要です。

Relationshipそのものではなく、

```
Claim
{
  claim_id
  subject_id
  predicate
  object_id
  evidence_ids[]
  confidence
  status
}
```

として保持します。

例えば、

```
[DAIDZEIN]
    │
    └── substrate_for ──>
          [EQUOL_PRODUCTION_FUNCTION]
```

というClaimにEvidenceを直接紐付けます。

# 12. Data Integrity Rules

### Rule 01

**TaxonomyからFunctionを自動推論しない。**

### Rule 02

**FunctionからClinical Effectを直接推論しない。**

### Rule 03

**Functional CapacityとActivityを混同しない。**

### Rule 04

**Presence ≠ Activity**

### Rule 05

**Association ≠ Causation**

### Rule 06

**Evidenceなしの重要RelationshipはProduction KGに昇格させない。**

### Rule 07

**Essentialityは菌種ではなく原則Function単位で評価する。**

今回、重要な点を明確に固定します。

```

 ↓
Nutrient
 ↓
Human
```

### MIOS

```
Food
 ↓
Nutrient / Phytochemical
 ↓
Microbiome
 ↓
Essential Microbial Functions
 ↓
Functional Capacity
 ↓
Microbial Transformation
 ↓
Metabolite
 ↓
Host Signaling
 ↓
Phenotype
```

つまり、

> **栄養学の対象を「人間が摂取する物質」だけから、「人間の代謝を成立・補完・拡張する生物学的機能」まで拡張する。**

これが今回のData Contractの最上位設計原則です。
