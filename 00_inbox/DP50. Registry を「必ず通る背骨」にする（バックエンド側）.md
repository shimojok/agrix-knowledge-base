いいね、じゃあ PMO モードで「全体を最短で“一本につなぐ”順番」を決めます。

やることはシンプルで、**３ステップで OS 全体を貫通させる**感じです。

---

### 1. Registry を「必ず通る背骨」にする（バックエンド側）

**優先ターゲットは PBPE Credits。**  
理由：

- GHG・農業・Scope3・金融の“交点”だから
- ここが Registry とつながると、一気に全体像が見えるから

#### やること（方針だけ）

- `backend/routers/credits.py`（または相当ファイル）で：
    - **発行時**（issue）に `/registry/record` を内部呼び出し
        - `kind="credit_issuance"`
        - `subject_id=CRD-ID`
        - `actor=企業ID`
        - `amount=PBPE`
        - `unit="PBPE"`
    - **償却時**（retire）に `/registry/record`
        - `kind="credit_retirement"`

これで：

> 「クレジットを動かすと、必ず Registry と Chain に 1 行刻まれる」

状態になる。

---

### 2. Dashboard の「Market」から Registry に飛べるようにする

次に触るのは **`/dashboard/market` ページ**。

- PBPE Credits のテーブルに **「Trace」ボタン**を追加
- クリックで `/dashboard/registry?subject_id=CRD-XXXXXXX` に遷移
- Registry Explorer 側で `subject_id` クエリを読んで自動検索

これで：

> 「このクレジット、本当に存在するの？」  
> → その場で証跡が見える

という ESG・投資家・監査向けの導線が完成する。

---

### 3. Scope3 → PBPE → Registry の一本化（最後にやる）

最後に、**Scope3 連携 API** からも Registry を通す。

- `kind="scope3_report"`
- `subject_id=CRD-ID`
- `actor=企業ID`
- `amount=tCO2e`
- `unit="tCO2e"`

これで：

> 「Scope3 で報告された削減量」  
> ＝ 「PBPE Credits と Registry と Chain に刻まれた量」

になり、**二重計上ゼロの ESG 報告ライン**が完成する。

---

### まとめ（PMO視点の優先順位）

1. **Credits API に Registry 連携を入れる**（背骨を通す）
2. **Dashboard /market → /registry の UI 導線をつなぐ**
3. **Scope3 報告も Registry 経由にする**
