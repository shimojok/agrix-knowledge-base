# Architecture

はい。**新しいマルチAIエージェントモデルへ移管するための「AGRIX Platform Canonical Migration Package」**として出力するのが適切です。

ただし、重要な点があります。

今回の検索では、現在こちらから検索可能なファイルソースからAGRIX文書本文を再取得できませんでした。したがって、**存在を確認できない文書内容を推測してJSON化することはしません**。

一方、これまでのスレッドで確定しているアーキテクチャ情報を基に、移管フォーマット自体は先に固定できます。

# 3. AIエージェントが最も重要視する構造

特に重要なのは、

```text

   ↓

   ↓
Decision
   ↓
Process
   ↓
Evidence
   ↓
KPI
   ↓
Business Value
```

です。

例えばAgriWare™なら、

```text
MBT55
  ↓
Microbial Metabolism
  ↓
Enzyme Activity
  ↓
Mineral Availability
  ↓
Plant Metabolic State
  ↓
Phenotype
  ↓
Freshness Retention
  ↓
SafetyChain
  ↓
PBPE
  ↓
```

という**因果・依存グラフ**として保存します。

これにより、新しいAIは単なる文書検索ではなく、

> 「AgriWare™で何を監視し、それがSafetyChain™とPBPEにどう接続するか」

を推論できます。

# 7. 今回の移管で特に重要な「Decision Registry」

これを必ず作ります。

```json
{
  "decision_id": "ADR-AGRIX-001",
  "decision": "AgriWare is defined as a metabolic intelligence and control layer rather than conventional agricultural IoT.",
  "status": "proposed",
  "scope": "AGRIX",
  "rationale": "",
  "dependencies": [
    "MBT55",
    "PMH",
    "Phenotyping",
    "SafetyChain"
  ],
  "source_documents": []
}
```

これによって新しいAIが、

**確定事項**

と

**仮説・提案**

を混同しません。

これは今回の移管では非常に重要です。

---

# 8. 「事実・仮説・設計・主張」を分離

各Knowledge Assetに必ず、

```json
{
  "epistemic_status": "source_supported"
}
```

を持たせます。

分類は、

```text
SOURCE_SUPPORTED
CANONICAL_DECISION
DESIGN_PROPOSAL
HYPOTHESIS
UNVERIFIED_CLAIM
EXTERNAL_RESEARCH
```

とします。

これにより、今後AIが勝手に

**「仮説 → 科学的事実」**

へ変換することを防止できます。

# 9. 今回の成果物移管で最終的に作るべきもの

最終成果物は以下の**7層**にします。

```text
Layer 0  PROJECT MANIFEST
         ↓
Layer 1  CANONICAL KNOWLEDGE
         ↓
Layer 2  ARCHITECTURE
         ↓
Layer 3  DATA / ENTITY / RELATIONSHIP
         ↓
Layer 4  AI AGENT / WORKFLOW
         ↓
Layer 5  EVIDENCE / PROVENANCE
         ↓

         ↓

```

これなら、将来、

**GPT / Claude / Gemini / Copilot / 自社Agent**

のどれに移しても、同じCanonical Knowledgeを利用できます。

# 10. 今回の重要な制約

現時点では、私が**このスレッドで作成した全成果物を完全自動的に再取得できる状態ではありません**。

したがって、ここで「全成果物をJSON化した」と言うのは不正確です。

今回アップロードされたAGRIX資料群を含め、**実文書を再取得できる状態で一括正規化する必要があります**。

その際には、

```text
28+ AGRIX
↓
AI開発
↓
PBPE
↓
MBT55
↓
MBT漢方代謝
↓
HealthBook
↓
GHG
```

という今回の順序を維持し、

**Document → Canonical Asset → Knowledge Graph → Agent Context**

へ変換するのが最短ルートです。
