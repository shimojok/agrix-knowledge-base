進捗自体は正常です(3450件まで成功しています)。今起きているのは、**レート制限が「たまに当たる」段階から「継続的に当たる」段階に移った**ということです。おそらく処理が進むにつれてPinecone側のトークン消費ペースが積み重なり、60秒待ってもまだ枠が回復しきっていない状態です。

ここで2つ、直しておいた方がいいポイントがあります。

### 問題点

**① 待機時間の上限(60秒)が短すぎる** `wait = min(60, 10 * attempt)`としているため、最大でも60秒しか待ちません。1分あたりのトークン制限が本当にタイトな状況では、これでは足りません。

**② 再実行のたびに最初(`i=0`)からやり直している** これが実は一番もったいない点です。`Ctrl+C`で止めて再実行すると、**すでに成功済みの3450件分もすべて再度Pineconeに送信し直しています**。中身は同じなので上書きされるだけで害はありませんが、**その分のトークン消費が無駄になり、レート制限に当たりやすくなっています**。

### 対処: チェックポイント(再開位置の記録)を追加する

進捗をファイルに保存し、次回実行時は**すでに成功した分をスキップして続きから始める**ようにします。これでレート制限の枠を新しいファイルの処理だけに使えます。

```python
import os
import glob
import time
import json
from pinecone import Pinecone

PINECONE_API_KEY = os.environ["PINECONE_API_KEY"]

VAULT_PATH = r"C:\Users\user\OneDrive\BioNexus_vault"
BATCH_SIZE = 20
SLEEP_BETWEEN_BATCHES = 15.0
MAX_RETRIES = 8
MAX_WAIT_SECONDS = 90
CHECKPOINT_FILE = "upload_checkpoint.json"

print("[1/4] Pineconeに接続中...")
pc = Pinecone(api_key=PINECONE_API_KEY)
index = pc.Index("agrix-knowledge-base")
print("[2/4] Pineconeに接続しました。(統合埋め込み: llama-text-embed-v2 を使用)")

print(f"[3/4] Obsidian Vaultを読み込み中: {VAULT_PATH}")
md_files = sorted(glob.glob(os.path.join(VAULT_PATH, "**/*.md"), recursive=True)) 
print(f"ファイル数: {len(md_files)} 個のMarkdownファイルが見つかりました。")

# --- チェックポイント読み込み ---
completed_indices = set()
if os.path.exists(CHECKPOINT_FILE):
    with open(CHECKPOINT_FILE, "r", encoding="utf-8") as f:
        completed_indices = set(json.load(f))
    print(f"[チェックポイント] 前回までに成功済み: {len(completed_indices)} 件をスキップします。")

def save_checkpoint():
    with open(CHECKPOINT_FILE, "w", encoding="utf-8") as f:
        json.dump(list(completed_indices), f)

print("[4/4] アップロードを開始します（時間がかかることがあります）...")

def flush_batch_with_retry(batch):
    if not batch:
        return True
    for attempt in range(1, MAX_RETRIES + 1):
        try:
            index.upsert_records(namespace="__default__", records=batch)
            return True
        except Exception as e:
            msg = str(e)
            if "429" in msg or "RESOURCE_EXHAUSTED" in msg:
                wait = min(MAX_WAIT_SECONDS, 10 * attempt)
                print(f"   [レート制限] {wait}秒待って再試行します ({attempt}/{MAX_RETRIES})")
                time.sleep(wait)
            else:
                print(f"   [バッチ失敗・リトライ対象外] {msg}")
                return False
    print("   [失敗] リトライ上限に達しました。このバッチ分はスキップします。")
    return False

batch = []
batch_indices = []
uploaded_count = len(completed_indices)
skipped_files = []

def process_batch_and_reset():
    global batch, batch_indices, uploaded_count
    ok = flush_batch_with_retry(batch)
    if ok:
        uploaded_count += len(batch)
        completed_indices.update(batch_indices)
        save_checkpoint()  # ← 成功するたびに保存。ここで止めても続きから再開できる
    else:
        for rec in batch:
            skipped_files.append(rec["filename"])
    batch = []
    batch_indices = []

for i, file_path in enumerate(md_files):
    if i in completed_indices:
        continue  # すでに成功済みならスキップ(トークンを消費しない)

    try:
        with open(file_path, 'r', encoding='utf-8') as f:
            content = f.read()
        if len(content.strip()) < 50:
            continue

        file_name = os.path.basename(file_path)
        folder_name = os.path.basename(os.path.dirname(file_path))

        batch.append({
            "_id": f"file_{i}",
            "text": content[:8000],
            "filename": file_name,
            "folder": folder_name,
            "full_path": file_path,
            "content_preview": content[:500],
        })
        batch_indices.append(i)

        if len(batch) >= BATCH_SIZE:
            process_batch_and_reset()
            print(f"   進捗: {uploaded_count} 件成功 / {i+1}/{len(md_files)} ファイル処理済み")
            time.sleep(SLEEP_BETWEEN_BATCHES)

    except Exception as e:
        skipped_files.append(os.path.basename(file_path))
        print(f"   SKIP(読み込みエラー): {os.path.basename(file_path)} - {e}")

process_batch_and_reset()

print("すべてのファイルの処理が完了しました。")
print(f"成功: {uploaded_count} 件 / 失敗ファイル数: {len(skipped_files)} 件")
if skipped_files:
    print("失敗したファイル一覧(先頭20件):")
    for name in skipped_files[:20]:
        print(f"  - {name}")
print("Pineconeダッシュボードでレコード数を確認してください。")
```

### 変更点まとめ

1. **`upload_checkpoint.json`に成功済みインデックスを保存** — バッチが1つ成功するたびに書き込みます。`Ctrl+C`で止めても、次回実行時は完了済み分を飛ばして続きから始まります。
2. **`md_files`を`sorted()`で固定順にする** — `glob`の返す順番はOS依存でブレることがあるため、チェックポイントの`i`とファイルの対応を安定させます(Vaultにファイルを追加・削除していなければ問題ありません)。
3. **待機上限を60秒→90秒に延長、バッチ間隔を15秒に** — 継続的な制限に対して少し余裕を持たせます。
4. **バッチサイズを20に縮小** — 1回のリクエストで消費するトークンをさらに抑えます。

### 進め方

今動いているプロセスがあれば `Ctrl+C` で止めて、このコードに上書きしてから再実行してください。`upload_checkpoint.json`が同じフォルダに自動生成されるので、削除しない限り次回以降も続きから再開できます。

もしこれでも同じ場所(3500件付近)で頻繁に詰まるようなら、それは「一時的なバースト制限」ではなく「アカウント全体の分あたりトークン上限そのものが厳しい」ということなので、Pineconeダッシュボードでのプランアップグレードを検討した方が良いタイミングかもしれません。まずはこのチェックポイント版で様子を見てください。
