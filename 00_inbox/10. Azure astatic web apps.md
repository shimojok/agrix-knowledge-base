## デプロイ手順（4ステップ）

**① ZIPを解凍してGitHubにプッシュ**

```bash
cd healthbook-platform
npm install          # 依存関係インストール
npm run dev          # ローカル確認 → http://localhost:5173

git init
git add .
git commit -m "HealthBook v3.0 initial"
git branch -M main
git remote add origin https://github.com/あなたのID/healthbook-platform.git
git push -u origin main
```

**② Azure Portalで Static Web Apps を作成**

- リソース作成 → 「Static Web Apps」検索
- デプロイのソース：**GitHub** を選択
- リポジトリ：`healthbook-platform`、ブランチ：`main`
- ビルドプリセット：**React**
- アプリの場所：`/`、出力の場所：`dist`

**③ Azureが自動でGitHub Actionsを設定** `main`へのpushのたびに自動ビルド＆デプロイされます。

**④ 完成** `https://ランダム名.azurestaticapps.net` でアクセス可能になります。

## Azure Static Web Apps とは

一言で言うと、**「GitHubにpushするだけで世界中に公開されるWebホスティング」**です。サーバー管理が一切不要で、HealthBookのようなReactアプリに最適です。

---

## HealthBookに関係する主要機能

**① GitHub連携の自動デプロイ** `main`ブランチにpushした瞬間、自動でビルド→世界配信まで完了します。手動操作は不要です。

**② グローバルCDN（コンテンツ配信網）** 静的ファイルを世界中のエッジサーバーに自動配置するため、東南アジア・アフリカからのアクセスも高速です。HealthBookのグローバル展開に直結します。

**③ Azure Functions との統合** JavaScript、TypeScript、Python、C#でAzure Functionsを使ったサーバーレスAPIを構築できます。将来の**Pythonバックエンド**（推論エンジン本番版）をそのまま同じリポジトリに追加できます。

**④ プレビュー環境** Pull Requestを作るたびに独立したプレビューURLが自動生成されます。本番に影響せずテストできます。

## 一点注意点

APIファンクションのリクエスト処理は最大45秒に制限されており、2025年はSWAのGitHubリポジトリの更新が少ない状況です。将来、推論エンジンの処理が重くなった場合は、APIバックエンドだけ**Azure Container Apps**や**Azure App Service**に分離する設計が安全です。

ただしHealthBookのPOC段階では全く問題ありません。まずフリープランで公開し、本番移行時に構成を見直す形で進めましょう。
