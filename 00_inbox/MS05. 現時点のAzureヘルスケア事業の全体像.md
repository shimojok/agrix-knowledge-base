## 現時点のAzureヘルスケア事業の全体像

### 1. Azure Health Data Services（データ基盤層）

医療データの収集・保存・分析を担う中核サービスで、以下のコンポーネントで構成される：

| サービス | 機能 |
|---|---|
| **FHIR® サービス** | 高速医療相互運用性リソース（FHIR）標準に準拠した医療データの交換・保存 |
| **DICOM® サービス** | 医療画像データの安全な保存・管理・交換 |
| **識別解除サービス** | 機械学習で臨床テキストからPHIを自動検出・編集し匿名化 |
| **MedTech サービス** | デバイスデータをFHIR形式に変換して保存（2025年5月より非推奨化進行中） |

### 2. Azure AI Foundry ヘルスケア基盤モデル（AI推論層）

Microsoft ResearchとMayo Clinicなど戦略的パートナーが共同開発した**マルチモーダル医療基盤モデル**を提供：

- **MedImageInsight**：医用画像の分類・類似性検索を可能にする埋め込みモデル
- 放射線科・病理・眼科・皮膚科など複数領域をカバー
- 画像・ゲノム・臨床記録など多様なモダリティのデータを統合分析

ただし現状は**研究・開発目的に限定**され、臨床診断への直接使用は想定されていない。

### 3. Azure AI Health Bot（対話型AI層）

医療組織が**AI駆動の会話型医療体験**を構築するプラットフォーム。トリアージプロトコルを含む組み込み医療データベースを備え、患者エンゲージメントの向上に焦点。

### 4. Microsoft Cloud for Healthcare（統合業界クラウド）

上記サービスを統合し、患者エンゲージメント・分析・コラボレーションを**コンプライアンス準拠のAI対応プラットフォーム**として提供。

### 5. Dragon Copilot（臨床ワークフローAI）

2025年発表の**臨床ワークフロー向けAIアシスタント**。環境AI（Ambient AI）を活用し、**臨床文書作成の自動化・管理業務の軽減**を実現。


## HealthBook‑MI との比較

| 比較軸 | Azure ヘルスケア事業（現状） | HealthBook‑MI |
|---|---|---|
| **根本思想** | 医療データの**相互運用性・保存・分析**を提供する「プラットフォーム」 | 個体の**代謝をOSとして扱う**「Metabolic Intelligence OS」 |
| **アプローチ** | データ管理＋汎用AIによる**ワークフロー支援**（対症・効率化志向） | 代謝の**上流因果構造を推論**し根本原因に介入（原因治療志向） |
| **中心指標** | FHIR/DICOMなどの**データ標準**と医療画像・テキスト分析 | **アセチルCoA生成能力**を中心に据えた代謝ハブモデル |
| **統合範囲** | 電子カルテ・医療画像・デバイスデータ・臨床文書 | **腸内細菌（Estrobolome）・ホルモン・ミトコンドリア・炎症・痛み**を統合 |
| **推論の深さ** | 画像分類・テキスト要約・パターン認識（**相関分析**） | 代謝偏位コード（Deviation Codes）による**因果グラフ**構築 |
| **介入手段** | 臨床判断の支援・文書作成支援（**間接的**） | 漢方（Fコード）・食事・運動・サプリメントへの**直接的介入** |
| **対象** | 医療機関・研究者・開発者（**B2B中心**） | 個人・企業・医療機関・保険会社・政府（**B2C/B2B2G**） |
| **セキュリティ** | Azureネイティブの医療データ保護（PHI対応） | 同左に加え、**Sovereign Cloud**での国家医療主権対応が可能 |

### 本質的な差異

Azureの現行ヘルスケア事業は**「医療データの基盤（インフラ）」** に強みを持ち、データの相互運用性とAIによる業務効率化を提供する。しかし、**「なぜその症状が起きているのか」という代謝の因果構造を扱うレイヤーは存在しない**。

対してHealthBook‑MIは、**腸内細菌→ホルモン→ミトコンドリア→ATP→痛み**という因果連鎖を推論し、**代謝偏位コード**に基づいて介入する独自のポジショニングを持つ。これはAzureのヘルスケアエコシステムに**欠けている「代謝因果推論」レイヤー**を補完し、両者の統合によって**「データ基盤（Azure）」＋「代謝知能（HealthBook‑MI）」** という完全なスタックが実現する。
