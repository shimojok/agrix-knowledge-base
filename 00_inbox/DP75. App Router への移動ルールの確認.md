### 0. まず、App Router への移動ルールの確認

**Q1. `frontend/pages/dashboard/market.tsx` → `frontend/app/dashboard/market/page.tsx` で、ファイル名は全部 `page.tsx` にするのか？**

- **はい、その理解で正しいです。**
- App Router では「**ディレクトリ名がルート名**」「その直下の `page.tsx` がそのルートのコンポーネント」というルールになります。

例：

- `pages/dashboard/market.tsx`
- → `app/dashboard/market/page.tsx`

ここで：

- `dashboard/market/` が `/dashboard/market` というルート
- その中の `page.tsx` が React コンポーネント

---

**Q2. `pages/dashboard/dashboard.tsx` → `app/dashboard/dashboard/page.tsx` で、`dashboard/dashboard/` という二重の名前でいいのか？**

- **はい、技術的には問題ありません。**
- ルート的には `/dashboard/dashboard` になります。
- もし「URL として `/dashboard` の下に “Dashboard メイン画面” を置きたい」なら：
    - `/dashboard` → `app/dashboard/page.tsx`
    - `/dashboard/dashboard` → `app/dashboard/dashboard/page.tsx`  
        という構造も許容されます。

---

`pages/dashboard/index.tsx`:

### ②-3. import パス修正の方針

- もしコンポーネントやユーティリティが `pages/` 配下から相対 import されている場合：
    - `../../components/...` → `../../components/...` のように、**相対パスの深さが変わる**可能性があります。
- 理想的には：
    - `components/` や `lib/` は `src/components` `src/lib` などにまとめて、
    - `@/components/...` `@/lib/...` のような **絶対パス import** に統一する。

ここは、**あなたが今後「全体構造を src/ に寄せるかどうか」次第で変わりますが、方針としては：**

- App Router への移行時に、**相対パスを絶対パスに変える**のが安全です。
