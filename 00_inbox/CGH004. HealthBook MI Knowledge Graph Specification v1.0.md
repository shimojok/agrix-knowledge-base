# HealthBook MI Knowledge Graph Specification v1.0

## Official Architecture Specification

---

# 結論

HealthBook MI Knowledge Graph（HMI-KG）は、**HealthBook Platform全体の中核知識基盤**として位置付けます。

重要なのは、**「疾患」を中心ノードにしない**ことです。

HealthBookでは、

> **代謝（Metabolism）を中心に、生体・微生物・栄養・環境・介入を因果的に結び付けるKnowledge Graph**

として設計します。

これは一般的な医療ナレッジグラフ（疾患・症状・薬剤中心）とは設計思想が異なります。

```text

PROMOTES

CORRELATES
```

# 次世代構想（v2.0）

現在の仕様をさらに発展させるなら、Knowledge Graphを**静的な知識格納庫**ではなく、**推論可能な代謝デジタルツイン**として扱うことを推奨します。

そのために、Knowledge Graphの上位層として以下の4つのエンジンを追加すると、HealthBookの独自性がさらに明確になります。

```text
Knowledge Graph
      │
      ▼
Causal Reasoning Engine
      │
Counterfactual Simulation Engine
      │
Digital Twin Engine
      │
Continuous Learning Engine
```

これにより、

* **Knowledge Graph**：知識の構造化
* **Causal Reasoning**：原因経路の推論
* **Counterfactual Simulation**：「もし〇〇を変えたら」の予測
* **Digital Twin**：患者ごとの代謝モデル
* **Continuous Learning**：知識ベースの継続的な更新

という役割分担が実現できます。

これは、HealthBookを「データ解析ツール」ではなく、**Metabolic Intelligence Platform**として位置付けるうえで、中核となるアーキテクチャです。
