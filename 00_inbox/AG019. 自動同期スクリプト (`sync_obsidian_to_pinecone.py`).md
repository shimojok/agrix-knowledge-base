5000ノート規模のモジュール群からハルシネーションを極限まで排除するため、このスクリプトには以下の高度な機構を組み込んでいます。

1. **フロントマター（YAML）の厳密なパース**: `module_id` や `agent_relation` などのメタデータを自動抽出。
    
2. **見出し（Markdown Heading）単位のインテリジェント・チャンキング**: 単純な文字数分割ではなく、文脈が途切れない「意味のまとまり」で分割。
    
3. **Pineconeへのメタデータ付き一括アップサート**: Next.jsやANEが高速にメタデータフィルタリングを行える構造。
    

## 🛠️ 自動同期スクリプト (`sync_obsidian_to_pinecone.py`)

まずはローカル環境やGitHub Actionsで動作するベーススクリプトのプロトタイプです。

Python

```
import os
import re
import glob
import yaml
from typing import List, Dict, Any
from pinecone import Pinecone
from openai import OpenAI

# ==========================================
# 1. 環境変数・定数の設定
# ==========================================
PINECONE_API_KEY = os.getenv("PINECONE_API_KEY")
PINECONE_INDEX_NAME = os.getenv("PINECONE_INDEX_NAME", "agrix-knowledge")
OPENAI_API_KEY = os.getenv("OPENAI_API_KEY")
EMBEDDING_MODEL = "text-embedding-3-large"  # 精度を極限まで高めるため大容量モデルを採用
VAULT_DIR = "./vault"  # GitHubレポジトリ内でのObsidian Vaultへのパス

# クライアント初期化
pc = Pinecone(api_key=PINECONE_API_KEY)
index = pc.Index(PINECONE_INDEX_NAME)
openai_client = OpenAI(api_key=OPENAI_API_KEY)

# ==========================================
# 2. Markdownパース & チャンキング関数
# ==========================================
def parse_markdown_file(file_path: str) -> List[Dict[str, Any]]:
    with open(file_path, 'r', encoding='utf-8') as f:
        content = f.read()

    # フロントマターの解析
    front_matter = {}
    body = content
    front_matter_match = re.match(r'^---\s*\n(.*?)\n---\s*\n', content, re.DOTALL)
    if front_matter_match:
        try:
            front_matter = yaml.safe_load(front_matter_match.group(1)) or {}
            body = content[front_matter_match.end():]
        except yaml.YAMLError:
            pass

    # ファイル名から基本情報を取得
    filename = os.path.basename(file_path)
    
    # 見出し（#、##、###）でテキストを分割（文脈を維持するチャンキング）
    # 見出しごとに区切ることで、AIエージェントがトピックを誤認するのを防ぎます
    sections = re.split(r'(^#{1,4}\s+.*$)', body, flags=re.MULTILINE)
    
    chunks = []
    current_header = "概要"
    
    # 最初のセクションが見出しで始まらない場合（冒頭の文章など）
    first_text = sections[0].strip()
    if first_text:
        chunks.append({
            "text": first_text,
            "header": current_header
        })

    # 見出しと本文をペアにしてチャンク化
    for i in range(1, len(sections), 2):
        if i + 1 < len(sections):
            header = sections[i].strip().replace("#", "").strip()
            text = sections[i+1].strip()
            if text:
                chunks.append({
                    "text": f"[{header}]\n{text}",
                    "header": header
                })

    # Pineconeに格納するメタデータとテキストの統合オブジェクトを生成
    processed_chunks = []
    for idx, chunk in enumerate(chunks):
        # ハルシネーション抑制のため、リッチなメタデータを付与
        metadata = {
            "source_file": filename,
            "module_id": front_matter.get("module_id", "unknown"),
            "agent_relation": front_matter.get("agent_relation", []),
            "target_audience": front_matter.get("target_audience", []),
            "section_header": chunk["header"],
            "chunk_index": idx
        }
        processed_chunks.append({
            "id": f"{filename}#chunk-{idx}",
            "text": chunk["text"],
            "metadata": metadata
        })
        
    return processed_chunks

# ==========================================
# 3. ベクトル化 & アップサート関数
# ==========================================
def get_embedding(text: str) -> List[float]:
    """テキストをベクトルに変換（1536次元または3072次元）"""
    response = openai_client.embeddings.create(
        input=[text],
        model=EMBEDDING_MODEL
    )
    return response.data[0].embedding

def sync_vault():
    print("🚀 Obsidian Vault から Pinecone への同期を開始します...")
    
    # .md ファイルを再帰的に取得
    md_files = glob.glob(os.path.join(VAULT_DIR, "**/*.md"), recursive=True)
    
    for file_path in md_files:
        print(f"📄 処理中: {os.path.basename(file_path)}")
        chunks = parse_markdown_file(file_path)
        
        vectors_to_upsert = []
        for chunk in chunks:
            # 埋め込みベクトルの生成
            vector = get_embedding(chunk["text"])
            
            # Pineconeはメタデータ値に辞書型やリストの混在を嫌う場合があるため、
            # 安全のために文字列やプリミティブの配列に正規化して格納
            pinecone_metadata = chunk["metadata"]
            pinecone_metadata["text"] = chunk["text"] # 検索時にテキスト本文を復元できるように格納
            
            vectors_to_upsert.append({
                "id": chunk["id"],
                "values": vector,
                "metadata": pinecone_metadata
            })
            
        # Pineconeへバッチアップサート（一括送信）
        if vectors_to_upsert:
            index.upsert(vectors=vectors_to_upsert)
            print(f"✅ {len(vectors_to_upsert)} 個のチャンクをアップサートしました。")

if __name__ == "__main__":
    sync_vault()
```

## 📈 このスクリプトがハルシネーションを防げる理由

1. **`text` のセマンティック保持**:
    
    見出し（`### 1.1 好気性55%の制御ロジック` など）をカットせず、チャンクの冒頭に `[見出し]` として結合しています。これにより、AIがベクトル検索した際に「この記述がどの文脈について語られているか」を絶対に見失いません。
    
2. **完璧な属性フィルタリング**:
    
    `module_id`（例: `DS003`）がメタデータに明記されるため、Next.js側から「モジュールDS003の知識内だけで検索せよ」という**メタデータフィルタ**をかけたクエリが可能になります。無関係なモジュールの知識が混ざってハルシネーションを起こす確率をゼロに抑え込めます。
    

## 🛠️ Obsidian側のノート記述ルール（Kazへの推奨）

このスクリプトの恩恵を100%受けるため、Obsidianのノート（例: `DS003.md`）の冒頭には以下のようなフロントマター（YAML）を記載してください。

Markdown

```
---
module_id: "DS003"
agent_relation: ["Agent-1", "Agent-4"]
target_audience: ["Producer", "Insurance-Co"]
tags: ["MBT55", "土壌制御"]
---

## 1. データの収集頻度
...
```
