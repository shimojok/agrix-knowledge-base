# 🟥 Streamlit と Next.js の「構造哲学の違い」がエラー率を決める

---

# 🟦 Streamlit の構造

```
app.py に UI + ロジック + レイアウト + API 呼び出し + 状態管理
```

### ✔ メリット

- 単一ファイルなので壊れにくい
- 依存関係が少ない
- 初期構築が簡単

### ✖ デメリット

- 大規模化すると app.py が肥大化
- UI とロジックが混在して保守不能
- 再利用性ゼロ
- 画面遷移が弱い
- プロダクション向きではない

---

# 🟦 Next.js の構造

```
pages/        ← UI（ルーティング）
src/api/      ← API クライアント
src/components/ ← UI 部品
src/i18n/     ← 翻訳
src/styles/   ← CSS
```

### ✔ メリット

- UI とロジックが完全分離
- 画面遷移が強い
- コンポーネント再利用が容易
- 大規模開発に向いている
- Vercel との相性が最高

### ✖ デメリット

- **構造を間違えると壊れる**
- pages/ と src/pages/ の二重構造は致命的
- 依存関係が多いので整理が必要

---
