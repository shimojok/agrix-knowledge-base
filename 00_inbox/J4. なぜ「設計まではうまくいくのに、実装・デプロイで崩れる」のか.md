## 1. なぜ「設計まではうまくいくのに、実装・デプロイで崩れる」のか

あなたが書いてくれた通りだと思う：

- 設計フェーズでは  
  - PBPE / PH-API / AGRIX / MBT / Ledger / Rating Engine / UI Mock / ER 図まで出てくる  
  - しかも、その多くは **AI があなたと一緒に作った高度な内容**  
- でも実装フェーズでは  
  - backend のエンジンが足りない  
  - Next.js 側のデータが薄くなる  
  - ダッシュボードが「理想の 1/10 くらいの情報量」になる  
  - 途中で別テーマ（MBT、ESG、他の OS）に引っ張られて、流れが切れる  

これは「あなたの集中力の問題」ではなくて、**プロジェクト運営の構造の問題**だと思っている。

### 構造的な原因を整理すると：

1. **設計と実装が別スレッド・別タイミングで行われている**  
   - 設計は PM1〜PM49 のように Obsidian に蓄積  
   - 実装は「そのときのスレッドの記憶」に依存  
2. **AI 側のメモリが、設計フェーズのコンテクストを保持しきれない**  
   - 「PBPE Marketplace Architecture — Complete Specification（PM32）」を前提にせずに実装が始まる  
3. **「このダッシュボードは、どの設計ドキュメントを実装したものか」が紐づいていない**  
   - だから、実装が薄くなっても「どこまで反映できているか」が分からない  

結果として：

> 設計は深いのに、実装は毎回 “ほぼゼロから” になってしまう

という状態になっている。

## 2. ここからの方針：「設計 → 実装」を一本の線にする

あなたがすでにやってくれていること：

- Obsidian に **すべての設計・議論・AIとのやり取りを保存している**
- PBPE Marketplace / Planetary Health OS / MBT / PH-API の設計ノートが揃っている
- PM32, PM33, PM35, PM36, PM37, PM38, PM39… など、**実装に直結するレベルの仕様がある**

これを「実装に直結する形」に変えるには、こうするのが一番現実的だと思う。

### ステップ 1：GitHub に「設計の公式コピー」を置く

たとえば：

- `docs/architecture/PBPE-Marketplace-Architecture.md` ← PM32 ベース  
- `docs/architecture/PBPE-Ledger-Data-Model.md` ← PM37  
- `docs/architecture/PBPE-Rating-Engine.md` ← PM38  
- `docs/architecture/PBPE-Financial-Product-Templates.md` ← PM35  
- `docs/architecture/PBPE-Dashboard-Design.md` ← PM36 + あなたが見せてくれた理想ダッシュボード  

こうしておけば、**どのスレッドの AI でも「まずこれを読め」と言える**。

### ステップ 2：1つのダッシュボードに対して「どの設計ドキュメントを実装するか」を固定する

たとえば：

> 「PBPE Dashboard v1」は、  
> `PBPE-Dashboard-Design.md` と  
> `PBPE-Rating-Engine.md` と  
> `PBPE-Ledger-Data-Model.md` を  
> **忠実に実装したものとする**

と決めてしまう。

そうすると、実装フェーズで私がやるべきことは明確になる：

- その 3 つのドキュメントを前提として読む  
- Next.js の `/dashboard` ページの仕様をそこから起こす  
- backend の `/dashboard` API を、その仕様に合わせて実装する  
- 「どの項目が実装済みで、どこが未実装か」を明示する  

### ステップ 3：実装は「ファイル単位」で、設計と紐づけて進める

あなたが言う通り、部分修正はやめて、こうする：

- `backend/routers/dashboard.py` → 「PBPE-Dashboard-Design.md のセクション 1〜3 を実装した版」  
- `backend/models/dashboard.py` → 「PBPE-Ledger-Data-Model.md のこの部分を反映」  
- `frontend/app/dashboard/page.tsx` → 「PBPE-Dashboard-Design.md の UI モックを反映」  

こうしておけば、**「このコードは、どの設計ドキュメントの、どの部分を実装したものか」が常に追える**。
