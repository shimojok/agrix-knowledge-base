## 📁 **A: Pages Router（あなたの構造）**

コード

```
src/pages/
  index.tsx
  login.tsx
  dashboard/
    index.tsx
    kpis.tsx
    ...
```

- ファイル名 = ルート
    
- `pages/dashboard/index.tsx` → `/dashboard`
    
- `_app.tsx` で全体レイアウト
    
- `_document.tsx` で HTML カスタム
    

**直感的でわかりやすい。**

## 📁 **B: App Router（新構造）**

コード

```
app/
  layout.tsx
  page.tsx
  dashboard/
    layout.tsx
    page.tsx
    kpis/
      page.tsx
```

- すべてのページは `page.tsx`
    
- すべてのレイアウトは `layout.tsx`
    
- Server Components がデフォルト
    
- Suspense / Streaming が標準
    

**強力だが複雑。**

# 🛠 使用ツール・技術の違い

## **A: Pages Router**

- React Client Components（従来の React）
    
- getServerSideProps / getStaticProps
    
- useEffect / useState が中心
    
- axios / fetch を自由に使える
    
- レイアウトは `_app.tsx` で一括管理
    

## **B: App Router**

- Server Components（新概念）
    
- Route Handlers（API を app 内に置ける）
    
- Suspense / Streaming
    
- Layout の階層構造
    
- fetch がサーバー側で自動キャッシュ
    

**App Router は “Next.js 2.0” と言えるほど別物。**

# 🏗 構築プロセスの違い

## **A: Pages Router（あなたの現在の構造）**

1. `pages/xxx.tsx` を作る
    
2. 必要なら `_app.tsx` にレイアウトを書く
    
3. axios で API を叩く
    
4. 完成
    

**最短で動く。**

## **B: App Router**

1. `app/layout.tsx` を作る
    
2. `app/page.tsx` を作る
    
3. 各ページに `page.tsx`
    
4. 各階層に `layout.tsx`
    
5. Server Component / Client Component を分ける
    
6. Suspense / Loading UI を作る
    
7. fetch のキャッシュ戦略を決める
    
8. 完成（遠い）
    

**構築ステップが Pages Router の 3〜5倍。**
