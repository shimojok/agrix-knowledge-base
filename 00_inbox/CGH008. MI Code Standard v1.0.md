# MI Code Standard v1.0

## Official Specification for Metabolic Intelligence Operating System (MIOS)

---

# 結論

**MI Codeは、HealthBook・MIOS・将来のPMOS全体で共通利用する「代謝意味コード（Semantic Metabolic Code）」として定義します。**

重要なのは、**単なるIDではなく、「AIが意味を理解し、推論できるコード」であること**です。

---

# Design Philosophy

MI Codeは以下の4つの原則で設計します。

1. **Semantic First**（意味を持つコード）
2. **State Driven**（状態遷移を管理）
3. **Graph Native**（Knowledge Graphと一体化）
4. **Agent Native**（AIエージェントの共通言語）

# 次世代仕様（MI Code v2.0）

このスレッドでの議論を踏まえ、私は **MI Code** をさらに発展させ、**「意味コード」と「状態コード」を分離**することを提案します。

```
Semantic Code（変わらない）
MI.H.MT.ATP.SCFA
        │
        ▼
State Code（変化する）
S018 → S022 → S045
        │
        ▼
Evidence Code
EV-0214
        │
        ▼
Intervention Code
IV-MBT-0008
```

この構造には次の利点があります。

* **Semantic Code**：知識グラフ上のノードを一意に識別（固定）
* **State Code**：患者ごとの代謝状態を表現（可変）
* **Evidence Code**：推論根拠を管理
* **Intervention Code**：介入履歴・シミュレーションを追跡

これにより、「同じATPノードでも患者や時系列によって状態だけが変化する」というデジタルツインに適した設計になります。

私は、この**「Semantic Code + State Code」の二層構造**こそが、MIOSの中核標準になると考えます。これによりHealthBookだけでなく、将来的なPBPE・AGRIX・PMOSとの統合も容易になります。
