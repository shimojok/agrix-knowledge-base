### 1. SafetyChain™の整理（あなたの定義を Next.js/API に載せるために）

あなたが書いてくれた通り、SafetyChain™は「安全性の証明」ではなく、**消費者の選択基準となる機能性・品質そのもの**ですよね。

ポイントを API で扱える「変数」に落とすと、こうなります。

- **選択基準の中身**
    
    - **栄養価:** アミノ酸、ミネラル、糖度ではなく「ポリフェノールの質と量」
    - **鮮度保持力:** 収穫後どれだけ代謝が続くか（Metabolic Inertia／V-Score）
        
- **それを決める要因**
    
    - **土壌細菌群（MBT55）と土壌環境（pH, Eh, 水分, 有機炭素, N）**
    - **フェノタイピング（葉色・光学指標・代謝マーカー）**
        

SafetyChain™は、これらを「トレーサビリティ情報」ではなく、**消費者が比較・選択できる API データ**として出す——ここが肝ですね。

> 「SafetyChain™は、従来の静的なトレーサビリティの概念を超越し、農産物・畜産物・海産物が持つ『代謝の慣性』と『生態学的機能性』をリアルタイムで証明・追跡する、世界初の生命維持型サプライチェーン・プロトコルである。」

### 2. 土壌データ項目（AGRIX × MBT55 × SafetyChain 用）

API Routesで扱う「土壌データ項目」は、MBT55ドキュメントと SafetyChain 群から、最低限こう整理できます。

#### 土壌・環境系

- **pH**
- **Eh（酸化還元電位）**
- **水分（θ）**
- **温度**
- **電気伝導度（EC）**
- **交換性ナトリウム比（ESP）**
- **有機炭素量（C）**
- **有効態窒素（N）**

> 「土壌センサーデータ（pH, Eh, 水分）で拡張した、AGRIX-OSの中核演算モデル。」

#### MBT55・代謝系

- **有機物分解率（24h OM Degradation Rate）**
- **C/N 比の変化**
- **CO₂発生量（土壌呼吸）**
- **病原菌抑制率**
- **SCFA・ポリフェノール前駆体の生成指標**

> 「有機物分解率 ≥85% / 24h」「C/N比 40–60 → 15–18」など、MBT55の高速代謝圧縮パラメータ。

#### SafetyChain／フェノタイピング系

- **V-Score（代謝寿命指標）**
- **Metabolic Life（日数）**
- **ポリフェノール密度（機能性指数）**
- **鮮度保持力グレード（Platinum/Gold/Silver/Standard）**

> 「Vitality Score（V-Score）は、収穫後のATP減少速度に基づく代謝的活力指標（0-100）。」

#### `/app/api/safetychain/vscore/route.ts`

**役割:** SafetyChain™の「鮮度保持力＝代謝寿命」を計算・返却。

- **POST**: 収穫時バイオマーカー＋保存条件から V-Score と Metabolic Life を計算
    
- **GET**: 既存ロットの V-Score を取得
    

ts

```
// app/api/safetychain/vscore/route.ts
import { NextRequest, NextResponse } from 'next/server';

function computeVScore(params: {
  atp_initial: number;
  storageTempC: number;
  scfaIndex: number;
  antioxidantIndex: number;
}) {
  // 簡易モデル：本番は 04_vscore_model.md の式に合わせて精緻化
  const base = params.atp_initial;
  const tempFactor = params.storageTempC <= 5 ? 0.9 : 1.0;
  const protection =
    0.4 * params.scfaIndex + 0.6 * params.antioxidantIndex;
  const vScore = Math.min(1, (base * tempFactor * protection) / 100);
  return vScore;
}

export async function POST(req: NextRequest) {
  const body = await req.json();
  const vScore = computeVScore(body);
  // 閾値 0.35 を「機能性維持限界」として残日数をざっくり推定
  const metabolicLifeDays = Math.round((vScore - 0.35) * 30);
  return NextResponse.json({
    vScore,
    metabolicLifeDays: Math.max(0, metabolicLifeDays),
    grade:
      vScore >= 0.85
        ? 'Platinum'
        : vScore >= 0.7
        ? 'Gold'
        : vScore >= 0.55
        ? 'Silver'
        : 'Standard',
  });
}
```

> 「V-Scoreが機能的閾値（35）を下回るまでの残日数。」

#### `/app/api/safetychain/pricing/route.ts`

**役割:** 4レイヤー動的価格モデルを API 化。

ts

```
// app/api/safetychain/pricing/route.ts
import { NextRequest, NextResponse } from 'next/server';

export async function POST(req: NextRequest) {
  const body = await req.json();
  const { pMarket, V, L, m, C } = body;
  const pTotal = pMarket + V + L + m + C;
  return NextResponse.json({ pMarket, V, L, m, C, pTotal });
}
```

> 「P_total = P_market + V + L + m + C」という 4レイヤー動的価格モデル。
