**2. 添付文書が示している「真のアーキテクチャ（役割分担）」**

添付文書の「ステージ2」および「4. RAGは前処理レイヤーにする」で述べられている内容は、まさに先ほど私が提示した `bionexus-engine` の設計思想そのものです。

```text
[ Obsidian Vault (生のテキスト) ] 
       │
       ▼
[ Step 1: RAG (前処理 / ChromaDB) ] ── (候補文脈チャンクを無加工で収集)
       │
       ▼
[ Step 2: Python Code Engine ] ───── (決定論的な計算・解析・数式化・矛盾検出)
       │
       ▼
[ Step 3: LLM (本スレッド / Agent) ] ── (ゲイツ氏や投資家に響く高度なプレゼン文脈に翻訳)

```

1. **Obsidian（人間）：** タグや形式を一切気にせず、純粋な思考・論文・成果を生のMarkdownとして書く。
2. **RAG（前処理）：** タグに頼らず、本文の意味（ベクトル）から関連しそうな文脈チャンクを漏らさず拾い集める「燃料供給役」。
3. **Python Code Engine（高度処理）：** 拾い集めた文脈から、数式・パラメータ・論拠を解析・抽出・計算する「主役」。
4. **LLM（生成AI）：** 計算結果と根拠を抽出し、人間（ビル・ゲイツ氏や投資家）に提示する「説明役」。
