## 💡 このアプローチが「超スマート」である3つの理由

1. **データの性質に応じた最適化（無理にマージしない）** 5,100ノートは「非構造化された思考や文脈」ですが、`HealthBookMBT`や`M3-BioSynergy-Core`は「厳密な数理モデル、数式、JSONデータ」です。これらを1つのフォルダ（Vault）に無理やり混ぜると管理が破綻します。**リポジトリを分けたまま、Pinecone（脳）の中でだけ融合させる**のが最もスマートです。
    
2. **容量と実行コストの圧倒的な削減** 目的別リポジトリはファイル数が少ないため、Embedding（ベクトル化）の計算コストがほぼかかりません。それでいて、中身は数理モデル（ODE）や漢方代謝ライブラリなど高密度な情報ばかりなので、AIの回答精度が跳ね上がります。
    
3. **開発の並行性（モジュール化）** 「Obsidianで思考をアップデートする作業」と「StreamlitやNext.jsのコードを修正する作業」が完全に独立するため、GitHubのコンフリクト（衝突）が起きず、安全に開発を進められます。
    

## 🏗️ 複数リポジトリを1つのPineconeに繋ぐ「マルチソース・パイプライン」

これを実現するためには、Pythonスクリプトを以下のように設計します。Kazさんがやることは、**各リポジトリのGitHub Actionsにこのスクリプトを配置するだけ**です。

```
【データソース（GitHub群）】
① BioNexus_vault ─────> [自動同期] ──┐
② M3-BioSynergy-Core ──> [自動同期] ──┼─> 【 1つのPineconeインデックス 】
③ HealthBookMBT ──────> [自動同期] ──┘   (メタデータでソースを識別)
```

Pinecone側では、格納されるデータに以下のようなメタデータが自動で付与されるため、混ざることはありません。

- Vaultからのデータ ➔ `{"source_repo": "BioNexus_vault", "data_type": "text"}`
    
- M3-Coreからのデータ ➔ `{"source_repo": "M3-BioSynergy-Core", "data_type": "python_code"}`
    
- HealthBookMBTのJSON ➔ `{"source_repo": "HealthBookMBT", "data_type": "structured_json"}`
    

## 🐍 複数リポジトリ対応版：自動同期スクリプト

Kazさんのアイデアを具現化するため、先ほどのスクリプトを「今どのリポジトリから実行されているか」を自動判定する形にアップグレードしました。

各目的別リポジトリ（`M3-BioSynergy-Core` や `HealthBookMBT`）のCI/CD環境にそのまま配置して使い回せる、汎用性の高い共通ロジックです。Markdownだけでなく、**Pythonコード（`.py`）や漢方・代謝の`JSON`ファイルも自動パースしてPineconeへ格納**します。

Python

```
import os
import re
import glob
import json
from typing import List, Dict, Any
from pinecone import Pinecone
from sentence_transformers import SentenceTransformer

# ==========================================
# 1. 環境変数とモデルの初期化
# ==========================================
PINECONE_API_KEY = os.getenv("PINECONE_API_KEY")
PINECONE_INDEX_NAME = os.getenv("PINECONE_INDEX_NAME", "bionexus-hypercycle")

# 実行中のGitHubリポジトリ名を自動取得（例: "shimojok/M3-BioSynergy-Core"）
# ローカル実行時はフォルダ名をデフォルト値にする
REPO_NAME = os.getenv("GITHUB_REPOSITORY", os.path.basename(os.getcwd()))

print(f"🚀 リポジトリ [ {REPO_NAME} ] の同期処理を開始します...")
embedding_model = SentenceTransformer('sentence-transformers/all-MiniLM-L6-v2')

pc = Pinecone(api_key=PINECONE_API_KEY)
index = pc.Index(PINECONE_INDEX_NAME)

# ==========================================
# 2. ファイル拡張子に応じた自動パース処理
# ==========================================

def parse_file(file_path: str) -> List[Dict[str, Any]]:
    """ファイルの拡張子を自動判別してチャンクとメタデータを生成する"""
    ext = os.path.splitext(file_path)[1].lower()
    base_name = os.path.basename(file_path)
    
    # 共通メタデータの土台
    base_metadata = {
        "source_repo": REPO_NAME,
        "file_path": file_path.replace("\\", "/"),
        "file_name": base_name
    }
    
    chunks = []

    # ---- A. JSONファイルの処理 (漢方代謝ライブラリなど) ----
    if ext == ".json":
        with open(file_path, 'r', encoding='utf-8') as f:
            try:
                data = json.load(f)
                # JSON全体、または配列なら要素ごとに格納
                content_str = json.dumps(data, ensure_ascii=False, indent=2)
                meta = base_metadata.copy()
                meta.update({"data_type": "structured_json"})
                chunks.append({
                    "id": f"{base_name}#json-root",
                    "text": content_str,
                    "metadata": meta
                })
            except json.JSONDecodeError:
                pass

    # ---- B. Pythonコードの処理 (数理モデル、ODEエンジン) ----
    elif ext == ".py":
        with open(file_path, 'r', encoding='utf-8') as f:
            code = f.read()
        # クラスや関数ごとに区切るのが理想だが、簡易的に1ファイル（または大きければ分割）で格納
        meta = base_metadata.copy()
        meta.update({"data_type": "python_code"})
        chunks.append({
            "id": f"{base_name}#code",
            "text": f"### Python Code: {base_name} ###\n{code}",
            "metadata": meta
        })

    # ---- C. Markdownファイルの処理 (Obsidianノート、README) ----
    elif ext == ".md":
        with open(file_path, 'r', encoding='utf-8') as f:
            body = f.read()
        
        # 見出し単位で簡易分割
        sections = re.split(r'(^#{1 ignorcase,4}\s+.*$)', body, flags=re.MULTILINE)
        current_header = "General"
        
        for i in range(0, len(sections)-1, 2):
            header = sections[i].strip().replace("#", "").strip()
            text = sections[i+1].strip() if i+1 < len(sections) else ""
            if text:
                meta = base_metadata.copy()
                meta.update({
                    "data_type": "unstructured_text",
                    "section_header": header
                })
                chunks.append({
                    "id": f"{base_name}#md-{i}",
                    "text": f"[{header}]\n{text}",
                    "metadata": meta
                })

    return chunks

# ==========================================
# 3. メインスキャン実行
# ==========================================
def main():
    # 対象とする拡張子を指定
    targets = ["**/*.md", "**/*.py", "**/*.json"]
    file_paths = []
    for t in targets:
        file_paths.extend(glob.glob(t, recursive=True))

    print(f"📦 スキャン完了: 計 {len(file_paths)} 個のファイルを処理します。")

    for path in file_paths:
        # 特殊なフォルダや依存ライブラリ（venv, .git, node_modules）は完全に除外
        if any(x in path for x in ["node_modules", "venv", ".git", ".obsidian", ".trash"]):
            continue
            
        chunks = parse_file(path)
        if not chunks:
            continue
            
        print(f"📄 処理中: {path}")
        texts = [c["text"] for c in chunks]
        
        # ローカルで安全にEmbedding化
        embeddings = embedding_model.encode(texts).tolist()
        
        vectors_to_upsert = []
        for idx, chunk in enumerate(chunks):
            pinecone_metadata = chunk["metadata"]
            # 検索時に元のコードやJSONを復元できるように、text自体もメタデータに埋め込む
            pinecone_metadata["text"] = chunk["text"]
            
            vectors_to_upsert.append({
                "id": f"{REPO_NAME}#{chunk['id']}",
                "values": embeddings[idx],
                "metadata": pinecone_metadata
            })
            
        if vectors_to_upsert:
            index.upsert(vectors=vectors_to_upsert)

if __name__ == "__main__":
    main()
```

## 🎯 次の具体的な進め方

この方式で行く場合、Kazさんの作業は以下のように劇的にシンプルになります。

2. 既存の `M3-BioSynergy-Core` や `HealthBookMBT` などの目的別リポジトリをそのまま維持する（どこかに無理にコピーしてまとめる必要はありません）。
