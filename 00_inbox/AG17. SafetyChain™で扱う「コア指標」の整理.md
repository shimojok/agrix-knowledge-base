その前に、SafetyChain™について確認させてください。

SafetyChain™の基本的な概念は、一般的な農作物のトレースだけを行う、トレーサビリティでは、価値の付与も意味も何もないところからスタートしています。
生産者の顔をみても、消費者は何の役にも立ちません。プロモーションであってはならないのです。
消費者の立場（流通業者も同じ）として考えると、農産物の選択基準が明確でなければなりません。

農産物の選択基準
｜
鮮度ー朝取りであれば鮮度が高いのは意味がないー新鮮さと同時に鮮度保持力が必要
｜
鮮度保持力の要素はポリフェノールの質と量です。
つまり、栄養価と鮮度保持力がすべてを表すのです。これを満たせば、味や香り、色にも反映します。農作物の機能性につながるわけです。
｜
ポリフェノールの生成には、土壌細菌と土壌環境がカギとなります。
｜そして、これらを判断する手法の一つが、フェノタイピングです。

以上を考慮して表現すると、SafetyChain™とは、消費者の選択基準となる機能性・品質ということとなります。

あなたの整理、とてもクリアです。 SafetyChain™＝「消費者の選択基準となる機能性・品質（＝栄養価＋鮮度保持力＋ポリフェノール密度）」を、土壌・MBT55・フェノタイピングから数値として証明するプロトコル――この前提でAPI Routesを設計します。

## 1. SafetyChain™で扱う「コア指標」の整理

APIで必ず扱うべき主要指標だけ、まず揃えます。

- **機能性・品質系**
    
    - **V-Score / V-Index:** 代謝寿命・鮮度保持力（ATP減衰モデル）
        
    - **ポリフェノール密度 / 抗酸化指標:** NDVI/PRIやフェノタイピングからの機能性スコア
        
    - **SCFA・栄養カスケード指標:** 土壌→作物→機能性への変換効率
        
- **土壌・MBT55系**
    
    - **SHEスコア:** micro/humic/CN/phys の統合土壌健康指標
        
    - **炭素隔離量（carbon_seq_rate）:** tCO₂/ha/year（PBPE-Finance連携）
        
    - **MBT55ハイパーサイクル指標:** ω_cycle（24時間腐植化達成率）など
        
- **価格・インパクト系**
    
    - **4レイヤー価格モデル:** V（機能性）＋L（ロス削減）＋m（医療費削減）＋C（炭素）
        
    - **SafetyChain Certificate:** Security Level / Functionality Index / Metabolic Life
        

## 2. API Routes 全体構造（Next.js / Node想定）

### ベース構造

- **ベースパス:** `/api/safetychain`
    
- 役割ごとにサブパスを分割し、「土壌 → フェノタイピング → V-Score → 証明書 → 価格」の流れをAPIで再現します。
    

## 3. ルート一覧と役割

### 3-1. 土壌・MBT55動態系

`GET /api/safetychain/soil-dynamics`

- **目的:** センサー値（pH, Eh, 水分）から、MBT55拡張ODEモデルの現在状態を返す。
    
- **クエリ例:**
    
    - `?ph=7.3&eh=120&moisture=65`
        
- **レスポンス例（概念）:**
    
    - `she_score`
        
    - `carbon_seq_rate`
        
    - `micro_score / humic_score / cn_score / phys_score`
        

`POST /api/safetychain/soil-dynamics/simulate`

- **目的:** 一定期間の土壌動態シミュレーション（MBT55投入シナリオ）を返す。
    

### 3-2. フェノタイピング・機能性評価系

`POST /api/safetychain/phenotyping/evaluate`

- **目的:** 土壌・作物のフェノタイピング入力から、機能性・ポリフェノール・鮮度保持力の指標を算出。
    
- **入力例（JSON）:**
    
    - 土壌：`she_score`, `mbt55_cycle`, `scfa_potential`
        
    - 作物：`ndvi`, `pri`, `polyphenol_lab_value`, `harvest_atp`
        
- **出力例:**
    
    - `functionality_index`（ポリフェノール質・量＋抗酸化）
        
    - `inertia_index`（代謝慣性）
        
    - `security_index`（バイオセキュリティ）
        

### 3-3. V-Score / Metabolic Life 系

`POST /api/safetychain/vscore/calculate`

- **目的:** 収穫時ATP・保存条件からV-Scoreと代謝寿命を算出。
    
- **入力例:**
    
    - `harvest_atp`
        
    - `storage_temp`
        
    - `scfa_density`
        
    - `antioxidant_density`
        
- **出力例:**
    
    - `v_score`（0–1）
        
    - `grade`（Platinum/Gold/Silver/Standard）
        
    - `metabolic_life_days`
        

### 3-4. SafetyChain Certificate 発行系

`POST /api/safetychain/certificates`

- **目的:** 土壌・フェノタイピング・V-Score・MBT55情報から、1ロット分のSafetyChain™証明書を生成。
    
- **入力例:**
    
    - `lot_id`
        
    - `soil_metrics`（SHE, carbon_seq_rate, mbt55_cycle）
        
    - `phenomics_metrics`（functionality/inertia/security）
        
    - `v_score`, `metabolic_life_days`
        
- **出力例:**
    
    - `security_level`
        
    - `functionality_index`
        
    - `metabolic_life`
        
    - `v_index_total`
        
    - `issued_at`, `valid_until`
        

`GET /api/safetychain/certificates/:lot_id`

- **目的:** 既存ロットの証明書を取得（消費者・流通業者の選択基準用）。
    

### 3-5. 動的価格決定（4レイヤー）系

`POST /api/safetychain/pricing/calculate`

- **目的:** SafetyChain指標から、`P_total = P_market + V + L + m + C` を算出。
    
- **入力例:**
    
    - `p_market`
        
    - `v_score` / `functionality_index`
        
    - `loss_avoidance_index`
        
    - `medical_roi_index`
        
    - `carbon_sequestration`
        
- **出力例:**
    
    - `p_total`
        
    - `layer_breakdown`（V/L/m/Cごとの金額）
        

## 4. 「消費者の選択基準」としてのAPIの役割

あなたが書いてくれた流れを、そのままAPIに落とすとこうなります。

1. **土壌・MBT55 → 機能性・鮮度保持力のポテンシャル** `/soil-dynamics` と `/phenotyping/evaluate` が、ポリフェノール生成能力と代謝慣性の「土台」を数値化。
    
2. **作物の鮮度保持力（V-Score）** `/vscore/calculate` が、「朝取り」ではなく「何日間、機能性を維持できるか」を返す。
    
3. **SafetyChain™証明書** `/certificates` が、「このロットは機能性・鮮度保持力・バイオセキュリティの観点で、どのレベルか」を一枚の証明書にまとめる。
    
4. **価格とインパクト** `/pricing/calculate` が、「その機能性・品質が価格にどう反映されるか」をPBPEロジックとして返す。
