# 1️⃣ **デプロイ方式の決定（最重要）**

PBPE Marketplace は **国際展開前提の SaaS** だから、  
デプロイ方式は次の 3 つのどれかが最適。

---

## **A. Azure（最も相性が良い）**
- Azure App Service（Backend）  
- Azure Static Web Apps（Frontend）  
- Azure PostgreSQL  
- Azure Key Vault（Secrets）  
- Azure Monitor（ログ）

**メリット：**  
- BioNexus の世界観と相性が良い  
- PBPE Marketplace のスケールに耐える  
- 政府・企業向けに強い

---

## **B. Vercel + Railway（最速で公開できる）**
- Frontend → Vercel  
- Backend → Railway  
- DB → Railway PostgreSQL  

**メリット：**  
- デプロイが最速  
- Dashboard v3 が美しく動く  
- 国際アクセスに強い

---

## **C. AWS（エンタープライズ向け）**
- ECS / Fargate  
- RDS  
- CloudFront  
- Route53  

**メリット：**  
- 大規模運用に最適  
- 企業導入に強い

---

Kaz、あなたのプロジェクトの性質からすると：

> **最適解は「Azure」か「Vercel + Railway」**

どちらでも PBPE Marketplace は完璧に動く。

---

# 2️⃣ **環境変数・Secrets の整理**

必要な環境変数は以下：

- `DATABASE_URL`  
- `JWT_SECRET`  
- `CREDITS_API_KEY`  
- `BONDS_API_KEY`  
- `INSURANCE_API_KEY`  
- `SCOPE3_API_KEY`  
- `PBPE_API_KEY`  
- `NEXT_PUBLIC_API_URL`（Frontend）

これらを **Azure Key Vault / Railway Secrets / Vercel Env** に登録する。

---

# 3️⃣ **バックエンドのデプロイ**

バックエンドは以下の構成：

- Node.js / Express  
- PostgreSQL  
- JWT Auth  
- PBPE Finance Engine  
- Scope 3 Conversion Engine  
- Dashboard API  

デプロイ先：

- Azure App Service  
- Railway  
- AWS ECS  

---

# 4️⃣ **フロントエンドのデプロイ**

フロントエンド（Dashboard v3）は：

- React + Vite  
- i18n（日英切り替え）  
- PBPE Blue / Eco Green デザイン  
- 全ページ統一レイアウト  

デプロイ先：

- Azure Static Web Apps  
- Vercel  
- Netlify  

---

# 5️⃣ **ドメイン設定**

推奨ドメイン：

- **pbpe.marketplace**  
- **pbpe.global**  
- **marketplace.pbpe.global**  
- **dashboard.pbpe.global**

DNS 設定：

- A レコード → Backend  
- CNAME → Frontend  
- TXT → SSL / Verification
