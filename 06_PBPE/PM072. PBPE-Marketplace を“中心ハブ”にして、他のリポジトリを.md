# 🧭 **Step 1：まず結論（統合マップ）**

Kaz、あなたのプロジェクトはこう整理するのが最も美しい。

```
PBPE-Marketplace  ←（中心・SaaS本体）
│
├── PBPE-Finance（→ Marketplace backend に統合）
├── PBPE-Dashboard（→ Marketplace frontend に統合）
├── MBT-Biosecurity-Engine（→ API として連携）
└── PBPE-Coffee（→ 完全に Marketplace の一部へ統合）
```

つまり：

- **PBPE-Marketplace = PBPE 全体の“本体”**  
- PBPE-Finance / PBPE-Dashboard / PBPE-Coffee は **Marketplace に吸収**  
- MBT-Biosecurity-Engine は **独立 API として連携**（統合しない方が良い）

# 🧩 **Step 2：リポジトリごとの“最適な扱い”**

## ① **PBPE-Marketplace（中心）**
→ **すべての UI / API / PBPE ロジックをここに集約する**

- Dashboard v3  
- PBPE Credits / Bonds / Insurance  
- Scope 3 → PBPE  
- PBPE Issuance  
- Enterprise Dashboard  
- Global KPIs  

PBPE-Marketplace は **あなたの全プロジェクトの中心**。

---

## ② **PBPE-Finance → Marketplace backend に統合**
**統合すべき理由：**

- PBPE Credits / Bonds / Insurance は Marketplace の中核機能  
- Streamlit 版はプロトタイプ  
- Marketplace の API と UI に統合した方が自然

**統合方法：**

- PBPE-Finance のロジックを  
  → Marketplace の `/api/finance/*` に移植  
- Streamlit UI は削除（役割終了）

**分類：**  
→ **統合**

---

## ③ **PBPE-Dashboard → Marketplace frontend に統合**
**統合すべき理由：**

- PBPE-Dashboard は Streamlit 版の旧 UI  
- Dashboard v3（React）が正式版  
- 役割が完全に Marketplace に移行済み

**統合方法：**

- PBPE-Dashboard の KPI / チャート設計を  
  → Marketplace の React Dashboard に移植  
- Streamlit UI は削除（役割終了）

**分類：**  
→ **統合**

---

## ④ **PBPE-Coffee → Marketplace の一部へ統合**
**統合すべき理由：**

- PBPE-Coffee は PBPE の“最初のプロトタイプ”  
- 現在は Marketplace の一部として扱うのが自然  
- コードは軽量で、統合が簡単

**統合方法：**

- PBPE-Coffee のロジックを  
  → Marketplace の `/api/coffee/*` に移植  
- UI は Dashboard v3 の「Impact Breakdown」へ統合

**分類：**  
→ **統合**

---

## ⑤ **MBT-Biosecurity-Engine → 独立 API として連携（統合しない）**
**統合しない理由：**

- MBT-Biosecurity-Engine は **独立した専門エンジン**  
- PBPE Marketplace の一部にすると逆に複雑化  
- 将来、他プロジェクト（HealthBook / AGRIX）とも連携する

**最適な扱い：**

- MBT-Biosecurity-Engine は **外部 API** として扱う  
- Marketplace backend から  
  → `https://mbt-engine/api/biosecurity`  
  のように呼び出す

**分類：**  
→ **連携（統合しない）**
