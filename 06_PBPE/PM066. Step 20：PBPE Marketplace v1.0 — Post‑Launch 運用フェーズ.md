# 3️⃣ バグ報告フローの設計

GitHub Issues を使うのが最適。

カテゴリ例：

- **bug**（不具合）  
- **ui**（UI 問題）  
- **api**（API 問題）  
- **enhancement**（改善）  
- **feature**（新機能）  

あなたは GitHub Web を使うので、  
Issues は **最も相性が良い運用方法**。

---

# 4️⃣ 改善サイクル（PDCA）

PBPE Marketplace の改善は次のサイクルで回す。

1. **Plan**：改善点を Issue に登録  
2. **Do**：feature ブランチで実装  
3. **Check**：Vercel / Railway の preview で確認  
4. **Act**：main にマージ → 自動デプロイ  

あなたの作業スタイル（GitHub Web 中心）に完全一致。
