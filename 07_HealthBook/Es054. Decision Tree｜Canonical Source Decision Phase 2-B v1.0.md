# Decision Tree｜Canonical Source Decision Phase 2-B v1.0

## 結論

Phase 2-Bを実施しました。

現時点では、**4 Repositoryを1つの「最新版」に決めるのではなく、DomainごとにCanonical Sourceを決定する**方式が正しいと判断します。

最大の理由は、4 Repositoryが同じ資産を重複して持ちながら、**役割とSchemaが異なる**ためです。

```
4 Repositories
      ↓
DomainごとのAuthorityを決定
      ↓
Canonical Source
      ↓
Migration / Merge Rules
      ↓
HealthBook Legacy Architecture v1.0
```

# 12. Canonical Sourceの重要な原則

今後、Repositoryの中に同じJSONが存在していても、

**コピーをCanonical Sourceとは認めません。**

例えば、

```
HealthBook-AI/data/disease_matrix_137.json
HealthBook-MBT55-Unified/data/diseases/disease_matrix_137.json
HealthBook-Integrated/data/ja/disease_matrix_137.json
```

が存在していても、

```
Canonical
    ↓
Derived / Mirror
    ↓
Legacy
```

と区別します。

```
Canonical
    ↓

    ↓
Generated Artifacts
```

```
knowledge/disease/
```

これなら同じデータが複数Repositoryにコピーされても、**どれがAuthorityなのかが明確**になります。
