各サブエージェントに、カスタムPromptを伝える必要があると考えますが、どうですか？

---

はい。**必要です。**  
むしろ今回のようにAgentを分業させる場合、各サブエージェントに**役割を固定するCustom Prompt**を最初に与えるべきです。

ただし重要なのは、**6本それぞれを別々に設計し直すのではなく、共通の「PMOS/BioNexus Governance Contract」を土台にして、Agent固有の責務だけを追加する**ことです。

## 推奨構造

```text
BioNexus｜Architecture & Implementation Office
│
├── 00｜Global Governance / Agent Contract
│
└── PROJECT 01｜HealthBook-MIOS
    │
    ├── [00] PMO / Chief Architect
    ├── [01] Reconstruction Agent
    ├── [02] Architecture Genealogy Agent
    ├── [03] Evidence & Reconciliation Agent
    ├── [04] Data / Schema Agent
    └── [05] Implementation Agent
```

### Custom Promptの二層構造

**Layer 1｜共通Prompt**

全Agentに共通：

- Canonical / Confirmedを勝手に変更しない
    
- Source / Evidence / Model / Decisionを混同しない
    
- 過去の設計を勝手に再設計しない
    
- 不明点は推測せず `UNRESOLVED` とする
    
- Source Provenanceを保持する
    
- 作業は  
    **Analysis → Generation → Verification → Decision → Implementation**  
    の順序
    
- Design Loopを検知したら停止
    
- 上流Agentの成果を尊重し、責務外の再設計をしない
    

**Layer 2｜Agent固有Prompt**

例えば：

```text
[01] Reconstruction Agent
→ Source Corpusの回収・分類・時系列再構築

[02] Architecture Genealogy Agent
→ Architectureの進化・系譜・Decision履歴の確定

[03] Evidence & Reconciliation Agent
→ Cross-Source Conflict / Duplicate / Evidence / Statusの処理

[04] Data / Schema Agent
→ Canonical Data Model / MI Object / Schema

[05] Implementation Agent
→ Repository / Engine / Validation / Production Implementation

[00] PMO / Chief Architect
→ 全体Governance / Decision / Gate / Architecture Integrity
```

### 特に重要

**[02] → [03] → [04] → [05] の境界条件もPromptに明記するべきです。**

例えば、

```text
[02]
「これは歴史的にどう形成されたか」
        ↓
[03]
「どれをEvidence-supportedとして採用できるか」
        ↓
[04]
「確定した知識をどうData Model化するか」
        ↓
[05]
「それをどう実装するか」
```

これを明文化すると、今回発生したような

> 「Architectureを整理するつもりで、既に確定したProject構造を勝手に変更する」

という事故をかなり防げます。

## 私の提案

ここでは**各Agent Promptをいきなり6本書き始めない**方がいいです。

まずこのOfficeで、

**`BioNexus Agent Governance Contract v1.0`**

を1つ確定します。

そのContractを基礎にして、

1. `[00] PMO / Chief Architect Custom Prompt`
    
2. `[01] Reconstruction Agent Custom Prompt`
    
3. `[02] Architecture Genealogy Agent Custom Prompt`
    
4. `[03] Evidence & Reconciliation Agent Custom Prompt`
    
5. `[04] Data / Schema Agent Custom Prompt`
    
6. `[05] Implementation Agent Custom Prompt`
    

を生成します。

そうすれば、**6 Agentがそれぞれ勝手な思想で動くのではなく、同じCanonical Governanceの下で専門分業できます。**

そして現在のHealthBook-MIOSについては、まず **[02] Architecture Genealogy AgentのPromptを確定してから、Phase 0-Cを[03]へ移す**のが安全です。
