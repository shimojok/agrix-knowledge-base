### 1. 整合性チェックスクリプトのカバレッジ確認

**すでに仕様でカバーしているもの**

- **core_pathways の値検証:**
    
    - `high / moderate / low / normal` 以外をエラーとして検出。
        
- **AcetylCoA / Estrobolome 整合性:**
    
    - `acetylcoa != normal` → `MI-AcetylCoA` 必須
        
    - `estrobolome != normal` → `MI-Estrobolome` 必須
        
- **disease_id 検証:**
    
    - 形式 `^D[0-9]+$`
        
    - 重複チェック
        
- **自動修正（--fix）:**
    
    - 足りない MI エンジンを `related_mi_engines` に追記。
        

**ここに 2 点だけ追加したい**

- **1)** `related_mi_engines` の値もホワイトリスト検証
    
    - 許可値以外があればエラーとして報告。
        
- **2)** `core_pathways` のキー存在チェック
    
    - `acetylcoa` / `estrobolome` / `mitochondria` / `mbt55` / `inflammation` がすべて存在するか。
        

これで「MI 軸まわりの漏れ」はほぼゼロにできる。

### 2. MI API 実装のステップ整理（漏れ防止用チェックリスト）

**ステップ 1: Matrix ローダ**

- `disease_mi_matrix_v2.json` を読み込み、メモリ上にキャッシュ。
    
- 起動時に整合性チェックを走らせるか、別ツールに任せるかは運用方針次第。
    

**ステップ 2: スナップショット → D マッチング**

- 各 D レコードについて：
    
    - `snapshot_markers` とユーザー `snapshot` の一致数をカウント。
        
    - 一致率を 0〜1 に正規化して `match_score` とする。
        

**ステップ 3: MI 軸スコア計算**

- 各 D について、軸ごとに重み `w` を決定：
    
    - `high=1.0, moderate=0.7, low=0.4, normal=0.0`
        
- 軸 A のスコア：
    

MIA=∑i(match_scorei⋅wi,A)∑iwi,A+ϵ

- すべての軸（AcetylCoA / Estrobolome / MBT55 / Mitochondria / Inflammation / Neuro-Endocrine）で同様に計算。
    

**ステップ 4: 軸トリガー抽出**

- 軸 A について：
    
    - `match_score_i * w_{i,A}` が高い順にソート。
        
    - `options.max_triggers_per_axis` まで返す。
        

**ステップ 5: 介入集約**

- 各 D の `intervention_focus` を軸ごとに集約。
    
- 介入コード c のスコア：
    

priority(c)=max⁡A(MIA⋅support(c,A))

- `support(c, A)` は「軸 A に関連する D のうち、c を含む割合」で近似。
