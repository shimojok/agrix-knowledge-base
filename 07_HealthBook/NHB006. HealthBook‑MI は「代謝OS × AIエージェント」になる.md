# 🧠 **HealthBook‑MI は「代謝OS × AIエージェント」になる**

HealthBook‑MI の AI 利用は、単なる「質問に答える」ではない。  
**代謝の因果構造を理解し、推論し、提案し、改善を伴走するエージェント** になる。

そのため、AI の役割は 5 層に分かれる。

---

# 🟦 **1. Data Understanding Agent（入力理解エージェント）**

![[Pasted image 20260522192038.jpg]]

![[Pasted image 20260522192053.jpg]]

HealthBook‑MI は、ユーザーが入力したデータを **単なる数値ではなく “代謝の文脈” として理解する AI** を持つ。

AI が理解する入力：

- 食事 → 糖・脂質・タンパク質の代謝負荷  
- 便通 → Estrobolome 活性  
- 冷え → 酵素活性低下  
- ストレス → コルチゾール → ホルモン阻害  
- 加工食品 → 内分泌攪乱物質  
- 薬剤 → Mg/Mn 喪失 → ATP低下  
- 痛み → 代謝の出口症状  

つまり、AI は **「入力 → 代謝 → 出力」** の因果線を理解する。

---

# 🟩 **2. MI Core Engines を動かす “推論エージェント”**

![[Pasted image 20260522192118.jpg]]

![[Pasted image 20260522192134.jpg]]

HealthBook‑MI の中心は **MI Core Engines**。  
AI はこれらを動かし、代謝の因果構造を推論する。

AI が推論する内容：

- AcetylCoA 生成能力  
- Estrobolome 活性  
- MBT55 パスウェイ  
- ミトコンドリア ATP 生成  
- 炎症負荷  
- 神経同期  
- 筋膜ラインの負荷  

AI は Snapshot を読み取り、  
**「代謝のどこが詰まっているか？」** を推論する。

---

# 🟧 **3. Causal Graph Agent（因果構造エージェント）**
![[Pasted image 20260522192151.jpg]]

![[Pasted image 20260522192205.jpg]]

![[Pasted image 20260522192221.jpg]]

![[Pasted image 20260522192237.jpg]]

HealthBook‑MI の最大の特徴は、  
**代謝の因果構造（Causal Graph）を AI が生成すること。**

AI は以下を推論する：

- どの代謝偏位が原因で  
- どの症状が起きて  
- どの経路が詰まり  
- どこを改善すれば  
- どの症状が改善するか  

つまり、AI は **「代謝の地図」** を描く。

---

# 🟨 **4. Intervention Agent（介入提案エージェント）**

AI は、因果構造に基づいて **最適な介入を提案する**。

提案内容：

- 食事（MBT55 × Estrobolome × AcetylCoA）  
- 漢方（Fコード）  
- 生活習慣（冷え・睡眠・ストレス）  
- 運動（筋膜ライン）  
- サプリ（Mg/Mn/B群）  

AI は **「病名」ではなく “代謝偏位コード” に基づいて介入を提案する**。

---

# 🟥 **5. Companion Agent（伴走エージェント）**

![[Pasted image 20260522192314.jpg]]

![[Pasted image 20260522192330.jpg]]

![[Pasted image 20260522192346.jpg]]

![[Pasted image 20260522192404.jpg]]

HealthBook‑MI の AI は、  
**ユーザーの代謝の変化を継続的に追跡し、改善を伴走する。**

AI が行うこと：

- 日々の Snapshot を解析  
- 代謝偏位の変化を検出  
- 改善の兆候をフィードバック  
- 悪化の兆候を警告  
- 介入の優先順位を更新  
- 長期的な代謝トレンドを可視化  

つまり、AI は **「代謝のコーチ」** になる。
