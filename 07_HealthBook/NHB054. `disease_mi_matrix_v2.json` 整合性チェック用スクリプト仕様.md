## A. `disease_mi_matrix_v2.json` 整合性チェック用スクリプト仕様

### A-1. 対象ファイルと前提

- **対象:**
    
    - `disease_mi_matrix_v2.json`
        
    - 形式：`[ { ...Dxxx... }, { ...Dyyy... }, ... ]` の配列
        
- **必須フィールド（各 D レコード）:**
    
    - `disease_id`（例: `"D222"`）
        
    - `core_pathways`（オブジェクト）
        
        - `acetylcoa`
            
        - `estrobolome`
            
        - `mitochondria`
            
        - `mbt55`
            
        - `inflammation`
            
    - `related_mi_engines`（配列）
        

### A-2. チェック項目一覧

**1. MI エンジン整合性チェック**

- **ルール 1: AcetylCoA 軸**
    
    - 条件:
        
        - `core_pathways.acetylcoa` が `"high"`, `"low"`, `"moderate"` のいずれか
            
    - 期待:
        
        - `related_mi_engines` に `"MI-AcetylCoA"` が **含まれていること**
            
- **ルール 2: Estrobolome 軸**
    
    - 条件:
        
        - `core_pathways.estrobolome` が `"high"`, `"low"`, `"moderate"` のいずれか
            
    - 期待:
        
        - `related_mi_engines` に `"MI-Estrobolome"` が **含まれていること**
            

**2. 値のバリデーション**

- `core_pathways` の各値は以下のみ許可：
    
    - `"high"`, `"moderate"`, `"low"`, `"normal"`
        
- `related_mi_engines` の値は以下のみ許可：
    
    - `"MI-AcetylCoA"`, `"MI-Estrobolome"`, `"MI-MBT55"`, `"MI-Mitochondria"`, `"MI-Inflammation"`, `"MI-Neuro-Endocrine"`
        

**3. 重複・ID整合性**

- `disease_id` が重複していないこと
    
- `disease_id` が `"D"` + 数値 形式であること（例: `"D291"`）
    

### A-3. スクリプトの入出力仕様

**入力:**

- **引数:**
    
    - `--file path/to/disease_mi_matrix_v2.json`
        
    - `--fix`（オプション）
        
        - 指定時：検出された不整合を自動修正して上書き保存
            

**出力（標準出力）:**

- **検出レポート（例）:**
    

text

```
[INFO] Loaded 291 disease records from disease_mi_matrix_v2.json

[WARN] D222: core_pathways.acetylcoa = "high" but MI-AcetylCoA not in related_mi_engines
[FIX]  D222: added MI-AcetylCoA to related_mi_engines

[WARN] D231: core_pathways.estrobolome = "low" but MI-Estrobolome not in related_mi_engines
[FIX]  D231: added MI-Estrobolome to related_mi_engines

[OK]  All disease_id values are unique and valid.
[OK]  All core_pathways values are within allowed set.

[SUMMARY]
  total_records: 291
  fixed_records: 12
  warnings: 12
  errors: 0
```

**自動修正のルール:**

- ルール 1/2 に違反している場合：
    
    - `related_mi_engines` に該当 MI を **追記**（重複は避ける）
        
- 不正な `core_pathways` 値があれば：
    
    - **エラー扱い**とし、修正は行わずレポートのみ（手動対応前提）
        

## B. HealthBook MI API エンドポイント定義（リクエスト/レスポンス仕様）

ここでは「MI スコア計算＋介入提案」を 1 つのエンドポイントで返す設計にする。

### B-1. エンドポイント概要

- **HTTP Method:** `POST`
    
- **Path:** `/api/healthbook/mi/evaluate`
    
- **Purpose:**
    
    - ユーザーのスナップショット（症状・生活・栄養・腸内状態など）から、
        
        - MI スコア（AcetylCoA / Estrobolome / 他軸）
            
        - トリガーとなった Dxxx
            
        - 推奨介入（食事・生活・漢方） を返す。
            

### B-2. リクエスト仕様

**Content-Type:** `application/json`

json

```
{
  "user_id": "user-123",
  "snapshot": {
    "nutrition": ["processed_food_high", "high_fat_diet", "fiber_low"],
    "gut_status": ["bloating", "stool_color_change"],
    "hormone_state": ["stress_high"],
    "microbiome": ["dysbiosis"],
    "musculo_fascial": ["pelvic_floor_tension"],
    "symptoms": ["abdominal_pain", "odor_change"]
  },
  "options": {
    "include_raw_matches": false,
    "max_triggers_per_axis": 5
  }
}
```

**フィールド説明:**

- `user_id`
    
    - 任意。ログ・トレース用。
        
- `snapshot`
    
    - Disease‑MI Matrix v2 の `snapshot_markers` と同じ語彙を使う。
        
    - 各キーは配列。空配列も許可。
        
- `options`
    
    - `include_raw_matches`
        
        - `true` の場合、Dxxx ごとのマッチングスコアをレスポンスに含める。
            
    - `max_triggers_per_axis`
        
        - MI 軸ごとに返す Dxxx トリガーの最大数。
            

### B-3. レスポンス仕様

**Content-Type:** `application/json`

json

```
{
  "mi_scores": {
    "acetylcoa": 0.78,
    "estrobolome": 0.64,
    "mbt55": 0.52,
    "mitochondria": 0.40,
    "inflammation": 0.71,
    "neuro_endocrine": 0.33
  },
  "axis_triggers": {
    "acetylcoa": [
      { "disease_id": "D222", "score": 0.82 },
      { "disease_id": "D260", "score": 0.67 }
    ],
    "estrobolome": [
      { "disease_id": "D231", "score": 0.75 },
      { "disease_id": "D241", "score": 0.69 }
    ]
  },
  "recommended_interventions": {
    "diet": [
      { "code": "low_fat", "reason_axes": ["acetylcoa"], "priority": 0.9 },
      { "code": "fiber", "reason_axes": ["estrobolome", "mbt55"], "priority": 0.8 },
      { "code": "fermented_food", "reason_axes": ["estrobolome"], "priority": 0.7 }
    ],
    "lifestyle": [
      { "code": "stress_management", "reason_axes": ["neuro_endocrine", "inflammation"], "priority": 0.85 },
      { "code": "hydration", "reason_axes": ["acetylcoa", "mitochondria"], "priority": 0.7 }
    ],
    "kampo": [
      { "code": "F203", "reason_axes": ["acetylcoa", "estrobolome", "inflammation"], "priority": 0.9 },
      { "code": "F102", "reason_axes": ["neuro_endocrine"], "priority": 0.75 }
    ]
  },
  "meta": {
    "version": "MI-v2.1",
    "matrix_version": "Disease-MI-Matrix-v2.1",
    "timestamp": "2026-06-24T12:30:00+09:00"
  }
}
```

**フィールド説明:**

- `mi_scores`
    
    - 各 MI 軸のスコア（0〜1）。
        
- `axis_triggers`
    
    - 軸ごとに、スコアに強く寄与した Dxxx のリスト。
        
    - `score` は「その D がその軸に与えた寄与度」。
        
- `recommended_interventions`
    
    - `diet` / `lifestyle` / `kampo` ごとに、介入コードと理由軸、優先度。
        
    - `reason_axes` により「なぜこの介入が出ているか」を説明可能にする。
        
- `meta`
    
    - MI エンジンのバージョン、Matrix のバージョン、計算時刻。
        

### B-4. 内部ロジックの位置づけ

- この API の内部で、さっき決めたロジックを使う：
    
    1. `snapshot` と `disease_mi_matrix_v2.json` の `snapshot_markers` をマッチング。
        
    2. Dxxx ごとのマッチスコアを計算。
        
    3. `core_pathways` を軸に、MI スコアを集約。
        
    4. `intervention_focus` を軸ごとに集約し、優先度を付けて返す。
