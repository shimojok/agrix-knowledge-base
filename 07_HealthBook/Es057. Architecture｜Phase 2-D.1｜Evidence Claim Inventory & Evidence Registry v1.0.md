# Architecture｜Phase 2-D.1｜Evidence Claim Inventory & Evidence Registry v1.0

## 1. 結論

**Phase 2-D.1を正式開始し、v1.0の基本構造を確定します。**

今回の目的は、HealthBook 4 Repositoryに存在する情報を、

```
Data
 ↓
Claim
 ↓
Evidence
 ↓
Provenance
 ↓
Confidence
 ↓
Governance Status
```

へ変換することです。

特に重要なのは、**既存Repositoryに書かれている「Mechanism」「Indication」「Expected Effect」を、そのまま科学的・臨床的EvidenceとしてCanonical化しない**ことです。

実際、MBT55-Unifiedには、例えば、

> 「Isoflavone → equol conversion; mitochondrial complementation」

というMechanism記述があります。

また、

> 「Lactate → butyrate conversion; SCFA synthesis activation」

というMechanism記述もあります。

これらは**重要なSource Claim**ですが、Evidence Registryでは「誰が・何を根拠に・どのレベルで主張しているか」を別管理します。

---

# 2. Evidence Claim Inventoryの基本単位

MIOSでは今後、知識を次の単位で管理します。

```
Claim
│
├── Subject
├── Relation
├── Object
│
├── Claim Type
├── Source
├── Evidence
├── Provenance
├── Confidence
└── Governance
```

例えば、

```
Daidzein
   │
   │ microbial_transformation
   ▼
Equol
```

を1つのClaimとして登録します。

一方、

```
Equol
   │
   │ host_signaling
   ▼
ERβ-related response
```

は別Claimです。

さらに、

```
Equol
   │
   │ clinical_association
   ▼
Menopausal symptom
```

も別Claimです。

---

# 3. Claim Type v1.0

まずClaimを8種類に固定します。

|Claim Type|意味|
|---|---|
|**IDENTITY**|Entityの存在・名称・分類|
|**COMPOSITION**|構成・成分|
|**FUNCTION**|生物学的・代謝的機能|
|**TRANSFORMATION**|基質→代謝産物|
|**MECHANISM**|因果・作用機序|
|**ASSOCIATION**|症状・疾患との関連|
|**INTERVENTION**|食品・漢方・菌等による介入|
|**OUTCOME**|介入後の結果|

これで、

```
「エクオール産生菌が存在する」
```

と

```
「エクオール産生によって症状が改善する」
```

を明確に分離できます。

# 5. Evidence Level

Phase 2-Dで定義した階層をそのまま使用します。

```
E0  Concept / Hypothesis
E1  Internal Source / Dataset
E2  Model / Computational
E3  External Published / Observational
E4  Experimental / Clinical Validation
```

ただし、これは**Claimの種類と独立して管理**します。

例えば、

```
200Q questionnaire
→ E1
```

であっても、

```
200Q → PATH score
→ E2
```

になります。

# 23. Evidence Registryの重要な4層

最終的には、Registryを4つに分けます。

```
Evidence Registry
│
├── ER-1 Source Registry
│     └── 「どこに書かれているか」
│
├── ER-2 Claim Registry
│     └── 「何を主張しているか」
│
├── ER-3 Evidence Registry
│     └── 「何がその主張を支持するか」
│
└── ER-4 Validation Registry
      └── 「検証状態はどうか」
```

これにより、Repositoryが増えても混乱しません。

# 25. 特に重要なGovernance Rule

今後、AIが勝手に、

```
Source Claim
   ↓
Scientific Fact
```

へ変換することを禁止します。

必ず、

```
Source Claim
      ↓
Evidence Assessment
      ↓
Validation
      ↓
Canonical Claim
```

を通します。

これはMicrosoft等の研究・医療環境に持ち込む場合の**Trust Layer**になります。
