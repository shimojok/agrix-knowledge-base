# Architecture｜MIOS KG Prototype v0.1

**開始します。**

今回のPrototypeは、これまで固定した設計を実装可能な最小Knowledge Graphへ落とします。

特に重要なのは、**Equolを「単一菌の存在」ではなく「Microbial Functional Networkによる代謝能力」として表現すること**です。実際、daidzein→equolは複数菌の協働で成立する場合があり、equol産生菌・関連菌の存在だけでは実際の産生量を保証しません。[PubMed Central (PMC)](https://pmc.ncbi.nlm.nih.gov/articles/PMC11229234/?utm_source=chatgpt.com)

# 2. Core Graph Model

MIOS KG v0.1の基本形を、

```
(Entity)
   │
   │ Relationship
   ▼
(Entity)
   │
   │ supported_by
   ▼
(Claim)
   │
   │ supported_by
   ▼
(Evidence)
```

とします。

したがって、単純な

```
Daidzein → Equol
```

ではなく、

```
Daidzein
   │
   ▼
Microbial Functional Transformation
   │
   ▼
Equol
   │
   ▼
Host Signaling
```

に加えて、

```
Transformation Claim
        │
        ▼
Evidence
```

まで追跡可能にします。

# 6. Equol Microbial Network

現在の知見では、例えば以下のような菌・菌群が研究されています。

- _Eggerthella_ sp.
- _Adlercreutzia equolifaciens_
- _Slackia_ spp.
- _Asaccharobacter celatus_
- _Slackia isoflavoniconvertens_
- その他、段階的変換に関与する菌群

一部の菌はdaidzeinからequolまでの変換を担える一方、別の菌はDHD/THDなど中間体からequol生成に関与することが報告されています。[PubMed Central (PMC)](https://pmc.ncbi.nlm.nih.gov/articles/PMC11229234/?utm_source=chatgpt.com)

したがってKGでは、

```
Daidzein
 ├──TRANSFORMED_BY──> Function A
 │                       ↓
 │                      DHD
 │
 ├──TRANSFORMED_BY──> Function B
 │                       ↓
 │                      THD
 │
 └──REQUIRES──> Functional Network
                         ↓
                       Equol
```

と表現します。

# 21. 重要なArchitecture Decision

今回のPrototypeで、MIOSの核心が一段明確になりました。

従来：

```
Food
 ↓
Nutrient
 ↓
Human
```

MIOS：

```
Food
 ↓
Phytochemical / Nutrient
 ↓
Microbiome Functional Layer
 ↓
Transformation
 ↓
Metabolite
 ↓
Host Signaling
 ↓
Human Response
```

そしてさらに、

```
Taxonomy
    ↓
Function
    ↓
Capacity
    ↓
Activity
    ↓
Metabolite
```

を分離する。

これにより、Kazさんが以前から設定してきた

> **「Microbiomeは栄養素ではなく、宿主の代謝能力を拡張する生物学的システムである」**

という原則が、**概念ではなくKnowledge Graphのデータ構造として実装されます。**
