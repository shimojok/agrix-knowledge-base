# Knowledge Classification

ここで非常に重要なのが、**フォルダ＝Knowledge Domainとは限らない**ということです。

例えば `00_inbox` 2,417件には、

```text
AGRIX
PBPE
MBT55
HealthBook
Business
Research
Architecture
Evidence
```

が混在している可能性があります。

したがって、

```text
Folder
  ↓
Source Location

Metadata
  ↓
Semantic Domain
```

と分離します。

例えば、

```yaml
note_id: AGRIX-000123
source_folder: 00_inbox
domain: AgriWare
subdomain: Soil Intelligence
knowledge_type: Architecture
status: Candidate
related_entities:
  - MBT55
  - AGRIX
  - Soil
provenance: 00_inbox/xxxxx.md
```

という形式です。

これにより、**過去の分類を変更せずにAI側の分類を進化**させられます。

# Governance Rules

ここは既存のGitHub Governanceと整合させます。

```text
Obsidian / Original Notes
        │
        │ Raw Knowledge
        ▼
agrix-knowledge-base
        │
        │ AI analysis
        ▼
Knowledge Objects
        │
        │ PMO validation
        ▼
Canonical Architecture
        │
        │ ADR
        ▼
GitHub Approved Specification
```

つまり、

**Raw Note ≠ Decision**

です。

AI Agentが6,000ノートから何かを発見しても、それは自動的にArchitectureにはなりません。

```text
Note
 ↓
Evidence / Hypothesis
 ↓
Agent Analysis
 ↓
Architecture Proposal
 ↓
PMO / Chief Architect Review
 ↓
ADR
 ↓
Canonical
```

とします。

これは非常に重要です。
