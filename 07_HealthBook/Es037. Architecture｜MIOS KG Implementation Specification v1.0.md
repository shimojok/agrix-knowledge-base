# 2. Implementation Principles

## Rule 01｜KG is the Single Semantic Layer

各Engineが独自に、

```
"equol"
"Equol"
"EQ"
"エクオール"
```

などを持つことは禁止します。

すべて、

```
Canonical Entity ID
```

に変換します。

---

## Rule 02｜Entity ≠ Claim

例えば、

```
Equol
```

はEntityです。

一方、

```
Equol may interact with estrogen receptor signaling
```

はClaimです。

この2つを混同しません。

---

## Rule 03｜Relationship ≠ Evidence

```
Equol
 ↓
ASSOCIATED_WITH
 ↓
Estrogen Receptor Signaling
```

というRelationshipと、

```
このRelationshipを支持するEvidence
```

は分離します。

# 4. Entity ID Convention

Canonical IDは、

```
MIOS:<DOMAIN>:<LOCAL_ID>
```

とします。

例：

```
MIOS:METABOLITE:EQUOL
MIOS:METABOLITE:UROLITHIN_A
MIOS:METABOLITE:SCFA

MIOS:PATHWAY:RP001
MIOS:PATHWAY:RP002
MIOS:PATHWAY:RP003

MIOS:FUNCTION:ESSENTIAL_001
```

### VersionはIDに埋め込まない

```
MIOS:METABOLITE:EQUOL:v1
```

ではなく、

```
MIOS:METABOLITE:EQUOL
```

とします。

Version管理はRegistry側で行います。

# 14. Essentiality Model

「必須腸内細菌」という概念を、まず**菌種そのものの必須性ではなくFunctionの必須性**として実装します。

```
Microbial Taxon
       │
       ▼
Functional Capability
       │
       ▼
Essential Microbial Function
       │
       ▼
Host Metabolic Relevance
```

これにより、

> 「この菌が必須」

ではなく、

> **「この宿主機能を補完する微生物機能が必要」**

というMIOSの原則を維持できます。
