## 1. Metabolic JSON Schemaをどう深く設計するか

まず、「何を1ユニットとして扱うか」を決めます。HealthBook-MIでは、**1人の1タイミングの“代謝状態スナップショット”**を基本単位にすると整理しやすいです。

### 1-1. コア構造イメージ

```json
{
  "subject_id": "HB-000123",
  "snapshot_id": "HB-000123-2026-05-18-01",
  "timestamp": "2026-05-18T09:30:00",
  "context": {
    "age": 54,
    "sex": "F",
    "bmi": 23.1,
    "medications": [...],
    "diagnosed_conditions": [...]
  },
  "inputs": {
    "questionnaire_200": { ... },
    "disease_risk_137": { ... },
    "blood_panel": { ... },
    "microbiome": { ... },
    "phenotyping": { ... },
    "diet_intake": { ... },
    "kampo_profile": { ... }
  },
  "mi_layer": {
    "mbt55_activity": { ... },
    "metabolic_pathways": { ... },
    "risk_inference": { ... },
    "intervention_plan": { ... },
    "prognosis": { ... }
  },
  "follow_up": {
    "previous_snapshot_id": "HB-000123-2026-04-10-01",
    "delta": { ... }
  }
}
```

ここから、各ブロックを深掘りします。

---

### 1-2. inputs層の詳細

**① 問診・疾病リスク**

- **`questionnaire_200`**
    - 各質問ID → 回答（Yes/No/スコア/テキスト）
- **`disease_risk_137`**
    - 疾病ID → リスクスコア（0–1 or 0–100）
    - リスク算出根拠（どの問診・どの血液指標が効いているか）

**② 血液データ（30+項目）**

- **`blood_panel`**
    - 項目ID → 値
    - 各項目に対して：
        - 正常レンジ
        - 個人基準値からの偏差
        - 「レンジ内だが注意」フラグ

**③ 腸内細菌データ**

- **`microbiome`**
    - taxonレベル（属/種）ごとの相対存在量
    - 機能プロファイル（SCFA産生、胆汁酸変換、ポリフェノール代謝など）
    - MBT55との関連指標（どのMBT55経路に寄与しているか）

**④ フェノタイピング**

- **`phenotyping`**
    - 自覚症状の推移（スコア＋時系列）
    - 視覚情報（画像ID/動画IDへの参照）
    - 睡眠・活動・ストレスなどの動態データ（ウェアラブル連携も想定）

**⑤ 食・生薬・ファイトケミカル**

- **`diet_intake`**
    - 食材ID・量・時間
    - 栄養素・ファイトケミカル推定量
- **`kampo_profile`**
    - 使用生薬・方剤
    - 体質分類（虚実・寒熱・気血水など）

---

### 1-3. mi_layer（Metabolic Intelligence層）の詳細

ここがHealthBook-MIの“心臓部”です。

**① MBT55アクティビティ**

- **`mbt55_activity`**
    - MBT55各代謝機能ID → 活性度スコア
    - 推定根拠（腸内細菌・食事・血液・症状）

**② 代謝経路ネットワーク**

- **`metabolic_pathways`**
    - 経路ID（例：SCFA生成、芳香族アミノ酸代謝、胆汁酸変換…）
    - 稼働度（0–1）
    - バランス指標（偏り・過剰・低下）

**③ リスク推論**

- **`risk_inference`**
    - 疾病・症候群ID → リスクスコア
    - 代謝経路・MBT55・血液・問診の寄与度

**④ 介入プラン（MBT Probiotics & Food & Kampo）**

- **`intervention_plan`**
    - 推奨MBT Probiotics（菌種・組成・用量）
    - 推奨食材・ファイトケミカル
    - 推奨漢方・生薬
    - 期待される代謝経路変化（どの経路を上げ/下げるか）

**⑤ 予後・シナリオ**

- **`prognosis`**
    - 介入なし vs 介入ありの予測リスクカーブ
    - 期待される血液・症状・代謝経路の変化

---

### 1-4. follow_up層（動態の扱い）

- **`previous_snapshot_id`**
- **`delta`**
    - 血液・症状・MBT55・経路稼働度の変化量
    - 介入との因果関係の推定（どの介入が効いたか）

ここで「動態」「推移」をスキーマとして明示しておくと、  
ダッシュボード設計が一気にやりやすくなります。

## 2. HealthBook-MI統合リポジトリのダッシュボード案

このスキーマを前提にすると、ダッシュボードで“見せられるもの”がかなりクリアになります。

### 2-1. リポジトリ全体のトップダッシュボード

**1. Metabolic Intelligence Overview**

- **総サンプル数・総被験者数**
- **主要疾患リスク分布（ヒートマップ）**
- **MBT55アクティビティ分布（レーダーチャート）**
- **主要代謝経路の稼働バランス（ネットワーク図）**

**2. 介入とアウトカム**

- MBT Probiotics介入前後の：
    - 血液指標の変化
    - 症状スコアの変化
    - MBT55アクティビティの変化
- 「どの介入がどの経路に効いているか」のマップ

**3. データカバレッジ**

- 問診・血液・腸内細菌・フェノタイピングのカバレッジ率
- 欠損の多い領域（今後のデータ収集の指針）

---

### 2-2. 開発者・研究者向けビュー

**1. Schema Explorer**

- `inputs` / `mi_layer` / `follow_up` の構造を可視化
- 各フィールドの説明・型・例（JSON Schemaドキュメント連動）

**2. API Usage Metrics**

- `/analyze_metabolism`
- `/recommend_mbt_probiotics`
- `/predict_risk`  
    などのエンドポイントごとの呼び出し数・レスポンスタイム

**3. モデル・ロジックのバージョン管理**

- リスク推論ロジックのバージョン
- MBT55評価アルゴリズムのバージョン
- それぞれの変更履歴と影響範囲

---

### 2-3. ビル・ゲイツ／Microsoft向け“見せる用”ビュー

**1. 「生活習慣病の動態」ストーリーボード**

- 典型的なケースの時系列：
    - 初診 → 解析 → 介入 → 3ヶ月後 → 6ヶ月後
- 血液・症状・MBT55・代謝経路の変化を一画面で

**2. 「コードとしての食」の可視化**

- 食材・生薬 → MBT55 → 代謝経路 → 疾病リスク  
    を一本のフローとして見せるインタラクティブ図

**3. 「HealthBook MIがなければ見えない世界」**

- 通常の健康診断では「正常」とされるが、  
    HealthBook MIでは「代謝ネットワークの偏り」を検出している例
- ここで、あなたが言った
    
    > 「レンジ内でも症状が出る」  
    > を具体例として見せる。

## 3. 次の一手（具体）

ここまで整理すると、次の順番が自然です：

1. **Metabolic JSON Schema v0.1 を、今の粒度で実際のJSON Schemaとして書き起こす**
    - `inputs` / `mi_layer` / `follow_up` の3階層
    - 各フィールドに `description` を付ける
2. それを前提に、  
    **GitHubリポジトリの `/schemas` ディレクトリ構成案**を作る
3. その上で、  
    **ダッシュボードに載せる「最初の4〜5枚のビュー」をワイヤーフレームレベルで定義**
