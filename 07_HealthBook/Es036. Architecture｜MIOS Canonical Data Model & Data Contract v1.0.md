        ↓

        ↓

        ↓
Functional Capacity
        ↓

次Moduleは、このCanonical Outputだけを受け取ります。

# 27. Dependency Rule

```
┌─────────────────────────────┐
│       MIOS Knowledge Graph  │
└──────────────┬──────────────┘
               │
     Canonical Data Contract
               │
 ┌─────────────┼─────────────┐
 ▼             ▼             ▼
Module A     Module B      Module C
```

### 禁止

```
Module A → Module B internal function
Module B → Module C internal database
Module C → Module A hidden state
```

### 原則

> **Module間通信はCanonical Contract経由のみ。**

---

# 28. Validation Rules

## Schema Validation

```
Required field missing → REJECT
Invalid datatype → REJECT
Invalid enum → REJECT
Invalid Object ID → REJECT
Invalid Relationship → REJECT
```

## Semantic Validation

```
Taxon → Function
```

はEvidenceが必要。

```
Function → Capacity
```

もEvidenceが必要。

```
Capacity → Activity
```

は別Evidenceが必要。

---

# 29. Clinical Safety Validation

以下は自動Reject対象とします。

```
Risk → Diagnosis
Mechanism → Guaranteed Outcome
Association → Causation
Presence → Activity
Capacity → Actual Production
```

特に、

> **エクオール産生菌が存在する = エクオールを十分産生している**

とは判定しません。

これは今回確立した**Essential Microbial Functions**の思想とも完全に一致します。
