# Architecture｜MIOS Health Profile Schema v1.0

**正式策定します。**

今回のSchemaは、これまで構築した **200Q・Phenotype・Nutrition・Hormone・Mineral・Energy/ATP・Essential Microbial Functions・Metabolite・Host Signaling・137疾病Risk・MBT漢方代謝Library・Evidence** を、1つのCanonical Health Objectに統合するための基盤です。

外部連携については、FHIRの `Observation` が測定値・簡単な臨床的アサーションを扱う標準Resourceであり、診断そのものは `Condition` 等で扱う設計です。この境界をMIOSでも採用します。[FHIR](https://fhir.hl7.org/fhir/observation-definitions.html?utm_source=chatgpt.com)

# 3. Assessment Object

既存200問を保存します。

```
{
  "assessment": {
    "instrument": "HealthBook-200Q",
    "version": "1.0",
    "completion_rate": 1.0,
    "responses": [
      {
        "question_id": "Q001",
        "answer": "...",

```

 ↓

 ↓

# 24. Confidence Model

Confidenceを一つの数字だけにしません。

```
Evidence Confidence
Functional Confidence
Inference Confidence
```

に分離します。

```
{
  "confidence": {
    "evidence": 0.92,
    "functional": 0.65,
    "inference": 0.58
  }
}
```

これはMIOSにとって非常に重要です。

---

# 25. Confidence Chain

```
Evidence
   ↓
Knowledge Claim
   ↓
Functional Interpretation
   ↓
Patient-specific Inference
   ↓
Output
```

それぞれ異なる確度を持つためです。

例えば、

```
Daidzein → Equol
        ↑
    Evidence: High

本人がequol producer
        ↑
    Evidence: Unknown

本人の症状に影響
        ↑
    Inference: Low
```

という状態を正しく表現できます。

# 28. FHIR Interoperability

MIOS独自SchemaをFHIRの代替にはしません。

```
MIOS Canonical Model
        │
        ├── Internal Knowledge Representation
        │
        └── FHIR Adapter
                ↓
          FHIR Resources
```

FHIR R5はObservation、DiagnosticReport、Condition、Medication等を分離しており、MIOSの各Layerを外部医療データ交換へマッピングできる構造です。[HL7](https://hl7.org/fhir/R5/?utm_source=chatgpt.com)

### Mapping

```
MIOS Observation
      ↓
FHIR Observation

MIOS Disease Risk
      ↓
FHIR RiskAssessment

MIOS Clinical Diagnosis
      ↓
FHIR Condition

MIOS Questionnaire
      ↓
FHIR Questionnaire / QuestionnaireResponse
```

したがって、**MIOS内部モデルと国際標準交換モデルを分離**します。
