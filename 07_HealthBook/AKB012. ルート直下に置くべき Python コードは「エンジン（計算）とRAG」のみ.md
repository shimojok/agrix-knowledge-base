Pythonコードを全てルート直下に集めるのですか？

---

Kaz、ここは **AGRIX Knowledge Base のディレクトリ設計（PMOとしての正解）**に直結する重要ポイントなので、誤解ゼロで整理します。

あなたの質問：

> Pythonコードを全てルート直下に集めるのですか？

結論は **YES だが “全部” ではなく “役割が異なるコードだけ” をルート直下に置くのが正しい** です。

理由は、ローカルRAG・Canonical数値テーブル・計算エンジン・UI・Azure の流れを壊さず、 **どのAI（NotebookLM / Claude / Python / Azure）が見ても迷わない構造**にするためです。

# 🟥 結論（PMOとしての最適解）

## **ルート直下に置くべき Python コードは「エンジン（計算）とRAG」のみ。**

## **その他のコード（試作、実験、AIログ生成コード）はフォルダに分離する。**

# 🟦 なぜルート直下に置くのか？

あなたの Knowledge Base は **AIが参照する巨大な脳**です。

NotebookLM → 全体構造を理解する Claude → 設計・UI・ロジックを生成する Python → 計算エンジンとして動く Azure → デプロイする

このとき、Pythonコードがフォルダの奥に散らばっていると：

- NotebookLM がコードを見つけられない
    
- Claude がコードの位置を誤認する
    
- RAG が検索対象を誤る
    
- Azure Functions が参照パスでエラーを起こす
    

という **AI特有の構造破壊** が起きます。

だから、**計算エンジンだけはルート直下に置くのが正しい**。

# 🟩 ルート直下に置くべき Python ファイル（PMO決定版）

|ファイル名|役割|ルート直下に置く理由|
|---|---|---|
|**rag_engine.py**|RAG検索エンジン|txtフォルダを読み込むため、ルート直下が最適|
|**canonical_data.json**|公式数値テーブル|全計算の唯一の真値なのでルート直下|
|**pbpe_engine.py**|PBPE金融モデル|UI・Azure Functionsが直接参照する|
|**mbt_engine.py**|MBT55モデル|計算エンジンの中心|
|**ghg_engine.py**|GHG削減モデル|PBPEとMBT55と連動するためルート直下|

# 🟦 逆に、ルート直下に置かない方が良いもの

|種類|理由|
|---|---|
|AIログ（Claude、ChatGPT、DeepSeek）|RAGの検索ノイズになる|
|試作コード|NotebookLMが誤学習する|
|実験用スクリプト|Claudeが誤って参照する|
|古いUIコード|Azureデプロイ時に混乱する|

これらは **11_AI_Development/** にまとめるのが正しい。

# 🟦 つまり、Pythonコードは「全部」ではなく「計算エンジンだけ」ルート直下に置く

あなたの質問に対する最終回答：

## **Pythonコードは全てルート直下に集めるのではなく、計算エンジン（RAG＋PBPE＋MBT55＋GHG）だけをルート直下に置くのが正しい。**

理由は：

- AIが誤解しない
    
- RAGが正しく検索する
    
- NotebookLMが正しく理解する
    
- Claudeが正しく設計する
    
- Azure Functionsが正しく参照する
    

という **AIシステム全体の整合性を守るため**。
