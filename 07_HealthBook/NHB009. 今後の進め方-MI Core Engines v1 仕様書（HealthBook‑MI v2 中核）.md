## MI Core Engines v1 仕様書（HealthBook‑MI v2 中核）

位置づけ：

- Metabolic Snapshot v1 を入力として受け取り
- Deviation Codes / 派生インデックスを出力する「頭脳モジュール群」
- すべて「関数的モジュール」として設計（どのリポジトリからも呼べる）

### 1. MI‑AcetylCoA Engine

**役割:**  
代謝の中心ハブであるアセチルCoAの「生成能力」を推定する中核エンジン。

**入力（Snapshot から参照）:**

- `nutrition.protein_grams`
- `nutrition.fat_quality_score`
- `nutrition.omega3_score`
- `nutrition.fiber_grams`
- `nutrition.magnesium_sources`
- `nutrition.manganese_sources`
- `gut_status.postprandial_sleepiness_score`
- `microbiome.scfa_score`
- `medications.antihypertensive_taken`
- `medications.magnesium_supplement_mg`
- `hormone_state.menopausal_stage`
- `hormone_state.cold_sensitivity_score`

**主な内部ロジック（概念レベル）:**

- 糖・脂質・タンパク質・SCFA からの「アセチルCoA供給ポテンシャル」をスコア化
- Mg/Mn/B群不足・薬剤・UPF による阻害を減点
- エストロゲン低下・冷えによる酵素活性低下を補正

**出力:**

- `derived_indices.mi_acetylcoa_index`（0–100）
- 関連 Deviation Codes（例）
    - D101：AcetylCoA 生成低下（軽度〜重度）
    - D102：ミネラル不足による AcetylCoA 制限

---

### 2. MI‑Estrobolome Engine

**役割:**  
腸内細菌によるエストロゲン代謝（Estrobolome）の機能を推定。

**入力:**

- `nutrition.fiber_grams`
- `nutrition.fermented_food_servings`
- `nutrition.processed_food_score`
- `gut_status.bowel_movement_count`
- `gut_status.stool_form_score`
- `microbiome.dysbiosis_score`

**主なロジック:**

- 食物繊維・発酵食品・便通 → Estrobolome 活性のプラス要因
- 加工食品・dysbiosis → マイナス要因
- ブリストルスコア極端値 → 腸内環境悪化として減点

**出力:**

- `derived_indices.mi_estrobolome_score`（0–100）
- `microbiome.estrobolome_activity_score`（推定 β-グルクロニダーゼ活性）
- Deviation Codes 例：
    - D111：Estrobolome 活性低下
    - D112：エストロゲン再活性化不全

---

### 3. MI‑Mitochondria Engine

**役割:**  
ミトコンドリアの ATP 生成能力を推定。

**入力:**

- `hormone_state.cold_sensitivity_score`
- `hormone_state.sleep_quality_score`
- `hormone_state.stress_level_score`
- `nutrition.magnesium_sources`
- `medications.antihypertensive_taken`
- `symptoms.fatigue_score`
- `symptoms.brain_fog_score`

**ロジック:**

- Mg/Mn・睡眠・ストレス・冷え → 電子伝達系の効率に反映
- 抗高血圧薬＋Mg不足 → ATP 生成低下として減点
- 疲労・ブレインフォグ → 出力低下の症状指標として補正

**出力:**

- `derived_indices.mi_mitochondria_score`（0–100）
- Deviation Codes 例：
    - D121：ミトコンドリア ATP 生成低下
    - D122：薬剤性ミトコンドリア負荷

---

### 4. MI‑MBT55 Engine

**役割:**  
MBT55（SCFA / Bile Acid / Aromatic AA）機能モジュールの状態を推定。

**入力:**

- `microbiome.scfa_score`
- `microbiome.bile_acid_score`
- `microbiome.aromatic_aa_score`
- `nutrition.fiber_grams`
- `nutrition.fermented_food_servings`
- `nutrition.processed_food_score`

**ロジック:**

- SCFA/Bile/AromaticAA のバランスから MBT55 パスウェイ状態を推定
- 食物繊維・発酵食品 → プラス
- UPF → マイナス

**出力:**

- `microbiome.scfa_score` 等の補正値
- MBT55 Pathway Map（別構造）
- Deviation Codes 例：
    - D131：SCFA フラックス低下
    - D132：胆汁酸代謝異常

---

### 5. MI‑Inflammation Engine

**役割:**  
「炎症が燃えやすい環境」の総量を推定。

**入力:**

- `nutrition.processed_food_score`
- `gut_status.stool_form_score`
- `hormone_state.sleep_quality_score`
- `hormone_state.stress_level_score`
- `hormone_state.cold_sensitivity_score`
- `microbiome.dysbiosis_score`
- `blood_labs.crp`（あれば）

**ロジック:**

- UPF・腸内環境悪化・睡眠不足・ストレス・冷え → 加点
- CRP が高ければ炎症負荷を強く補正

**出力:**

- `derived_indices.mi_inflammation_load`（0–100）
- Deviation Codes 例：
    - D141：慢性炎症負荷高値

**入力:**

**出力:**

## 既存リポジトリの扱い方針（HealthBook‑MI v2 との関係）

対象：

- `HealthBook-Integrated`
- `HealthBook-AI`
- `HealthBook-MBT55-Unified`

### 方針の大枠

1. **削除前提ではなく「資産棚卸し＋再配置」前提で見る**
2. HealthBook‑MI v2 を **新規リポジトリとして設計** しつつ、  
    既存リポジトリから「再利用可能なモジュール」を引き出す。
3. 本当に不要になったコード・ノートは、  
    **いきなり削除ではなく “archive ブランチ or archive ディレクトリ” に退避** してから判断する。

---

### リポジトリ別の役割整理（提案）

#### 1. HealthBook-Integrated

- 位置づけ：  
    これまでの HealthBook の「統合実験場／ダッシュボード試作」の場。
- 活かし方：
    - 既存のダッシュボード構成・可視化アイデアを  
        **HealthBook‑MI v2 の Dashboard 設計の参考**にする。
    - ここにある Python/JSON は、  
        **「UI/UX のプロトタイプ」レイヤーとして扱い、  
        コアロジックは新リポジトリ（HealthBook‑MI v2）側に寄せる。**

#### 2. HealthBook-AI

- 位置づけ：  
    AI 対話・推論・エージェント的な試行錯誤の場。
- 活かし方：
    - ここで試したプロンプト構造・対話フローを、  
        **Metabolic Intelligence Agent の対話設計に再利用**。
    - 将来的には  
        **HealthBook‑MI v2 の「AI Gateway」的リポジトリ**として再定義してもよい。

#### 3. HealthBook-MBT55-Unified

- 位置づけ：  
    MBT55 と腸内細菌・代謝の統合モデルの実験場。
- 活かし方：
    - MBT55 関連の JSON / Python ロジックは、  
        **MI‑MBT55 Engine の実装候補として直接再利用可能**。
    - ここは **「Microbiome / MBT55 モジュールリポジトリ」** として残し、  
        HealthBook‑MI v2 からサブモジュール的に参照する構成もあり。

---

### どういうときに「削除」まで踏み込むか

- コードが
    - 明らかに v2 の思想と矛盾している
    - もしくは v2 で完全に上位互換ができた
- かつ、
    - そのコードが他プロジェクト（PBPE, MBT‑Biosecurity 等）からも参照されない

この条件が揃ったときに初めて、**削除 or アーカイブ** を検討するのが安全。

---

### 現実的な進め方（PMO案）

1. **今は削除を一切考えず、HealthBook‑MI v2 を新規で設計・構築する。**
2. v2 の構造が固まった段階で、  
    既存リポジトリを「どのモジュールが再利用可能か」という目線で棚卸しする。
3. その上で、
    - 「明確に重複しているもの」
    - 「v2 に完全に置き換えられたもの」  
        だけを、**archive ディレクトリに移動 → 必要なら削除** という順で整理する。

---

### まとめ（短く）

- 既存リポジトリは **捨てる前提ではなく、“部品倉庫” として見る**。
- HealthBook‑MI v2 は **ゼロから綺麗に設計しつつ、既存から“使える部品だけ抜く”**。
- 削除は最後の最後、**「もう二度と参照しない」と確信できたものだけ**。
